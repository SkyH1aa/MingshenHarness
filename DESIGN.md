# Design System: Mingshen Harness

## Overview

**Creative North Star: "The Quiet Orbit"**

Unqualified rules below describe the default **Simple** style. **Light Trails (光轨)**
is the user-approved second visual world; its scoped rules appear within the same
eight sections. Simple remains the `simple` default for old and new preferences.
Light Trails uses the internal value `orbit`. The original style and shared business
behavior remain intact.

Mingshen Harness is arranged as a calm command surface for sustained technical work. The conversation remains the largest and quietest region; session navigation recedes into a graphite rail; model, reasoning and workspace controls gather into one framed composer. The atom mark is the one distinctive brand gesture, while aqua and vermilion appear only when they carry state or action.

The product should read as a polished desktop instrument, not a terminal costume or a web dashboard. Chinese typography leads. English is reserved for protocol names, model IDs, shell commands, metrics, and other technical identifiers.

Light Trails is a distinct working composition for reading conversation, evidence
and task progress together. It has a separate tool rail and session column, a
workspace breadcrumb above the conversation, simultaneous review and task panes,
and a bottom status strip. Its continuous workplane is built from aligned tonal
planes, 1px hairlines and a restrained state line rather than floating cards. Day
uses a white conversation pane on a pale gray-green shell; night uses a low-saturation
ink-teal shell and pane with slightly raised work surfaces. The original bitmap atom
remains the identity asset. No large local-memory feature tile, simulated task
records or decorative metrics are part of this world.

**Key Characteristics:**

- Soft-white surfaces by day and true graphite-black surfaces at night.
- One framed composer with compact, low-chrome controls.
- An atom mark that provides identity without decorating every surface.
- Tonal elevation and quiet borders instead of heavy outlines or glows.
- No gradient atmosphere, terminal chrome, or card mosaics.

**Light Trails Characteristics:**

- An independent tool rail, workspace sidebar and breadcrumb composition.
- Conversation, review evidence and task progress visible together.
- White or ink-teal planes with silver-green hairlines and one restrained composer lift.
- The same real sessions, tools, permissions, settings and project memory as Simple.

## Colors

The palette pairs neutral work surfaces with an aqua brand signal and a vermilion execution signal. Aqua identifies the product and current agent state; vermilion is reserved for execution, approval and error. Primary actions invert to white on dark and near-black on light.

### Primary

- **Vermilion Signal** (`#C44D42` day / `#E25B4D` night): The execution and exception accent. Used for active work, approvals and errors, never as a default button fill.
- **Orbital Aqua** (`#2F727B` day / `#B9DEE3` night): The product identity and agent-state signal. Used on the atom mark, selected-session dot, active model and focus treatment.

### Secondary

- **Information Blue** (`#2D5F9F`): Links, informational state, and secondary selection. Never used as a second competing primary.

### Neutral

- **Soft White** (`#F5F5F7`): Day-theme application ground.
- **Paper Surface** (`#FBFBFC`): Day-theme sidebars, composer, settings, and panel grounds.
- **Pure Raised** (`#FFFFFF`): Day-theme menus, popovers, and selected rows.
- **Paper Line** (`#E5E5E9`): Day-theme dividers and control strokes.
- **Graphite Text** (`#18181B`): Day-theme primary text.
- **Cool Gray** (`#5F626A`): Day-theme secondary text.
- **Abyss Ink** (`#09090B`): Night-theme application ground.
- **Abyss Surface** (`#0F0F12`): Night-theme panel ground.
- **Abyss Raised** (`#17171B`): Night-theme menus and selected rows.
- **Abyss Line** (`#27272D`): Night-theme dividers and control strokes.
- **Cool White** (`#F4F4F5`): Night-theme primary text.
- **Quiet Mist** (`#A6A6AF`): Night-theme secondary text.

### Named Rules

**The Signal Rarity Rule.** Accent color covers less than one tenth of a screen and always indicates action, selection, focus, or live state.

**The State Is Not Decoration Rule.** Success, warning, and danger colors appear only when they communicate a real state. They are not used for atmosphere.

### Light Trails

The `orbit-*` frontmatter tokens capture the effective runtime palette after
`orbit-workbench.css` overrides the base `orbit.css` surfaces. Preview-only swatches
remain limited to the style-picker thumbnail.

- **Mineral Mint** uses the `orbit-*-brand` and `orbit-*-primary` tokens for identity,
  active controls, actual running state and send actions.
- **Ice Blue** uses `orbit-*-signal` and `orbit-*-secondary` for supporting tool and
  workspace signals.
- **Ink Teal / Ice White** uses `orbit-*-shell`, `orbit-*-pane`, `orbit-*-surface` and
  `orbit-*-raised` to distinguish aligned work regions.
- **Silver-Green Edges** use `orbit-*-line`, `orbit-*-line-strong`, `orbit-*-metal` and
  translucent `orbit-*-edge` for boundaries and etched control detail.
- Warning and danger use their Orbit theme tokens for real waiting, failure and
  destructive states. Running is mint; it does not inherit Simple's vermilion accent.

## Typography

**Display Font:** Segoe UI Variable Text with Microsoft YaHei UI fallback  
**Body Font:** Segoe UI Variable Text with Microsoft YaHei UI fallback  
**Label/Mono Font:** IBM Plex Mono with Cascadia Code fallback

**Character:** One compact, neutral Chinese sans handles interface hierarchy. The monospaced face is restricted to code, timings, token counts, IDs, commands, and state labels where character alignment helps comparison.

### Hierarchy

- **Display** (650, 32px, 1.2): Workspace and onboarding titles only.
- **Headline** (600, 21px, 1.35): Settings section titles and major conversation headings.
- **Title** (600, 15px, 1.4): Panels, dialogs, and grouped controls.
- **Body** (400, 15px, 1.8): Conversation content. Settings descriptions use 13px; supporting information is at least 12px.
- **Compact body** (400, 13px, 1.55): Dense sidebars, file trees, and tool results.
- **Label** (500, 12px, 1.4, 0): Technical state labels and metrics. Sentence case is preferred; uppercase is reserved for short protocol tags.

### Named Rules

**The Chinese Leads Rule.** Chinese text sets the reading rhythm. English identifiers appear inline without forcing English sentence structure.

**The Mono Is Evidence Rule.** Monospace appears only for something the user can measure, execute, compare, or copy.

### Light Trails

The same Chinese-first sans and Lucide family remain. Conversation prose retains
the shared body size; message identities use compact interface text, and execution
labels use 14px sans above 12px Cascadia/Consolas command previews.

Timestamps, role tags, counts, execution states, task states and status metrics in
the main workbench use 12px metadata. The compact secondary caption under the product
name remains a scoped 10px brand label, while the dedicated Chat conversation list
uses 13px titles and 12px metadata. These exceptions do not lower the general
supporting-text minimum. The breadcrumb title uses the 15px/600
`orbit-workspace-title` role and reduces to 14px when the workbench is narrow.

## Layout

The desktop shell is a continuous workbench below one 48px custom title bar. Three modes share component identities: focused chat opens the right inspector on demand, code workbench opens files and review, and collaboration docks the task tree on the right. Layout and panel preferences persist per normalized project path in app_settings. Mode changes preserve draft, reading position, unsaved editor content and running work.

The left sidebar defaults to 260px (220–320px), the inspector to 460px (360–720px). Pointer and keyboard splitters persist sizes on commit. The chat retains at least 480px; insufficient width converts the inspector to a drawer, then the sidebar, with mutually exclusive overlays. The conversation measure is at most 880px; the composer is at most 920px. Model and Agent selectors live only in the composer. A compact plan summary sits above chat only when work exists; collaboration can reveal the full task workspace.

Spacing follows a 4px base scale. Groups use 8px and 12px, sections 24px, and major layout breaks 32px. Panel borders are 1px. The main content ground is continuous; regions are divided by hairlines and tonal steps, not by separate rounded cards.

Drawer thresholds derive from current panel widths and the minimum chat measure. Settings use a full application workspace below the caption, six category groups and a search field. Menus constrain their own height and scroll internally. Primary dialog actions stay visible while long content scrolls.

### Light Trails

The full-width caption is 56px tall, uses the shell ground and has no outer frame
or gradient. Beneath it, the workbench uses a separate 48px tool rail, 12px side
and bottom insets, and 8px gaps between aligned regions. The breadcrumb spans the
conversation and right column at 44px; the bottom status strip spans the same
columns at 24px. Both rows are square-cornered. The right column shows workspace
review/files/terminal above a task/Agent dock whose default height is
`clamp(224px, 28dvh, 304px)`. The conversation spans both middle rows. These are
aligned regions within one shell, not repeated dashboard cards.

The task dock has its own horizontal splitter. Pointer dragging changes its height;
the focused splitter accepts Up/Down in 16px steps and Home/End at its bounds;
Escape cancels an active drag. Enter or double-click restores the responsive default. The
effective expanded height is constrained to the available window height and at
most 640px; a 40px collapsed header leaves more room for the upper workspace.
The header can reopen the dock, and task-tree navigation reveals it automatically.

New Orbit project layouts default to a 228px sidebar and a 360px right column,
with the right column open. The shared resize ranges remain 220-320px and
360-720px. Layout keys use the `@orbit:` prefix so mode, widths, task height and
collapsed state, and panel visibility remain independent from Simple for the same
normalized project path. Switching the three modes retains mounted conversation
and editor components.

Orbit keeps the shared 480px minimum chat calculation, with its additional rail
and insets included in drawer thresholds. The upper workspace and lower task pane
open and close as one right drawer group; sidebar and right overlays remain
mutually exclusive. Conversation measure is at most 960px with 64px total side
space. The composer fits its conversation pane.

At 1100px and below, layout mode labels yield to their icons. At 900px and below,
the task dock defaults to 160px and conversation side space becomes 48px. When a
file editor opens at 760px height or below, the dock also defaults to 160px. A
saved custom height still applies within the available window bounds. The
composer's own container query changes its context grid at 600px or below: the
model selector takes the first row, while Agent and workspace controls share the
second row. At 700px height or below, rail controls and the textarea compress to
36px and 56px respectively. Responsive drawers retain access to the same live
content.

The Orbit app body isolates its stacking context and clips overflow so aligned
planes and drawers cannot paint outside the workbench. Responsive drawer
calculations reserve an 88px rail/sidebar shell and a 96px rail/inspector shell,
including outer insets and splitters. These values are calculation contracts, not
additional visible rails.

ChatAgent uses its own grouped conversation page instead of the Code/Work sidebar.
In Orbit, that page uses a 264px conversation sidebar, square shell edges, solid
chrome and 13px/550 titles with 12px metadata. The selected row is a flat selected
tone with a 1px brand inset line and no border or glow. The empty conversation title
is fixed at 24px in Orbit, overriding the older viewport-scaled heading. At 900px
and below the Chat sidebar becomes an overlay drawer instead of compressing the
conversation.

## Elevation & Depth

The system is flat by default. Depth is communicated by tonal surfaces, borders, and occlusion. Menus and popovers use an offset shadow with a soft blur and a 1px border. Focus uses a 2px accent outline with a 2px offset, never a colored halo.

Streaming, loading, and approval states use restrained motion and precise status labels rather than pulsing glows.

Button feedback lasts 100ms, menus 160ms and workspace entrance 200ms. Motion uses opacity and small translations; system reduced-motion and the application Off preference remove transitions and animations. Paused, waiting and completed states stay static.

### Light Trails

Orbit is flat by default, but not a single undifferentiated color. Depth comes
from aligned tone steps, 1px hairlines and selective occlusion. The caption, rail
and work regions do not use gradients, glows or floating inset frames. Selection
uses a flat selected tone plus a 1px brand line on the nearest existing edge.

The composer is the one intentionally lifted control surface. It uses a 1px
hairline, an 8px radius and `0 4px 16px #0000000D`; overlays retain the theme
`--shadow`. Focus uses a visible 1px brand outline at a 2px offset. The focused
composer changes its border to brand and shows one 40px focus beam on the top edge.
Text selection uses primary fill/text tokens; editable carets use brand.

Motion communicates state and continuity only. The composer focus beam runs once
over 520ms. Streamed messages move by 3px over 280ms while their opacity remains 1
from the first frame, so text is never hidden by the entrance effect. Disclosures
use 190ms and detail or settings transitions use up to 280ms. Execution nodes
breathe over 2.2s and the status signal over 1.9s only while their real status is
running. Waiting, approval, questions, completion and idle states stay static.
System reduced motion and application Motion off remove travel and loops; hidden
pages pause animation.

## Shapes

Radii are restrained: 4–6px for compact controls and 8px for composer and dialogs. Full workspace regions have no floating rounded outer border. Geometry comes from alignment and tonal surfaces. Icons use one Lucide stroke family with consistent 16px and 18px sizes.

Light Trails deliberately keeps the outer workplane square and continuous. Alignment,
tonal cuts and 1px hairlines separate regions; the caption and aligned work regions
do not become floating rounded frames. Session rows use 4px corners, execution
groups and user-message bodies use 6px, and message-role labels use 3px. Tool-rail
buttons are stable 40px squares with 4px corners. Keep these scoped forms separate
from Simple's continuous outer shell. The original bitmap atom remains unchanged;
19px rail icons and 24px message marks support Orbit's denser identity hierarchy.

## Components

### Brand Identity

The renderer mark at `apps/desktop/src/renderer/src/assets/brand-icon.png` and
packaging mark at `apps/desktop/build/icon.png` are pre-existing user-confirmed
aqua atom assets. Preserve their bytes and pixels; this reconstruction introduces
no new raster. Their user-confirmed origin is recorded here because the original
files have no embedded provenance metadata.

**Light Trails:** the bitmap atom appears once in the main caption beside the
product name. The tool rail, breadcrumb, conversation roles and empty regions do
not repeat the brand, invent a letter-M mark or add a central light-trail wordmark.
The titlebar state label reflects real runtime state without adding another
decorative logo.

### Buttons

Buttons are compact, direct, and unmistakably interactive.

- **Primary:** inverted near-white ground on dark and near-black ground on light, 8px radius, 34px default height, 13px horizontal padding.
- **Secondary:** raised surface with a 1px line, text in primary color, and brand border on focus.
- **Ghost:** no ground at rest, muted text, raised tone on hover.
- **Danger:** danger color only for destructive confirmation actions, never for normal navigation.
- **States:** hover, active, focus-visible, disabled, and loading are all explicit. Icon-only buttons include tooltips.

### Inputs and Selects

Inputs use the panel ground, a 1px line and a stable height appropriate to the form. Existing settings fields retain their 9px corner radius; compact workbench controls use 4–8px. Focus moves the border to the accent and adds the standard 2px outline. Error text sits directly below the field and names the recovery. Placeholders use secondary text at 4.5:1 contrast.

### Session List

A session row is 44px tall with a status dot, title, and relative time. Running sessions show a small activity mark; waiting sessions show an approval marker. Selected rows use a neutral raised ground with no colored outline. The list supports pinning, rename, archive, delete, and search.

**Light Trails:** rows have a 52px minimum height, 13px/500 titles, 12px metadata,
4px corners and a quiet border. The selected row uses a flat Orbit selected tone

## Do's and Don'ts

### Do:

- **Do** keep the conversation as the visual center and make agent state readable at a glance.
- **Do** use real event data for the run ledger and every metric.
- **Do** use hairlines, tonal steps, and aligned columns to create order.
- **Do** keep touch and click targets at least 32px, with primary mobile targets at 44px.
- **Do** keep focus visible, contrast compliant, and status legible without color.
- **Do** reserve monospace for code, commands, identifiers, and measurements.
- **Do** support reduced motion and keyboard-only operation.
- **Do** keep Simple and Light Trails layout preferences independent for the same project.
- **Do** preserve Orbit's separate tool rail, breadcrumb, stacked evidence/task panes and status strip.
- **Do** drive Orbit navigation, identities, execution records and task counts from real application data.

### Don't:

- **Don't** imitate a terminal with scanlines, prompt glyphs, glowing cursors, or fake CRT effects.
- **Don't** wrap every section in a card or place cards inside cards.
- **Don't** use gradient text, gradient blobs, bokeh, glass panels, or colored halos.
- **Don't** use accent color as decoration or apply it to inactive states.
- **Don't** use negative letter spacing or viewport-scaled font sizes.
- **Don't** use oversized marketing headings or explanatory onboarding copy inside the workspace.
- **Don't** hide errors, approvals, or tool state behind color alone.
- **Don't** reduce Light Trails to a recolor of Simple or restore the large local-memory tile.
- **Don't** copy Orbit's local light effects or inset panel frames into Simple.
- **Don't** add alignment grids, animated session rails, fabricated records or decorative metrics to Orbit.
- **Don't** repeat the bitmap atom, substitute a synthetic letter-M identity or add a central wordmark inside the workplane.
