# Mingshen Harness

**Windows 本地优先的 AI 编程、办公与对话 Agent。**

连接自己的模型供应商，把编程任务、Office 交付、普通对话、工具执行和并行 Agent 放在同一个桌面工作台中。会话与项目记忆保存在本机，模型和扩展服务由你选择。

**版本 1.3.7** · **Windows 10/11 x64** · **简体中文 / English**

### 1.3.7 运行治理与远程生图确认

- **一键已读**：顶栏新增全局已读入口。点击后立即清除 CodeAgent、WorkAgent 和 ChatAgent 会话的完成未读标记，以及 Windows 任务栏应用图标的未读数字，无需额外确认；不会处理审批、提问、运行任务或删除历史。
- **独立生图协议**：供应商可明确选择 `OpenAI /v1/images`，不再借用 Chat Completions 或 Responses。该协议新增或导入的模型默认且强制为纯图片生成模型，隐藏上下文、工具、思考等级和提示缓存等文本参数；即使调用方省略输出模态，后端也按纯图片模型处理，显式文字/混合输出或工具调用仍会拒绝。专用供应商不会出现在聊天、审批、压缩、润色或反推提示词的语言模型选择中，也不接受文本提示缓存配置；从文本协议切换到该协议时会清除旧缓存设置。旧 Responses / Chat Completions 下已配置的纯图片模型继续兼容。
- **URL 生图结果**：供应商返回 Base64、远程图片 URL 或混合结果时，Base64 仍按原流程安全保存；URL 结果不会直接写入素材库。为显示应用内预览，主进程先以不带模型 API Key、Cookie 或浏览器凭据的请求，将图片载入有限内存；用户确认后才把已验证候选保存为素材并写入素材库。预览弹窗提供“在浏览器打开”，加载中、加载失败和已就绪状态均可用；该操作不等待预览下载队列，也不改变保存状态。
- **来源与提示词保留**：确认保存的图片沿用本次生成请求的正面、负面及供应商修订提示词，后续可加入画布、下载、批量导出、删除或执行提示词回导。
- **受限预览与保存边界**：主进程只连接无凭据的公开 HTTPS 图片地址，不转发模型 API Key、Cookie 或浏览器凭据；拒绝私网、回环、本机、保留地址、不安全重定向和 DNS 重绑定目标。单图 25 MiB、单次结果 100 MiB、单次下载 90 秒属于 URL 生图预算；既有手动导入、拖放和批量导出/ZIP 的 500 MiB 预算单独适用。确认保存时仍须通过完整格式和像素校验。
- **默认浏览器独立检查**：外部浏览器入口只提交不透明候选 ID 和本次请求 ID；主进程重新核对候选、期限、字面网络目标和 `browser.use` 策略，并对域名执行最多 5 秒的 A/AAAA 全量解析，任一结果不是公网地址即拒绝。解析完成后、交棒前会再次核对候选期限、operational 与网络/浏览器策略，之后才调用系统默认浏览器。外部浏览器拥有独立 Cookie、登录和验证码会话，不会把验证码或 Cookie 回传到 Mingshen Harness；其后续 DNS、重定向和页面导航也不受应用内受控图片下载器的同一约束。浏览器中能打开图片不表示 Mingshen Harness 的远程下载安全校验已经通过。
- **并发生图与提交快照**：生图工作台与主进程分别限制最多 3 个并发生成请求，每项有独立状态和取消入口，切换 ChatAgent 或工作站不会中断。每个 generation 的总预算为 600 秒，包含供应商请求、响应解析和结果提交；远程 URL 预览下载仍为 90 秒，文本润色、反推提示词等旧流程的预算独立。请求提交时快照正面/负面提示词、参考图和目标画布；结果返回时保留用户之后编辑的提示词及当前画布，不会复活已关闭或删除的画布。
- **统一运行与恢复**：请求在附件处理、命令预处理和模型调用前先持久接纳并分配 `runId`。相同幂等键和相同载荷返回原运行，同键不同内容返回冲突；停止绑定具体运行，不会误停同会话下一轮。崩溃重启把未结束执行标为中断，用户继续前须先核实可能发生的副作用，不自动重放已完成工具。
- **事件续接与模型等待**：持久事件支持会话快照、事件游标、SSE `id` 与 `Last-Event-ID`；事件默认保留 30 天或总计 256 MiB，过期游标明确要求重新取快照。设置 → 运行与集成 → 运行治理可把一次模型请求的首个有效响应等待设为默认 5 分钟、流空闲设为默认 15 分钟，`0` 关闭；心跳不续期，等待工具、审批或用户输入期间不计入，这不是任务或 SubAgent 的总运行时限。
- **管理策略与工具结果**：当前用户可在应用内设置限制；机器管理员可使用 `%ProgramData%\MingshenHarness\managed-policy.json` 部署只读策略。内置边界、机器策略、应用策略、模式、项目与隔离限制叠加，拒绝优先，`full_access`、项目文件和 Agent 提示词不能放宽。机器策略存在但损坏、不可读或版本不支持时，新模型、工具和扩展执行暂停，历史查看、诊断、停止与清理仍可用。工具结果统一区分执行状态、副作用确定性、结构和业务验证；Schema 校验失败不记成功，可能已有写副作用时保留屏障并禁止自动重放。
- **任务认领与办公回执**：活动计划步骤使用 generation、原子认领、1 分钟心跳和 5 分钟租约，迟到旧 generation 不能覆盖新计划；租约过期只核活，不杀任务或自动重派写操作。主 CodeAgent/WorkAgent 在宿主、完全访问且有工作区时，工具批次后产生的 DOCX/XLSX/PPTX/PDF 变化会自动进入办公交付服务，生成绑定最终文件哈希的回执并检查包、结构、内容、公式、重算、渲染和视觉状态。可修复问题会回到当前模型，按每个文件最多 3 轮受控修复；预算耗尽后本轮对该文件的写入被阻断，必须查看回执并另起运行继续。缺少 Office/LibreOffice、视觉模型或预算截断时如实降级，不因文件写入成功而宣称交付通过。
- **开发者与本地管理接口**：`/v1` 仅监听回环地址并使用 Bearer Token，服务重启后轮换 Token。新集成可使用会话快照、幂等发送、准确运行停止、事件续接和有效策略；计划认领支持 `claim`、`heartbeat`、`settle`、`recover`，外部办公回执写入仅支持宿主受控的 `prepare`、`check`，其中准备回执只接受会话工作区内相对路径。外部 `visual-batch`/`record-visual` 被拒绝，不能伪造已验证视觉证据；桌面宿主仍保留内部视觉续接。停止返回 `202` 只表示 `stopRequested`，必须在准确 `runId` 上观察终态。完整约定见[开发者接口](docs/DEVELOPER_API.md)和[运行治理](docs/RUNTIME_GOVERNANCE.md)。
- **本地诊断**：运行日志覆盖桌面接口、本地 API 和后台任务的错误及警告，设置页可查看当前留存窗口的数量、来源和操作汇总，也可主动导出 JSON。日志本地保留最多 30 天、五个文件合计最多 15 MiB；统计按记录而非去重故障计数，不是永久历史。已知过载、写盘失败造成的遗漏和损坏记录单独标记，导出前仍应检查可能出现的敏感信息。
- **交互修复**：修正生图画布的滚轮事件监听，避免被动监听器重复报警并保持原有缩放操作；更新 Electron 控制台事件接法，减少同一 IPC 错误的重复记录。

1.3.7 的 URL 结果在确认前只作为短期预览候选，不写入素材库。关闭预览或选择“稍后”不会立即丢弃候选，仍可在约 30 分钟内重新打开；候选到期、被明确丢弃或应用退出等情况下才结束可用期。混合结果中有效的 Base64 图片仍可正常保存，不因同批 URL 候选等待确认而丢失。此前并发生图版本的完整回归为 **3,131 项通过、15 项环境跳过、0 失败**，生图 Electron 专项 **17 组通过**；它们是本轮诊断调整前的基线，当前类型、Lint、生产构建、定向和资源检查范围见 [1.3.7 验证记录](docs/VALIDATION_1.3.7.md)。正式安装器与更新 ZIP 的精确大小和 SHA-256 以 `apps/desktop/release-artifacts/` 旁置元数据为准，安装、升级和卸载另行验收。

### 1.3.6 生图画布库与参考图

- **本地画布工程**：新建和导入的画布将作为独立工程文件保存在应用的本地数据目录，关闭标签不会删除工程；再次进入生图工作台时，可从“我的画布”重新打开。
- **我的画布**：素材侧栏增加本地画布库，支持搜索、打开、重命名、复制、删除和定位文件。关闭顶部标签只结束当前编辑会话，只有画布库中的删除操作才会移除工程。
- **导入与保存入口**：工作台明确区分导入素材和导入画布，并提供新建、打开、导入、重命名和关闭入口；画布文件不依赖用户后来移动或删除原始图片。
- **本地数据边界**：Renderer 只提交合法画布标识，主进程负责解析本地目录和文件。损坏、越界或格式不符的工程会被拒绝，不会用任意本地路径覆盖画布文件。
- **兼容旧工作区**：首次使用新画布库时会迁移旧版 SQLite 工作区中的画布；迁移保留原设置备份，重复启动不会覆盖已存在工程。
- **供应商尺寸偏差**：供应商返回有效图片但分辨率不同于请求值时，仍保存并按实际尺寸加入画布，同时显示逐张尺寸警告。
- **参考图生成**：生图设置新增“使用参考图”开关，默认关闭并随工作区保存。开启后按照素材勾选顺序发送最多前 3 张；勾选超过 3 张时仍只参考前三张并显示处理提示，可预览和移除已选图片。
- **手动上传**：可直接上传 PNG、JPEG、WebP 或 GIF 作为参考图，上传文件会进入本地素材库并自动选入参考。GIF 和 WebP 都会只取第一帧并转换为 PNG 后发送；转换后的参考图仍受单图 25 MiB 限制，素材库中的原文件不会被替换；APNG 暂不支持。
- **接口与兼容性**：没有参考图时继续使用 OpenAI Images 兼容 `/images/generations` JSON 请求；启用参考图后改用 `/images/edits` multipart 请求，单图或多图参考均走编辑接口。网关不支持编辑、多图或相关参数时会明确报错，不会静默退回无参考生成。
- **数据边界**：只有用户主动开启参考图并明确勾选后，图片才会发给所选图片供应商。Renderer 只提交受控素材 ID，主进程校验、去重并读取文件；图片反推仍独立使用视觉语言模型。
- **后台生图**：图片请求发出后可切换到 ChatAgent 或工作站；应用保持运行期间，生图工作台会在后台等待供应商结果并将图片保存到素材库和当前画布。切换页面不会取消请求，仍可在生图工作台主动取消；退出应用会结束未完成请求。
- **提示词回导**：在 Mingshen Harness 中生成的素材会分别保存用户原始正面提示词、负面提示词和供应商返回的修订提示词，不把供应商修订内容冒充用户原文。素材卡可把记录导入当前工作区；每次导入都先询问是否覆盖，取消不会改动现有正面或负面提示词。某个素材生成时明确没有负面提示词，确认后可清空当前负面提示词；旧版本或记录不完整时只明确提示无法可靠恢复，不猜测、不拆分旧文本，也不清空当前提示词。外部导入图片不会获得可信生成提示词记录，仍可使用反推提示词。
- **批量素材**：素材选择栏支持全选当前搜索结果、清空选择、把所选素材加入当前画布、合并导出为 ZIP 或确认后批量删除；选择上限为素材库的 200 张，ZIP 内源图片合计上限为 500 MiB，导出时会显示已处理素材数与字节进度。批量删除只要有一张仍被任一已保存或当前打开的画布引用，就会整批取消；删除后会同步清理素材记录和旧工作区备份中的绑定提示词。执行前会检查并处理画布回收区；无法安全清理时会取消删除。ZIP 只包含图片，不附带未经独立来源验证的提示词 sidecar。

1.3.6 生图素材导入和批量 ZIP 导出各有 500 MiB 源图片预算；导出显示素材数和字节进度。Windows x64 安装包按本仓库源码与随包文档生成，精确文件大小和 SHA-256 以 `apps/desktop/release-artifacts/` 中的 `.sha256`、`.json` 实测元数据为准。安装器未运行，安装、升级和卸载尚未验收；之后若修改源码或随包文档，需要重新打包。检查结果和边界见 [1.3.6 验证记录](docs/VALIDATION_1.3.6.md)。

### 1.3.5 简约主题与桌面体验

- **简约主题**：收紧标题栏、工作区、会话列表、对话和输入区的层级与留白，保留原有业务布局和键盘操作；空任务区域按内容收缩，不再保留大块无内容占位。
- **启动展示**：原子标识与轨道动效覆盖主屏并置顶展示，状态来自真实启动阶段；它不是独占全屏。正常展示且主窗口就绪时约 5 秒，设置 → 桌面体验可关闭，展示中可跳过；异常或约 8 秒兜底会结束展示。已同意协议的用户在展示期间可选预热有界会话索引，不读取会话正文或密钥，也不保证启动提速。首次协议阅读计时在展示结束且主窗口实际显示后开始。
- **桌宠**：可在设置 → 桌面体验开启独立透明桌宠窗口。Windows 置顶使用 Electron `screen-saver` 窗口层级；置顶期间每 200ms 检查系统隐藏/最小化，并在窗口仍可见时重新申明置顶和 Z 序，以处理未触发失焦事件的其他置顶窗口遮挡；系统隐藏后延迟 120ms 尝试无焦点恢复。桌宠自己的原生右键菜单打开时暂停 Z 序重申，避免菜单被遮住。用户主动隐藏、关闭或取消置顶不会被重新唤起。此为应用级尽力处理，不保证覆盖 UAC 安全桌面、独占全屏、其他 Windows 会话或系统级窗口，也未以自动化单测替代真实 Win32 Shell 验收。内置 36 段由用户角色视频处理的透明动作，按任务、互动、拖动与休息状态调度；播放失败时回退角色静图，但不承诺无损去背。工作会话面板显示当前会话的标题、状态和本地运行时长，可折叠并跳转会话；标题默认显示，可在设置中关闭，关闭后不向桌宠窗口传递标题。右键菜单提供快捷 Chat、互动、休息和显示选项。空闲趣味动作可调整频率或关闭，免打扰会暂停自动问候、闲聊、趣味动作和自动休息，不影响真实任务或手动互动；闲聊仅使用本地预设短句，不调用模型或联网。除标题外不向桌宠传递会话正文、文件内容、工作目录路径、命令参数或审批细节；系统减少动态效果时保留静态反馈。原始视频保留，素材处理与限制见[桌宠动画说明](docs/COMPANION_ANIMATIONS_1.3.5.md)。
- **安装资源**：Windows 安装资源包含与原子标识配套的头图、侧图和标识素材；欢迎页内嵌 `00–07` 共 8 帧原子动画并按定时器轮换。正式安装器、ZIP、SHA-256 和大小需以本次实际打包输出为准。
- **插件与联网**：内置插件技能支持实际入口文件名或默认 `SKILL.md`，缺失资源会列出可用路径；设置支持单插件或市场根逐项校验。`web_search` 与 `web_fetch` 的单次请求预算为 90 秒，并区分取消、超时和网页服务错误。

### 1.3.4 工作站与可靠性

- **Mingshen 工作站**：内置 780 个独立工作场景，覆盖 65 种任务结构、12 个分类。每项均提供保留原有方式的简略版和详细版；默认中文详细提示词不少于 800 汉字，由场景专属内容与同类共享的专业流程、执行规则组成，编辑后长度可能变化，字数不等于质量验收。详细版写明资料、专业方法、版式、场景风险、验收及真实推荐技能。支持分类、交付格式与多关键词组合搜索、全文预览和复制；切换版本保留已编辑内容，草稿可撤销、保存及导入导出。模板涵盖文档、演示、表格、财务、人力、采购、销售、协作与教学，Office 协作产品按当前支持的文件或交接规格交付。实际文件由 WorkAgent 按需制作，详见[模板说明](docs/WORKSTATION_TEMPLATES.md)。
- **内置技能与侧栏**：同源、同路径技能的多个版本按语义版本只显示最新版，独立来源及用途变体继续保留；旧选择和权限规则兼容。修复 Code/Work 侧栏因行布局错位产生的大块空白，空项目与长列表均按内容分配空间。
- **生图工作台**：分别选择图片模型和语言模型，先预览并确认润色提示词再生成；可配置质量、自动/1K/2K/4K或自定义尺寸、比例、透明背景和1–10张输出；素材卡提供保存原图按钮，由系统保存对话框选择路径。支持视觉模型反推、画布图层编辑、工程导入导出与 GIF 合成。生图接收 Base64 时校验后直接保存，接收远程 URL 时先做公开 HTTPS 安全预览，仅由用户确认后保存；参数支持范围取决于所选模型/网关，拒绝时显示供应商错误；GIF 由已选图片帧组成。
- **AutoDrive 与角色协作**：点击自动规划下一步，由当前模型只读结合历史、计划和仓库证据提出至少三个不同方案，选择后加入草稿。worktree 模式只读取已建立的实际目录；尚未建立时提示先在该会话运行任务。协同总控可拆解工作包、点将并行执行、汇总结果，并通过独立 QA 记录真实质量状态。
- **项目开发工作面**：`Ctrl+Shift+P` 同时搜索文件、命令和历史会话；项目支持分支/worktree 分组和未读状态。右侧新增真实 Shell 多标签终端；本地审阅可按 Git、Branch、会话和上一轮切换，选择代码行写评论后送入输入框。
- **草稿辅助**：支持一键润色并预览确认，可在设置中指定润色模型；下一轮临时指令随该次发送或队列项使用，项目语气按工作目录保存。
- **运行中引导**：主 Code/Work/Chat 和快捷 Chat 可发送补充文字，当前回复和工具批次继续执行，在下一次模型请求接入。界面显示等待接入、已接入或未应用；“加入下一轮”仍用于当前任务结束后的独立任务。

- **DeepSeek 工具链续接**：修复 thinking 开启时，受控工具链中合成步骤缺少供应商续接状态而触发 HTTP 400 的问题。
- **原生 Memory 摘要**：修复 512 token 输出预算被推理内容耗尽后无法保存任务摘要的问题，并保留取消、超时及不写入半截摘要的边界。
- **原生沙箱终止**：为停止失败或子进程未关闭增加有界结算；清理结果无法确认时继续保留写入屏障，不降级到宿主执行。
- **会话目录同步**：修复增量同步跳过的未知会话在 revision 推进后无法恢复的问题，并覆盖新建、删除和升入可见范围的目录变更。
- **恢复路径竞态**：收紧宿主快照及 Git 恢复路径在检查与 I/O 之间的重解析窗口，以句柄级检查拒绝 junction、reparse point 和 NTFS 硬链接，并在临时文件 Flush/SHA 校验后通过受保护句柄提交，失败时恢复旧内容或保留明确备份；静态链接拒绝和用户主动恢复语义保持不变。
- **缓存与命令清理**：移除工具结果去重产生但无人读取的缓存条目；持久命令后续清理成功时清除旧错误并释放名额，未确认时保留命令记录、写入屏障和租约。Native Sandbox 的未确认清理另保留 typed tombstone。退出时所有服务也会完成结算后才关闭数据库。
- **对话与附件**：Chat Completions 的 `[DONE]` 不再单独视为成功，必须收到正式非空 `finish_reason`。每条消息最多 10 个附件、单文件 25 MiB、合计 50 MiB，并在读取文件字节和 IPC 前预检。
- **ChatAgent 联网控制**：输入区可按会话切换“允许联网 / 禁止联网”。允许时只开放 `web_search`、`web_fetch`，不再逐次弹出联网审批；禁止时工具从模型列表中隐藏，主进程仍拒绝伪造调用。此开关不阻断所选模型供应商连接，也不改变附件提交行为；基于原对话新建或分支时保留其禁网状态。
- **项目与执行边界**：OpenCode/Mingshen 项目 JSON 与项目 Markdown Agent 只在项目已信任后加载，项目 `{file:...}` 指令引用不能越出工作区；项目 `build` 创建独立 Profile，不覆盖内置 `primary`，撤信任会清理项目来源。LSP 查询同样限定当前工作区。全访问宿主命令取消或进程树清理失败时有界结算并保留未确认屏障；启动初始化失败会在有界清理后退出，不继续持有单实例锁。
- **文档与集成防护**：Office 解析进入有界 worker，ZIP 路径、条目、解压总量和 XML 主动声明有硬限制；Excel 请求有累计工作量预算，危险公式和外部引用被拒绝，嵌入工作簿限制递归深度、数量与累计解压量。宿主文档覆盖使用受控提交与失败恢复：锁定旧目标、备份、提交、回读核对，并在失败时恢复旧内容或保留明确备份；Windows 分步重命名之间仍有极短 gap，不宣称断电级无间隙原子覆盖。MCP OAuth 请求拒绝重定向，编辑密钥时保留未改值；ACP 处理失败/中断，并有界处理取消请求，abort 失败或超时会清理本地 waiter 并报告远端停止未确认；本地浏览器预览使用会话授权令牌；无头 API 复用正常会话校验。实验入口每次先构建当前源码；插件市场清单使用同进程队列、跨进程锁、随机临时文件及原子替换，正常写入最多等待 15 秒。锁超过 60 秒时不按 mtime 自动删除，会保留原清单并报告锁路径，要求确认无 writer 后仅人工删除锁文件。

## 快速开始

### 使用安装版

1. 从 [GitHub Releases](https://github.com/SkyH1aa/MingshenHarness/releases) 选择所需版本，运行 Windows x64 安装包。
2. 首次启动时阅读三份协议与内置使用手册。
3. 在“设置 → 供应商与模型”添加自己的服务地址、API Key 和模型。
4. 选择 CodeAgent 或 WorkAgent 并指定工作文件夹；如需不带本地工具的普通问答，切换到 ChatAgent 新建独立对话。

安装版无需另装开发用 Node.js/pnpm。项目命令、stdio MCP 和外部运行时按各自依赖配置。应用不提供免费模型额度或 ChatGPT 订阅；界面中的 `Chatgpt Pro` 仅为可编辑的示例供应商名称。

### 从源码运行

需要 **Windows 10/11 x64、Node.js 24+、pnpm 11+**，仓库固定包管理器为 `pnpm@11.25.0`。获取源码后，在仓库根目录运行：

```powershell
pnpm install --frozen-lockfile
node scripts/provision-electron-runtime.cjs
node scripts/provision-native-runtime.mjs
pnpm dev
```

准备脚本会下载并校验固定版本的原生 Windows 沙箱执行器。该 EXE 不随源码提交，新克隆需要执行上述准备步骤；来源与哈希见[运行时说明](apps/desktop/resources/native/PROVENANCE.md)。它只用于沙箱执行，不使用用户的 Codex 账户或模型服务。

需要运行构建后的实验版时：

```powershell
pnpm build
.\run-experimental.cmd
```

实验版使用独立数据目录 `%LOCALAPPDATA%\MingshenHarnessExperimental`。启动器每次都会先核验固定原生沙箱并重新构建当前源码，再启动实验版，避免删除源码、配置变化或产物缺失时误用旧构建。为避免旧实例占用文件，替换构建前仍应先从托盘正常退出正在运行的实验版。

### 执行环境

受保护模式可选择 Windows 原生 MXC 或 Docker。MXC 需要兼容的较新 Windows 11；Windows 10/旧版 Windows 11 使用 Docker。隔离不可用时，受保护操作会停止，不会静默改在宿主执行。

Docker Desktop、WSL2 和 Embiody 属于按需配置的外部依赖，不包含在安装包中。完整要求见[使用手册](docs/USER_GUIDE.md)和[安全说明](SECURITY.md)。

## 模型配置

每个供应商选择一种协议，应用自动追加请求端点。Base URL 不要重复填写完整请求路径。

| 协议 | 典型 Base URL | 鉴权 |
| --- | --- | --- |
| OpenAI Responses | 供应商提供的 `/v1` 地址 | 通常为 `Authorization: Bearer` |
| Chat Completions | 供应商提供的 `/v1` 地址 | 通常为 `Authorization: Bearer` |
| OpenAI Images | 供应商提供的 `/v1` 地址 | 通常为 `Authorization: Bearer` |
| Anthropic Messages | 供应商提供的 `/v1` 地址 | 通常为 `x-api-key` |
| Google Gemini 原生 GenerateContent | `https://generativelanguage.googleapis.com/v1beta` | `x-goog-api-key` |

OpenAI Images 的无参考生成请求使用 `/images/generations` JSON，参考图编辑请求使用 `/images/edits` multipart。Base URL 填写到 `/v1`；把完整图片端点填入 Base URL 会被拒绝，应用不会自动删改端点路径。Gemini 的 Chat Completions 兼容接口使用 `https://generativelanguage.googleapis.com/v1beta/openai`，与原生协议分开配置。DeepSeek 的官方路径按协议区分，完整地址、推理续接及缓存条件见[供应商缓存说明](docs/PROVIDER_CACHING.md)。

每个模型可以配置上下文窗口、输出上限、输入模态、工具能力和思考等级。供应商长按拖动排序、模型星标会同步到聊天、新建会话、子 Agent、审批、压缩和记忆分析等模型选择入口。

图片供应商仍在“供应商与模型”中管理。建议使用独立 `OpenAI Images` 供应商并把 Base URL 填写到 `/v1`；通过手动输入或模型列表导入的模型都会默认勾选并锁定“仅图片生成模型”，后端在省略输出模态时也使用图片默认值，该模型不参与聊天、规划、审批、压缩或语言模型任务，相关文本与提示缓存参数不会显示。纯图片协议会拒绝缓存配置，切换到该协议时会清除旧缓存设置。生图工作台单独选择图片模型及语言模型，润色和反推提示词必须另选文本/视觉模型。无参考图时使用 `/images/generations` JSON 请求；启用参考图后使用 `/images/edits` multipart 请求，按勾选顺序最多发送前 3 张，单图和多图参考都依赖网关的编辑能力。当前实现使用标准同步 Images 响应，不启用第三方私有的异步任务轮询；网关不兼容时会明确报错，不会把请求改投 Chat Completions、Responses 或静默退回无参考生成。应用不嵌入外站账号页面；供应商只返回远程 URL 时，按上文的公开 HTTPS 安全预览与确认保存流程处理，不直接写入素材库。画布工程、图片素材和可移植工程互相独立，删除素材前仍需检查画布引用关系。

“模型体系”控制适配规则，不转换 API 协议。第三方网关需确认支持对应字段透传。Gemini / DeepSeek 默认使用隐式前缀缓存，不自动创建收费显式缓存资源；命中率由模型、请求、缓存有效期和供应商路由共同决定。

## Agent 模式

主界面标题栏的 CodeAgent、WorkAgent、ChatAgent 用于切换工作方式，不是三个独立模型供应商。三种模式共用供应商、模型、思考等级、上下文压缩和基础运行配置。

| 模式 | 工作区与工具 | 适合的任务 |
| --- | --- | --- |
| CodeAgent | 完整代码工作台、文件/命令、代码索引、诊断、测试与验证工具 | 开发、排障、重构、测试、代码审查和工程交付 |
| WorkAgent | 与 CodeAgent 共用会话和工作目录，并额外提供 Work 专精技能与 `office_document` | Word、Excel、PowerPoint、研究、分析、运营材料和办公成品 |
| ChatAgent | 无需工作目录，只开放 `web_search`、`web_fetch` 和用户主动上传的只读附件问答 | 普通问答、学习、写作、资料整理和不涉及本地文件操作的对话 |

CodeAgent 与 WorkAgent 可在同一会话内切换，不新建工作目录，也不复制历史。任务运行、等待审批、等待回答或正在压缩时不能切换；完成或手动停止后切换只影响下一轮。已有消息、工作目录、草稿、附件、计划、上下文摘要和权限记录不会被清空。ChatAgent 是独立的会话目录与页面，不能与 CodeAgent/WorkAgent 直接互转，也没有工作目录或本地工具入口。

ChatAgent 的侧栏顶部、分组加号、“未分组”加号和空态新建会直接创建空白对话，不再打开完整的新建弹窗。分组内新对话沿用该组最近更新的未归档 Chat 的供应商、模型、推理等级和聊天设置；来源按更新时间选择，不按置顶显示顺序选择。空分组回退最近未归档 Chat，没有 Chat 时使用可用模型默认值。历史、草稿、附件和运行状态不会复制，也不继承 Code/Work 工作目录。

ChatAgent 侧栏可进入批量管理，按搜索结果跨分组勾选或全选，再批量归档、恢复或永久删除。归档和删除须确认，运行中的会话不能归档；删除会先停止相关任务。部分操作失败时，已成功项保留结果，失败项继续勾选并显示原因供重试。

Agent 配置默认同时适用于 CodeAgent 和 WorkAgent，并可勾选限定适用模式；至少保留一个适用模式。ChatAgent 固定使用内置聊天行为，不显示自定义 Agent 配置。设置中的模型、工具、权限和项目指令仍按各模式的实际边界收窄，不会因为共用配置扩大 ChatAgent 权限。

### CodeAgent 工程能力

五个内置工程技能覆盖工程开发、前端、后端与数据、排障和验证，按任务继续加载仓库侦察、大型改动、故障取证、测试设计及发布安全参考。连续相同工具失败会触发策略调整要求，代码索引、LSP、诊断和测试/Lint/类型检查支持最多三轮修复验证。

大工具输出在有界保留区内由 `read_tool_output` 分页恢复，明确标注中间缺口及淘汰限制。逐文件写前检查点仅适用于主会话、完全访问、宿主执行下的受管文件工具，受文件大小和累计预算约束；命令及外部 MCP 副作用不属于逐文件快照保证。容量和验证边界见[使用手册](docs/USER_GUIDE.md)及[CodeAgent 调研与实现](docs/CODE_AGENT_RESEARCH_1.3.3.md)。

`spawn_subagent` 返回后台任务后，主 Agent 可继续独立工作，再由 `wait_subagents` 收集真实结果。SubAgent 没有固定 10 分钟总运行期限，仍会在明确完成、失败、用户停止或父任务取消时结束；单次模型、工具及网络请求保留各自超时。

## 技能与本地插件

CodeAgent 与 WorkAgent 自动发现内置能力和所有已安装且启用的 Skills/插件，按上下文检索，再由 `use_skill` 读取相关正文或参考。已启用插件默认按需激活：Agent 可通过 `discover_capabilities` 找到插件，再用 `use_plugin` 在本轮激活，无需先手动引用；`activation: "required"` 插件仍需用户手动引用。输入框“+ → 引用”也可手动选择，选中项优先，选择随会话保存；内置 Skill/Plugin 合计最多 32 项。手动引用不关闭自动发现，停用扩展不进入结果。加载及受控预载仍遵守 Agent 配置和审批，发现本身不执行脚本或扩大权限；GitHub、浏览器两类内置 Plugin 的引用只表达工具偏好，不会自动登录或连接服务。

CodeAgent 有 9 个基础技能入口；WorkAgent 有 16 个基础入口，另有 **98 个当前活动来源技能**。`WorkAgentSkill/` 的 124 个物理来源、104 个不同源正文 SHA 和 93 个名称仍完整保留用于溯源；同源、同路径的 9 组历史版本中，26 个旧版本不再重复进入自动发现或手动引用列表。比较使用语义版本，独立来源及不同用途不会按名称或正文 SHA 合并。PDF 的 10 个物理来源仍保留，当前展示 production、viewer、reading 和 loose 四种独立来源。旧会话的选择对应到最新版，旧配置的拒绝或审批规则继续生效。PPT Master 6.9.0、ASD-STE100 0.4.0 及这些来源仅对 WorkAgent 提供，Code 保持原有范围；切回 Work 后恢复其会话选择。正文按需加载，不把来源数当作独立原创技能数。出处与逐项映射见[Work 技能清单](apps/desktop/resources/prompts/skills/work-sources/inventory.md)和[第三方说明](THIRD_PARTY_NOTICES.md)。

本地插件使用 `.mingshen-plugin/plugin.json`，可声明 Skills、Markdown 命令、MCP 和受控 Hook；同时兼容 `.codex-plugin`、`.zcode-plugin` 与旧根清单。设置 → Skills 与插件 → 本地插件开发市场支持添加 `marketplace.json`、校验、手动安装、启停及更新；校验既可选择单插件，也可选择市场根目录逐项查看结果，不会在校验时注册或安装。市场打开、刷新或重新检查时，只读轮转检查最多 10 个市场、每个最多 200 个条目；只有严格语义版本较新且来源路径复核一致时提供更新，用户点击后才安装，不静默执行新版。安装生成独立副本，源码变更后需更新；单扩展最多 20,000 文件、64 MiB。主 Code/Work 的宿主 Windows 会话可按读取权限和审批使用只读 `local_plugin` 检查工作区内源码，安装与更新由用户在设置中完成。常规动作 Hook 仍须主会话、已信任项目、完全访问及宿主执行，并按动作审批；`activation: "required"` 插件仍需手动引用。

插件可声明 `BeforeModelRequest` prompt-only 钩子，在已激活插件的主 Code/Work 本轮每次模型请求和重试中加载声明文本，也覆盖本轮触发的压缩和记忆请求。`position` 可选 `before`（默认）或 `after`，`format` 可选 `context`（默认）或 `plain`。`format: "plain"` 是可复用的去归属开关：无论 `before` 还是 `after`，都不添加 `Plugin N`、插件标题、来源归属或 `<mingshen_plugin_context>` 包装；旧版 `format: "context"` 继续保留这些归属和低优先级上下文标记。默认的 `before + context` 保持旧版行为；`before + plain` 在普通输入轮次将普通文本放在原文前；`after + context` 在请求末尾保留包装；`after + plain` 在原文后用单个换行直接追加普通文本，例如 `xxxx\n123abc`，没有空行分隔。`before/after` 表示在本次发往模型的请求内容中的位置，不是响应前后；`plain` 是普通用户优先级内容，不会变成 system 指令或获得权限。未填写 `position`/`format` 时保持旧的 `before + context` 行为。`before + context` 仍进入系统上下文；其余用户内容型注入若遇到普通输入会就近追加，若请求以工具结果结束则按协议在完整工具结果内容之后添加普通用户文本块，或在需要独立消息的协议中新增普通 user 尾消息，若以 assistant 结束则新增普通 user 尾消息。任何协议都不会把用户内容型插件文本插入 tool call 与其 tool result 之间，也不会改写或拆开工具调用/结果配对。附加文本仅用于当次请求，不累积或写入会话历史。新激活从下一次请求生效，不追补已发请求；活动父任务通过 `runSubagent` 派生的子任务也只继承所选或已激活插件中的声明式提示文本，不开放插件动作。收集总预算为 3 秒，单条提示最多 4,000 字符、聚合最多 12,000 字符；读取失败、超时或超限时，本次模型请求会在发送前失败，避免静默漏掉标记。它不用于 ChatAgent、没有活动父运行映射的独立 `@` 子会话、审批安全审查、独立 AutoDrive/草稿润色或事后标题请求。内置插件技能的入口和引用资源按需加载，缺失资源时会列出实际可用路径。兼容清单不表示兼容第三方私有 API，上游脚本和依赖也不会自动安装或执行。

内置 `skill-creator`、`plugin-creator`、`harness-plugin-api` 可指导创建自己的 `SKILL.md`，或生成插件、Harness 适配技能、市场条目和手动安装说明。开发步骤、宿主校验、SDK 及完整安全边界见[本地插件接口](docs/LOCAL_PLUGINS.md)。ChatAgent 不加载 Skills、插件、MCP、Hooks 或自定义 Agent。

## 下一轮自动队列

主界面 CodeAgent、WorkAgent、ChatAgent 的主会话运行中，可点击“加入下一轮队列”，保存预编辑的文字及验证后的附件。每会话最多 **10 条待发消息**，当前执行不计入上限；单附件最多 25 MiB，队列附件合计最多 50 MiB。支持编辑文字、整体替换附件和删除，严格按首次加入顺序发送，不提供重排。

上一任务正常完成且后台清理结束后，自动发送队首，之后依次执行；切换到其他会话或收起窗口不影响派发。编辑时暂停发送，保存或显式取消后才允许继续。手动停止、运行失败、附件替换失败、自动发送失败、应用重启或编辑窗口丢失时保留并暂停队列；显式恢复或同会话后续一轮正常成功后从首项接续。审批等待不会推进，配置变化或派发结果未确认时阻塞队首，不会跳过。

队列不随 fork 复制，删除会话时清理；快捷 Chat 和实际 SubAgent 不提供队列。完整生命周期与防重放边界见[T3 Code 调研与自动队列](docs/T3_CODE_RESEARCH_1.3.3.md)。

## 工作区与项目记忆

CodeAgent 和 WorkAgent 的会话按工作文件夹组织，可搜索、分支、归档和批量管理。ChatAgent 在独立对话页按分组、置顶和归档管理，不要求文件夹。待发送文字、格式状态和附件自动保存草稿，切换会话或正常重启后恢复；发送被接收、手动清空或删除会话时移除相应草稿。

输入框默认以 Markdown/LaTeX 原文编辑；粘贴、键入、输入法组合和快捷键不会自动跳到格式预览。只有用户手动点击眼睛按钮才会切换预览，预览选择会随草稿保存并在正常恢复时保留，发送始终使用原文。设置 → 外观与语言可关闭输入区的预览按钮。“简约”和“光轨”共用会话与功能，界面风格在重载或重启后生效。

光轨将会话、聊天、文件审查、终端与任务放在连续工作平面中，日夜主题共享紧凑的信息层级和键盘焦点反馈。任务区支持拖动或键盘调整高度、恢复默认和单行收起，偏好按工作区保存；窄窗使用抽屉。Work 空会话提供 Word、Excel、PPT 起始草稿，点击只填入输入框。未保存计划时，跨会话导航、新建及归档当前会话或其祖先前会提示先保存或取消；状态动效遵循应用及系统的减少动态效果设置。

设置 → 项目指令与信任可按工作区选择：

| 记忆后端 | 本地目录 | 自动维护 |
| --- | --- | --- |
| 原生 Memory | `.harness-memory/` | 偏好、任务日记摘要、检索与归档 |
| TencentDB 本地核心 | `.harness-tencent-memory/` | 记忆分析模型提取语义记忆，再判断存储、跳过、更新或合并 |

工作区内的项目 Agent 配置和项目指令仍应先核对来源。OpenCode/Mingshen 项目 JSON 与项目 Markdown Agent 只会在该工作区已信任后加载；项目配置通过 `{file:...}` 引入的指令必须位于当前工作区内，并以句柄级受限读取拒绝链接或越界文件。项目 `build` 不会改写内置 `primary`，而是创建独立项目 Profile；撤销项目信任会清理对应项目来源。LSP 也只能查询当前工作区内、经过路径边界检查的真实文件。

TencentDB 可配置分析主备模型；主模型留空时使用当前主会话模型。提取与冲突判断提示复用固定上游版本的通用 `chat` 模板，宿主校验结果后原子保存。分析失败不会改存完整回答或规则摘录，切换后端保留两套目录。

该集成使用 TencentDB Agent Memory 的本地核心，不接入腾讯云记忆服务，也不等同于完整上游产品。固定版本、原文提示来源、集成范围与许可见[第三方说明](THIRD_PARTY_NOTICES.md)。

## 创作与项目工作面

标题栏的“工作站”和“生图”可随时进入独立工作面，对话继续保留在原会话。工作站可按类别、格式和多关键词筛选 780 个场景；新建草稿默认详细版，旧草稿没有版本字段时按简略版恢复。切换简略/详细不会重置标题、备注或章节，完整提示词可预览和复制，推荐技能写明 ID 和使用理由。填写目标、受众、资料、风格与约束，再调整章节并交给 WorkAgent；交接只追加草稿，生成仍遵守会话权限与验证流程。完整范围见[工作站模板说明](docs/WORKSTATION_TEMPLATES.md)。

生图画布支持多个工程、平移缩放、图层位置、尺寸、旋转、透明度与层级调整，可导出画面或携素材的工程文件。新建、导入和编辑过的画布保存在应用本地画布库中，关闭标签后仍可从“我的画布”重新打开、重命名、复制或删除。素材由用户导入或模型生成，保存在应用本地目录；也可以把图片文件拖到工作台快速导入素材库。手动导入和拖放共用边界：单图 25 MiB、每批最多 20 张、每批合计最多 500 MiB，并且不会自动启用参考图。批量 ZIP 导出最多选择素材库上限 200 张，源图片合计不超过 500 MiB，界面按已处理素材数和字节显示进度。PNG、JPEG、WebP、GIF 经过有界完整解码校验，暂不支持 APNG。“使用参考图”默认关闭；主动开启后按勾选顺序最多使用前三张，也可手动上传 PNG、JPEG、WebP、GIF 到素材库并自动选入参考。GIF 和 WebP 均只取第一帧并转换为 PNG 后发送，转换后的参考图仍受单图 25 MiB 限制；素材库原文件保持不变。只有用户明确选择的参考图才会发给图片供应商；图像反推仍只将单独选中的素材发给视觉语言模型。图片生成和文字润色分别使用所选供应商，具体费用与协议支持由供应商决定。最多可同时运行 3 个生图请求，每项单独计时、取消并显示状态；切换工作面时继续后台执行。每个 generation 的 600 秒预算与 URL 预览下载的 90 秒预算分开计算，文本润色、反推提示词和网页/文档旧超时不变。

项目图标栏用于切换项目，分支/worktree 分组使用会话创建时记录的分支信息；旧会话没有记录时明确显示未记录。`Ctrl+Shift+P` 打开命令面板，文件结果限定当前 Code/Work 工作区。交互终端由用户主动新建，只用于已信任项目中的主 Code/Work、完全访问及宿主/worktree 会话；Agent 的命令工具仍沿用原执行与审批流程。Shell 以当前 Windows 用户身份运行，可访问该用户有权访问的位置，工作目录不构成文件系统隔离。终端关闭、会话移除和应用退出会尝试有界清理受管进程，清理失败时明确显示未确认状态并保留重试入口。

本地审阅的四个范围为 Git 工作区、分支差异、当前会话和上一轮。选择旧行或新行后可暂存评论并加入输入框；提交前会重新核对 diff 版本，已变化的评论不会静默套用到新代码。评论、模板和 AutoDrive 方案均先进入草稿，由用户发送。

## 数据与安全

会话、配置、草稿和工作记录默认保存在本机。凭据通过系统 `safeStorage` 保存；普通会话、附件和项目记忆不属于凭据加密。数据库保留历史迁移，启动时自动升级旧数据；重要升级前应备份完整数据。

聊天、上下文压缩、自动审批、记忆分析及其备用模型会按配置向对应供应商发送所需内容，并可能产生 API 用量。Gemini 签名和 DeepSeek API 实际返回的明文推理可能随会话保存；外部 MCP 和扩展也有各自的数据边界。运行日志支持用户主动脱敏导出，不自动上传。

ChatAgent 只能解析用户主动上传的位图、PDF、Word、Excel 和 PPTX 文件，文件名或消息中的路径不会变成本地读取权限。每条消息最多 10 个附件、单文件最多 25 MiB、合计最多 50 MiB；图片还会在草稿和发送边界核对 MIME、文件头签名，SVG、伪装内容和旧版二进制 `.ppt` 会被明确拒绝。它只开放联网检索和网页读取，不运行浏览器自动化、命令、MCP、Skills、Hooks 或子 Agent，也不能创建、修改或删除本地文件。WorkAgent 的可选 Office COM 验证只在系统已安装 Office 且执行策略允许时使用临时副本；不会自动安装 Office，也不会把结构检查当作公式重算或页面渲染证明。

文件、命令和扩展操作仍需按权限执行。审批是操作授权，worktree 用于工作目录分离，两者都不能代替进程隔离。持续命令工具使用管道，不支持完整 PTY；定时任务需要应用保持运行。

请阅读[安全说明](SECURITY.md)和[隐私政策](docs/PRIVACY_POLICY.md)，并按任务需要配置模型、扩展及工作区权限。

## 开发与构建

应用使用 Electron、React、TypeScript 和 SQLite，包管理器为 pnpm。

### 源码检查

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

固定任务基线可用 `node scripts/harness-eval.mjs`，默认仅运行临时工作区中的合成夹具，不调用模型。桌面专项和真实服务测试的执行条件见对应验证记录。

### Windows 打包

```powershell
# 仅检查环境、必需资源、依赖与版本
.\package-win.cmd --check

# 可选：构建解包程序，不生成安装器
.\package-win.cmd --dir

# 生成正式 Windows 安装器及 ZIP 更新材料
.\package-win.cmd
```

脚本自动寻找 Node.js/pnpm，仅为当前进程补齐 PATH。已配置好环境时也可使用 `pnpm package:win`。完整打包会先检查 Electron，缺少运行时时调用已安装 Electron 包的官方安装器，再准备图标与固定沙箱、构建应用、校验必需资源和第三方哈希，并在 afterPack 再次检查。

原生依赖准备会保留经固定 SHA-256 校验的 `node-pty 1.1.0` 官方 Windows x64 Node-API 预编译文件，并使用官方 `@electron/rebuild` 处理其余生产/可选依赖；全部成功后才启动打包器，避免重复源码重编触发 `MSB8040`。无需为当前官方预编译方案额外安装 Visual Studio Spectre 库，也不会修改上游编译防护。缺失、篡改、未知版本或优先加载的旧编译文件会明确拒绝；`--check` 仍只是资源预检，不运行完整重编或 NSIS。

迁移仓库目录后，在新目录先执行 `pnpm install --frozen-lockfile`，同步依赖安装路径。`--check` 只检查，不下载；如果报告 Electron 运行时缺失，可执行 `node scripts/provision-electron-runtime.cjs` 后重新检查，也可直接运行完整打包入口，由它自动准备。运行时按当前工作区的模块解析定位，兼容根目录 hoisted 与桌面应用本地依赖布局。

源码预检还会核对 `WorkAgentSkill/`、`ppt-master/` 和 `asd-ste100-skill-master/` 中的来源与随包副本，打包前请保留这些目录及 `apps/desktop/resources/prompts/skills/`。安装后的应用使用随包技能资源，不依赖开发仓库。正式打包会自动重建应用，无需预先单独执行 `--dir`。

内置提示词和技能资源现被打入 `app.asar`，不再由 NSIS 作为上万个独立小文件逐个解压；LSP、原生沙箱和插件 SDK 等需要真实文件路径的运行资源仍保留在外部 resources 目录。正式打包会从 ASAR 回读完整提示词树并逐文件复核 SHA-256。安装耗时仍会受杀毒扫描、磁盘、Windows 策略和机器性能影响，不能只凭布局变化承诺固定分钟数。

当前目标为未签名、当前用户安装的 x64 NSIS，输出目录为 `apps/desktop/release-artifacts/`：

```text
MingshenHarness-1.3.7-x64.exe
MingshenHarness-1.3.7-x64.zip
MingshenHarness-1.3.7-x64.zip.sha256
MingshenHarness-1.3.7-x64.zip.json
```

构建缓存位于 `%LOCALAPPDATA%\MingshenHarness\BuildCache\windows-1.3.7-*`。如果构建成功但文件复制回项目失败，控制台会打印 `Cached installer:` 或 `Update artifact retained in build cache:`，可按提示在缓存的 `output/` 中核对并取得对应 EXE、ZIP、SHA256 和 JSON；这些文件分别复制，不能只凭退出码认定项目目录中的材料已齐全。遇到 `EPERM`、`EACCES`、`EBUSY` 时，排查方法见[开发交接与打包指南](AGENT.md)。

自行分发时需核对 [release.ts](apps/desktop/src/shared/release.ts)、GitHub OAuth 和 Supabase 更新服务配置。发布材料使用本次 ZIP 实际生成的哈希与大小；`supabase/` 中的历史发布 SQL 只适用于对应旧包。配置方法见[GitHub OAuth 指南](docs/GITHUB_OAUTH_SETUP.md)和[更新服务部署指南](docs/SUPABASE_DEPLOY.md)。

### 仓库结构

```text
apps/desktop/
  src/main/             主进程、模型、Agent、工具、存储与隔离
  src/preload/          typed IPC 桥接
  src/renderer/         React 界面
  src/shared/           共享类型、配置与发布信息
  resources/            提示词、文档 worker、LSP、SDK 与第三方运行资源
  build/                正式 PNG / ICO 图标
docs/                   双语手册、协议、更新日志与验证记录
scripts/                构建、资源准备、检查、桌面验证与合成夹具
supabase/               更新服务迁移和历史发布 SQL
third_party/            固定 TencentDB 上游源码、适配及许可
```

`resources/lsp/`、`resources/tencentdb-memory/`、正式图标与合成测试夹具属于仓库资源。原生沙箱 EXE 则由准备脚本恢复。[.gitignore](.gitignore) 已排除依赖、构建产物、本地项目记忆、数据库和环境密钥。

开发前请阅读 [AGENT.md](AGENT.md)，了解代码位置、版本约束、数据保护及验证方法。[DESIGN.md](DESIGN.md) 记录界面约定。
