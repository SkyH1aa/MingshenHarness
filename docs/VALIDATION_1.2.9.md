日期：2026-11-06（Asia/Shanghai）。交付源码和已重建实验版。本轮没有生成解包应用或 NSIS、执行安装/升级、发布 GitHub 或执行云 SQL。保留所有已有修改、原子图标、schema7 永久迁移和用户数据。

## 实现范围

- `models.retry` 使用现有 `app_settings` 保存配置；默认 5，合法整数 0–20。0 禁用，每次断连分别计算连续重连次数，不包含首次请求；恢复有效输出后重置，不是整段对话/任务/流式回复的总额。主进程严格校验，旧数据缺省为 5，读取损坏值时规范化。
- 三种模型协议共用传输重试。HTTP 408/409/425/429/5xx、网络读取失败、缺少响应流和提前 EOF 可重试；已识别的鉴权、权限、参数、证书、内容政策错误不循环。未知上游逻辑错误直接显示，避免猜测重试。
- 退避约 1/2/4/8/16/30 秒，后续最多 30 秒；支持 Retry-After/Retry-After-ms，服务端延迟限制在 5 分钟内。停止立即取消等待及后续请求。没有新增持久后台恢复、工具本身重试或网络无限挂起超时机制。
- 仅重试当前模型请求；已完成工具、历史结果和执行检查点保留。重试清空失败尝试文字、思考、用量累加器和未完成工具参数，未完成文件准备活动结束为失败。工具在完整请求成功后执行，不会因模型重试重放先前工具。
- 主 Agent、委派子 Agent 与定时任务共用 ChatService 链路。审批/压缩也可在单个候选模型内进行传输重试，保留主备顺序、有效 DENY、人工决定、45 秒审核总时限及 300 秒摘要片段总时限。达到总时限可能先于次数耗尽；无效裁决/摘要仍按原备用逻辑处理，不自动放行。
- 等待活动显示次数、等待时间和脱敏错误，恢复/耗尽/取消状态持久保存。每次失败记录本地运行日志，最后完整报错保留。桌面通过 `model_attempt_reset` 清除当次未完成片段；ACP 不具备撤回 chunk 能力，发送明确分隔提示。
- 设置 → 运行与集成提供读取、保存、无效输入禁用、错误/成功状态及读取重试；搜索“重试”或“retry”可定位，中英文/日夜沿用现有视觉。

## 按每次断连独立计数复核

用户澄清：设置上限是每次断连最多重连次数，不是整段会话、任务或单次流式回复的总额。原代码跨完整模型请求已经独立，但同一流式回复内恢复部分输出后再次断连仍累计。本次修正为连续重连计数；有效内容继续推进或完整成功后恢复，后续断连从 1/N、1 秒退避重新开始。日志保留实际请求序号，界面只显示本次断连的次数。

各文字/思考/工具通道保存已见前缀以识别重复，分块方式改变不影响判定；不同但更短的输出也能建立恢复。空响应、心跳、usage 和相同未完成片段不重置。ChatService 通过 `onRecovered` 标记连接恢复，不再因任意流事件提前报成功。等待文案改为“正在自动尝试重连（n/N）”。已完成工具、审批、隔离、安全屏障、取消和辅助模型总超时保持原规则。

## 内置 Token Saver 补充（2026-11-07）

- 去掉固定4096输出钳制。总生成上限受主会话窗口15%、压缩模型配置及可用上下文共同约束；主窗口200000时最多30000，100000时最多15000。小压缩窗口先为输入和滚动摘要留空间，发送前按实际请求估算再保留256余量；较低模型输出配置仍生效。
- 合并摘要的估算预算也取主窗口15%，适用于当前/独立/备用模型。提示词声明该上限和本次正文目标；推理及正文共享输出，正文目标为推理预留空间。实际wire余量收紧时同步正文目标。
- 三协议明确输出耗尽归为不可原样传输重试的`ModelOutputLimitError`，脱敏后保留分类。每候选最多4次更短摘要/更小片段恢复；cached前缀耗尽后走无工具分段及最低支持思考档。其他incomplete、过滤、断流、认证及策略错误保留各自行为。
- 成功片段后才推进offset、更新滚动摘要，失败片段从原位置缩小后重试；未完成正文不成为后续输入。旧大摘要完整加入分片输入重建，备用重做原文，最终预算/缩小/主窗口/取消检查全部通过才保存检查点。原始消息和最近完整检查点在失败或停止时保留。
- 每个片段请求的5分钟含传输重试，每模型最多128次逻辑摘要请求；4次恢复是额外输出耗尽恢复上限，不是整次分段压缩固定5分钟。
