## 工作区布局

设置 → 外观与语言 → 界面风格可在“简约”和“光轨”之间选择。“简约”是默认风格，保留原有界面；“光轨”使用独立工作台结构。两种风格使用相同的会话、工具、设置、权限和项目数据，项目记忆仍从原设置与命令入口管理。风格选择为应用级设置；同一工作目录在两种风格下分别保存布局、面板宽度和开闭状态。

风格选择自动保存。保存成功后，点击“重载并应用”或正常退出并重新启动应用，选择才会生效。“重载并应用”会先等待界面偏好、输入框草稿及附件读写完成，保存失败会取消重载并提示重试；保存成功的待发送内容会在重载后恢复。创作工作站的未保存草稿不在该重载保护内，处理方式见下方“创作工作站”。未保存的文件、消息及计划编辑仍会阻止重载，请先保存这些编辑。主会话、子任务、准备发送、手动压缩或等待审批/回答尚未结束时，重载入口会拒绝执行；先完成或主动停止对应任务，再重载，不会替你停止任务。退出清理或安装更新交接期间，该入口也不能重载。

两种风格均支持日间与夜间，主题切换即时生效，不必为此重载。光轨日间使用白色会话面与灰绿外壳，夜间使用低饱和墨青表面和青绿色边缘。动态效果遵循系统减少动态效果设置，也可在外观设置选择“关闭”；窗口隐藏时暂停动画。任务运行、审批、错误和完成状态仍来自实际事件。

1.3.4 集中修复运行可靠性：DeepSeek thinking 工具链续接、原生 Memory 摘要预算、沙箱停止失败后的有界结算、会话目录增量恢复、宿主恢复路径竞态、工具缓存无效条目及持久命令旧清理错误。清理结果无法确认时仍保留写入屏障和资源租约；恢复操作仍需用户主动触发，不会为了“自动恢复”绕过现有权限。

1.3.3 将光轨进一步整理为企业工作台：侧栏、会话、执行时间轴、审查、终端和任务区使用一致的表面层级与标题节奏，移除装饰性渐变和泛光，以连续工作面、细线、平面选中态和真实运行状态线建立层级，保留原子图标。输入框聚焦时只出现一次短光迹，运行节点与状态栏信号仅在真实运行时缓慢呼吸，流式消息以轻微位移落定且首帧文字始终不透明，详情展开也只在说明状态时出现；关闭动效或系统减少动态效果时，内容、焦点和状态颜色仍保留。

简约的标题栏提供三个布局图标：专注对话、代码工作台、多任务协作，悬停可查看名称。专注对话以聊天为主，文件面板按需打开；代码工作台打开右侧文件区，可切换审查、文件、Git、命令和浏览器；多任务协作把计划、任务树和子 Agent 输出放在右侧。

光轨顶部是 56px 无外框标题条，左侧为独立 48px 工具轨及“工作空间”会话侧栏，上方以面包屑显示工作目录与当前会话，中央保留对话和输入区。工具轨可直达对话、文件、Agent、终端、审查及设置；面包屑旁也可切换三种布局。右上显示审查、文件或终端，并保留 Git 与浏览器入口；右下同时显示计划、Agent 任务树或计划库，计划页附真实子任务摘要。关闭右侧面板会同时收起上下两区。底部状态栏显示项目、本地运行标识和真实任务状态。各区域共享 12px 外边距与 8px 间距，面包屑和状态栏分别为无圆角的 44px/24px。

三种布局共用会话与执行状态，切换不会重发任务；当前输入草稿、聊天阅读位置和未保存的文件编辑在布局切换时保留。拖动侧栏与右面板边缘的分隔线调整宽度，也可聚焦分隔线后使用左右方向键；Home/End 调到宽度边界。简约侧栏/右面板默认 260/460px，光轨默认 228/360px；调整范围分别为 220–320px 和 360–720px。窗口不足时面板变为抽屉，点击遮罩关闭。设置 → 外观与语言可选择新项目的默认布局，以及跟随系统或关闭动态效果。

光轨在窄窗口中先收起布局文字，并将右下任务区的默认高度设为 160px；对话区自身窄于 600px 时，模型选择独占输入框首行，Agent 与工作目录排到第二行。窗口高度低于 700px 时，工具按钮和输入区同步收紧。打开文件编辑器且窗口较矮时，任务区默认也为 160px；已自定义的高度仍生效，但会受窗口可用高度限制。右侧内容通过抽屉访问，抽屉打开时会覆盖背景对话，收起后可继续输入。抽屉判断完整计入工具轨、外边距和分隔线，为聊天区保留所需空间。

模型和 Agent 统一在输入框上方选择；当前模型显示为“模型名（供应商名）”，长名称分别省略，悬停可查看完整供应商、模型名称和模型 ID。Agent 名称含简短用途，全部已启用的内置和自建配置可用。工作目录只显示短名称，悬停查看完整路径。光轨将权限选择、隔离及仅补丁详情放在输入框底栏；简约保留原位置。请求批准时，单次允许和拒绝直接显示；展开“更多授权选项”可使用本会话、同类批量批准、自动审批及项目完全访问。扩大授权前核对范围。

设置覆盖六组：通用、模型与 Agent、扩展连接、项目与安全、自动化与记录、数据与应用。搜索框按分类名称和标识筛选，点击结果进入对应页。供应商左侧选择连接，右侧在“连接 / API Keys / 模型”间切换；输入内容未保存时不会因后台刷新移走焦点。

MCP 页面可搜索连接，点击名称查看配置状态、工具数量和测试结果；添加与编辑仍使用原来的凭据保护。定时任务可按启用/暂停筛选，点击任务名展开提示词。快照与轨迹可筛选记录，轨迹按需展开，每次显示 100 步；步骤摘要单独折叠，随步骤批次显示，长记录不会一次铺满页面。审查页的长命令记录也可逐批查看。手册及更新日志附带章节目录，点击即可定位对应内容。

简约任务摘要默认折叠，没有计划和子任务时不占空间；光轨任务区位于右下，计划与子任务状态可和右上审查同时查看。拖动上下区域间的分隔线可调整任务区高度；聚焦分隔线后按上下方向键每次调整 16px，Home/End 调至当前边界，拖动时按 Esc 取消，按 Enter 或双击分隔线恢复响应式默认高度。点击任务标题栏的收起按钮可将任务区收至一行，再点击即可展开；查看子 Agent 任务树也会重新展开。高度与收起状态按工作目录保存，和简约风格的布局偏好分开。两种风格均可编辑计划并进入项目计划库。

右侧“审查”可切换 Git、分支、会话和上一轮四种 diff 范围；选中文件后可查看行号和差异，包括已删除文件。命令按钮可将历史命令记录面板停靠在右区底部；它与单独的交互式终端不同。浏览器继续使用应用内页面。

### 展开完整信息

简约运行活动默认只显示摘要，先展开当前活动条，再点击具体记录的箭头查看详情。光轨将真实工具调用及状态组织为“执行记录”时间轴，记录组默认展开，每条记录可独立展开/收起以查看命令、参数与已保存输出；消息标头显示用户或主/子 Agent 身份及真实消息时间。重连、最终报错、压缩失败及集成设置的长诊断也使用详情入口。历史工具记录按命令、参数、输出分区显示，右侧审查和命令面板同样可展开。Tab 聚焦详情标题后按 Enter 或空格可开合。

1.3.1 修复长诊断及详情展开、收起时的聊天偏移，并减少长工具历史对输入和流式输出的渲染开销。详情按需显示，完整已保存内容及复制入口继续保留。

展开后长行自动换行，长内容在详情内部滚动，可直接选择文字或点击复制图标复制完整内容；复制不受当前可见行数限制。查看聊天详情会暂停自动跟随，避免后续输出拉走阅读位置；使用聊天区向下箭头回到最新并恢复跟随。新任务运行时，历史命令详情仍可展开；小窗口中多条输入区错误同时展开后，可在输入区滚动查看错误和输入框。子 Agent 预览只保留近期内容，出现截断提示时可点击旁边的打开会话图标查看完整子会话。工具执行、HTTP 响应及预览原有容量上限仍有效，已经由源头限幅的内容不能通过展开恢复。

## 创作与项目协作

### 创作工作站

从主界面的工作站入口打开创作工作站，按分类、交付格式和多个关键词组合查找 **780 个原创工作场景**，覆盖 65 种任务结构、12 个分类。每个场景都有简略、详细两个版本，共 1,560 个可选版本，场景数量不重复计数。可编辑主题、受众、约束及章节，调整顺序，撤销或重做，并导入、导出 JSON 草稿；本地草稿按工作区保存。

简略版保留原有的章节、流程和验收框架；默认中文详细提示词至少 800 汉字，包含场景专属的资料字段、方法、交付物和风险，以及同类共享的专业流程与执行规则，并列出可引用的真实内置技能 ID 和用途。字数不表示每项均独立撰写 800 字，也不保证编辑后的长度或交付质量，成品仍需实际验收。新草稿默认详细版，没有版本字段的旧草稿按简略版恢复；切换版本不会覆盖标题、需求、备注或章节，也可撤销并随 JSON 保存。全文预览和复制使用当前草稿与交付格式，交给 WorkAgent 时使用同一份提示词。推荐技能不等于已调用或已授权，模型加载仍遵守当前启用状态和权限。

Office 场景涵盖 Word、Excel、PowerPoint，以及 Outlook、OneNote、Teams、SharePoint、Forms、Visio、Project、Access 和 Power BI 的离线内容、规格或交接工作流。实际产物限定当前可用的 DOCX、XLSX、PPTX、PDF 或 HTML，不承诺生成原生 `.mpp`、`.vsdx`、`.accdb`、`.pbix`，也不会因选模板而自动发邮件或发布云端内容。业务范围与示例见[工作站模板说明](WORKSTATION_TEMPLATES.md)。

选择模板或导入 JSON 会要求确认替换当前草稿，确认后可撤销。自动保存写入失败时，未保存版本暂存于当前运行的界面进程；切换页面后可返回该工作区恢复，并重试保存或导出。该暂存不跨重载、退出或崩溃；刷新或退出前请先在该工作区重试保存或导出 JSON，切到其他页面后也不会因此阻止退出或重载。若原有草稿损坏或无法读取，自动保存暂停且不覆盖原始值；在没有待恢复写入失败副本时，新编辑只保留在当前工作面，离开前请先导出。

选择“交给 WorkAgent 执行”会把整理后的要求追加到输入草稿，保留原有文字和附件。先检查和修改内容，再由你主动发送；选择模板本身不会创建成品或启动任务。取消选择工作目录、保存失败或草稿冲突时，先处理界面提示再重试。

### 生图工作台

从主界面的生图入口打开工作台。自行配置并选择支持 **OpenAI Images 兼容接口且返回 Base64 图片**的图片模型；它与语言模型分别选择，图片专用模型不会作为普通文本聊天模型。提示词润色使用所选语言模型，先预览并确认建议再采用；根据图片反推提示词需要支持图片输入的语言模型。供应商请求可能产生费用，具体兼容性由所选服务决定，应用不会跟随供应商返回的远程图片 URL 下载图片。

可导入本地素材，在画布上平移、缩放和编辑图层，导出 PNG，或导入、导出包含素材的可移植工程。素材保存在本地应用数据目录的固定子目录，导入后不依赖原文件路径。按顺序选择图片帧可合成为 GIF；这是已有图片帧的组装，不是文本生成 AI 视频。

画布工具栏可展开或收起素材库和设置面板；窄窗口默认收起两侧，保留完整画布及缩放、适应画布和 PNG 导出入口。展开面板后若想重新查看全部画布，可点击“适应画布”；面板切换不会改写图层位置。

### 自动规划与多角色协作

CodeAgent/WorkAgent 主会话的任务区提供 AutoDrive“自动规划下一步”。显式点击后，当前模型可结合聊天、已有计划和权限允许的有界项目证据提出 **3 至 5 个方案**；规划只读，不向模型开放命令或文件修改工具。若会话选择的 worktree 尚未建立，AutoDrive 会提示先在该会话运行任务建立 worktree，不会自动创建或回退到主目录。选中的方案只追加到输入草稿，仍须由你检查和发送。

内置 Agent 共 18 个角色，包含协同总控、实施、测试、文档和独立质量复核等。可选择协同总控并描述目标，由模型明确拆分 2 至 6 个工作包、选择可用角色并派发真实子任务；总控派发后可继续处理独立工作，随后收取结果。并发上限、审批和文件写入协调仍然适用。任务区分别显示执行、验证和 QA 状态；缺少实际证据、验证命令受阻或失败时，不能仅凭 QA 文字认定通过。测试工程师的文件编写仍需按其权限审批，质量复核角色不编辑文件。

### 搜索、终端与审阅

按 `Ctrl+Shift+P` 打开命令面板，搜索当前模式可用操作、会话和工作区文件。项目导航显示工作区与未读状态；分支和 worktree 信息只依据会话实际建立的记录，旧会话未记录时显示未知，不会用当前 checkout 推测其历史归属。聊天分支也不等于 Git 分支。

右侧终端是由用户操作的真实多标签交互式 Shell，可输入、调整窗口大小并停止；它不是向模型新增的终端工具。只能在主窗口的可信 Code/Work 项目中使用，要求完全访问、非仅补丁模式，并在宿主或实际已建立的 worktree 中执行；Chat、快捷窗口及实际子 Agent 不开放。该 Shell 使用你的 Windows 账户权限，运行命令前应自行核对；退出或关闭时若进程清理未确认，界面会保留错误与重试状态。历史命令记录面板和模型使用管道的 `exec_command` / `write_stdin` 仍是独立入口。

本地审阅在 Git、分支、会话和上一轮范围间切换；分支范围可选择比较基准。选中旧行或新行及连续行范围，填写行评论后，可将编号意见追加到当前草稿，不自动发送。交接前会重新核对文件和 diff；内容已变化时保留意见并提示刷新，刷新后重新添加受影响的评论。只有草稿保存成功后才清空已交接意见。

审阅区域高度不足时可滚动整个面板，继续访问评论编辑和“送入输入框”；较长的代码和待送入意见列表也可独立滚动。

### 草稿辅助

在设置的“上下文与压缩”中可指定独立的草稿润色文本模型；未指定时使用当前会话模型。输入区主动点击润色后，先比较原文和建议，再选择是否应用；若草稿期间发生变化，须先处理冲突。润色请求会把草稿发送给所选模型供应商。

输入区还可设置仅下一轮生效的临时指令，以及按工作目录保存、由 CodeAgent 和 WorkAgent 共用的项目语气。临时指令不改写草稿或历史正文，队列项保留其对应指令，不影响之后其他轮次；它和项目语气都不能扩大工具或权限。

## Agent 模式

主界面标题栏可直接切换 CodeAgent、WorkAgent 和 ChatAgent，不需要进入设置。模式决定当前任务可使用的专精提示、技能和工具边界，不是模型供应商；三种模式共用已配置的供应商、模型、思考等级、上下文压缩和其他基础运行配置。

| 模式 | 页面与工作目录 | 默认能力边界 |
| --- | --- | --- |
| CodeAgent | 使用原有 Code/Work 会话列表和工作目录 | 代码、文件、命令、代码索引、诊断、测试、审查和工程验证 |
| WorkAgent | 与 CodeAgent 共用会话列表和工作目录 | 同一底层执行引擎，增加办公技能与 `office_document`，专精文档、表格、演示、研究和办公成品 |
| ChatAgent | 独立对话页，不需要工作目录，按分组、置顶、归档管理 | 只允许联网检索、网页读取和用户主动上传的只读附件；无本地文件修改能力 |

CodeAgent 与 WorkAgent 可以在同一会话内切换。切换不会新建工作目录、复制聊天或重置上下文；原有消息、计划、草稿、附件、内置/已安装能力引用和项目记忆继续属于该会话。任务运行、准备发送、等待审批、等待回答或正在压缩时，模式按钮会被锁定，主进程也会拒绝绕过界面的模式修改。等待任务完成或点击停止后即可切换；切换只影响下一轮模型请求，不回溯改写历史，也不会自动重发上一条消息。没有适用于目标模式的 Agent 配置时，界面会拒绝切换并给出提示。

ChatAgent 与 CodeAgent/WorkAgent 不能在同一会话中直接互换：进入 ChatAgent 会打开独立对话页，已有对话仍保留各自分组、标题、消息、草稿和附件。光轨下使用 264px 分组会话侧栏、纯色背景与 1px 选中线，以 13px 标题和 12px 辅助信息保持紧凑层级，空态标题固定为 24px；窗口不足 900px 时侧栏改为抽屉，不挤压聊天区。ChatAgent 没有工作文件夹选择、文件任务树、审查、终端、Skills/MCP 引用、`/` 本地命令或 `@` 子 Agent 入口。消息中即使包含 Windows 路径或 `file://` 地址，也只作为文字，不能据此读取本机文件。

ChatAgent 输入区提供会话级“允许联网 / 禁止联网”控制，默认允许以兼容现有行为。允许联网时，`web_search` 和 `web_fetch` 不再逐次询问审批；网页读取仍执行 HTTP(S)、公网目标等安全检查。禁止联网时这两个工具从模型工具列表中移除，主进程也会拒绝伪造的直接工具调用。运行、发送准备或等待审批期间不能切换。基于原对话创建的同组新会话、分支和到期后重建的快捷 Chat 会继承该对话的禁网状态；没有来源会话的新 Chat 默认允许。

这个开关只控制 ChatAgent 代表用户主动执行的网页搜索和网页读取，不会断开调用所选模型供应商所需的网络连接，也不屏蔽应用更新等连接；用户主动上传附件仍按所选模型的配置发送。若需要避免内容发送到云端模型，应配置本地模型或不要提交敏感内容。

ChatAgent 的分组标题和“未分组”标题都提供加号。点击后直接在该组创建并选中一条空白对话，不再打开完整的新建对话弹窗；新对话沿用该组最近更新的未归档 Chat 的供应商、模型、推理等级和聊天设置。来源按更新时间选择，不按置顶显示顺序选择。空分组回退到最近更新的未归档 Chat；完全没有 Chat 时使用当前已配置的可用模型默认值。历史、草稿、附件和运行状态不会复制，也不会继承 CodeAgent/WorkAgent 的工作目录；创建后仍可在输入区切换模型。侧栏顶部和 Chat 空态的新建入口也直接创建未分组 Chat。若用于继承的原对话模型已被删除或失效，应用会提示先修复，不会静默换成另一模型。

### 快捷对话与全局快捷键

默认 `Ctrl+M` 打开快捷 Chat：软件保持运行时，可在当前界面或 Windows 其他应用中唤起约 480×680 的 ChatAgent 快捷对话窗口，不需要先切换到聊天页；窗口已经显示时再次按下同一快捷键会收起。首次唤起会创建一条独立的 Chat 对话；在 **10 分钟**有效期内再次唤起，会显示并复用当前快捷对话，同时把有效期重新续到 10 分钟。超过有效期后再次唤起会创建新的快捷对话，旧对话仍保留在 ChatAgent 的分组历史中，不会被删除。有效期只由唤起动作续期，聊天或等待回复不会改写租约。

快捷窗口顶部可新建对话、打开主界面并定位当前快捷对话、切换置顶或隐藏窗口。置顶状态会持久保存，启用后主进程把该原生窗口设为始终置顶；Windows 安全桌面、系统级弹窗和其他更高层窗口仍可能显示在其上。`Esc` 也可在输入法未组合文字、没有打开菜单或对话框时收起小窗口。隐藏窗口不会丢弃当前草稿，再次唤起可继续；顶部“新建对话”会立即创建下一条 Chat 对话。应用正常重启后，尚未过期的租约可以继续恢复；若租约已过期，下一次唤起创建新会话。没有可用文本模型时，窗口会提供“打开模型设置”入口，并通过主界面完成配置。

快捷对话仍受 ChatAgent 权限约束：可以使用 `web_search`、`web_fetch`，可解析你主动上传的只读附件，并共用供应商、模型、上下文压缩与草稿能力；不能读取本地路径、修改文件、执行命令、使用 MCP/Skills/Hooks/子 Agent，也不会成为 CodeAgent 或 WorkAgent。小窗口只接受当前 Chat 会话的状态与操作，旧窗口事件不能去操作另一条对话。

默认 `Ctrl+Alt+L` 切换主界面/托盘：主界面已可见并处于焦点时收回，否则显示、还原并聚焦主界面。用户可在设置中录制并自定义这两项全局快捷键；支持组合 `Ctrl`、`Shift`、`Alt` 形成三键或四键快捷键，同时保留默认 `Ctrl+M` / `Ctrl+Alt+L` 二键组合。每项组合必须至少包含一个 `Ctrl`/`Shift`/`Alt` 修饰键和一个主键，两项不可冲突。保存时会实际注册；若组合被其他程序占用或注册失败，软件保留原有效绑定并显示错误。用户也可恢复默认。两个快捷键都是系统级注册，软件必须仍在运行；快捷键只操作窗口，不发送消息、不批准操作，也不改变权限。

首次协议或内置手册步骤尚未完成时，`Ctrl+M` 会先打开主界面完成引导，不会在未完成的同意流程上绕过限制创建快捷会话。

### CodeAgent 专精

CodeAgent 继续使用完整代码工作台，并强化以下闭环：

- 通过内置代码工程、前端、后端/数据、排障和验证技能按需加载专业知识；每个入口只在需要时继续读取对应的参考文档。技能目录先提供元数据，实际需要时再用 `use_skill` 读取正文和资源，避免把所有内容一次塞入上下文。
- 会话会在输入框加号的“引用”面板提供内置 Skills/Plugins 和已安装且启用的扩展。手动选择的内置能力与扩展优先，其他匹配能力仍由 Agent 自动发现，两者不是二选一。任务出现数据库、设计、文档、审查等领域线索时，CodeAgent 会按能力搜索候选，再以精确 ID 加载相关 Skill。已停用项不会出现；发现、加载或 MCP 工具声明都不会自行执行脚本或提升权限。GitHub、浏览器等内置 Plugin 的手选只表示工具偏好，不会连接账号、登录或启动外部服务。
- 使用本地代码索引、LSP/诊断、文件读取和 diff 先确认调用路径与现有约束，再实施最小范围修改；跨模块工作要同时核对类型、IPC、存储、界面和失败路径。
- 同一失败工具连续以相同参数重试会被识别并要求检查参数、状态、权限或环境，更换假设、输入或策略，而不是机械重放。拒绝审批、依赖缺失、超时和产品断言失败属于不同错误类别。
- 单个工具结果最多保留 4,000,000 个 UTF-16 字符，以头尾片段呈现并显式标注中间缺口；单会话最多保留 40 条、累计 16,000,000 个 UTF-16 字符。模型可调用 `read_tool_output`，以 `call_id` 和字符偏移分页读取该有界保留区，但不能恢复已遗漏、淘汰或未捕获的内容。
- 仅主会话、完全访问、宿主执行模式下的受管文件工具会在写入前创建逐文件局部检查点。单文件最多 25 MiB；单检查点及单轮累计受 `128 MiB / 128 个检查点`预算约束。命令和外部 MCP 的副作用不提供逐文件快照保证；运行结束时保留的项目快照与轨迹也不等于这些副作用可完整回滚。模型轮次中断后应根据真实现场恢复，而不是假装某个副作用已经完成。
- 交付前执行与风险匹配的测试、类型检查、Lint、构建或真实界面检查。已有明确项目检查最多支持三轮“失败、定位、修复、重跑”，窗口提示或命令退出码不能替代最终验收。

### WorkAgent 专精

WorkAgent 与 CodeAgent 共用权限、隔离、审批、写入锁、取消和原子写入，不会自动获得更高权限。“办公专精”来自任务方法、内置技能和受控 Office 工具，而不是绕过执行层：

光轨中的 WorkAgent 空会话提供 Word、Excel 和 PPT 起始任务。选择后，建议文字会追加到当前草稿，用户仍可修改并自行发送；不会自动启动任务或创建文件。

- 先确定受众、决策、输入、交付物、结构和视觉约束，再为长文档列章节提纲、为演示稿写 storyboard、为工作簿建立输入/计算/输出结构。研究事实必须来自可核查资料，未读取的网页或文件不能假装已理解。
- 先写清读者、要支持的决定、语气、事实与来源，再删去空泛口号、重复结论和没有依据的形容词。标题应表达论点，表格、图表和提示框只在帮助比较、决策或风险提示时使用。
- Word、PDF 与 PPTX 可套用 `executive`、`consulting`、`editorial`、`minimal` 四种受控设计预设，并选择 `airy`、`balanced`、`compact` 三种信息密度和单一强调色；DOCX/PDF 可增加封面。版式使用统一的标题层级、安全区、字体和间距，不在每页任意换色或堆叠卡片。
- PPTX 可用封面、章节、正文、核心判断、卡片、时间线、数据页和收束页等 `slide.kind` 组织叙事；`metric_grid` 适合真实可比较的 2–6 个指标，`callout` 用于决策、风险或下一步，而不是填满每页。
- 使用结构化 `office_document` 创建或编辑 XLSX，支持带类型单元格、范围、公式、格式、表格、筛选、冻结窗格、列宽、合并和结构检查。工作表可设置标题/表头/正文范围、网格线、打印区域、重复标题行、方向和按页适配；旧工作簿可用 `format_sheet` 只调整展示表面。公式写入、缓存值和真实 Excel 重算分别记录，不能把“文件里有公式”当作“公式已算对”。
- 对 PPTX 旧稿只编辑已支持的形状/占位符文字、表格单元格和备注；先读取结构及 SHA-256，再按源版本提交操作。未修改包部件保留源字节，宏、签名、OLE、SmartArt、动画和复杂母版兼容性不承诺无损。
- 继续支持 DOCX 旧稿结构读取、无占位符文字/正文区段修改、段落排版、模板填充、原生公式、图表、页眉页脚和脚注；输出默认另存，并在源 SHA 变化、定位歧义、保护结构或容量越界时拒绝。
- 内置领域目录现有 21 个基础能力入口：5 项 Code、12 项 Work、3 项 Creator 和 1 项共享成品质量入口；其中 19 项为原创工作流，Work-only `builtin:work-ppt-master` 与 `builtin:work-asd-ste100` 分别适配 PPT Master 6.9.0 与 ASD-STE100 0.4.0 开源技能资源。CodeAgent 可见 9 个基础入口，WorkAgent 可见 16 个基础入口，并从 `WorkAgentSkill/` 展示 **98 个当前活动来源**。同源、同路径的技能按语义版本保留最新版，9 组中的 26 个旧版本不再重复出现在自动发现和手动引用中；不同用途或独立来源继续保留，不按同名或正文 SHA 合并。旧选择显示对应最新版，取消选择清理历史别名，旧配置的拒绝或审批规则继续有效。124 个物理来源、104 个唯一正文 SHA、93 个唯一名称和历史文件仍保留用于溯源；其中 82 个设计资源正文原样保留，另 22 个唯一正文为原创适配。PDF 当前保留 production、viewer、reading 和 loose 四种来源，其 10 个物理来源及历史 Viewer 0.2.1 正文不删除。正文按需加载，不全部注入默认提示词。PPT Master 的脚本、Python 依赖和付费服务不会自动安装或执行，WAV 等二进制不能通过 `use_skill` 直接加载；ASD-STE100 不含官方词表、不表示认证，私有 JWT/认证、viewer、canvas、脚本和宿主接口也不因技能存在而可运行。
- WorkAgent 与 CodeAgent 一样同时支持能力自动发现、内置能力手选和其他已安装且启用扩展；手动引用项优先，其他匹配项仍可通过能力搜索发现并按需加载。`builtin:work-ppt-master`、`builtin:work-asd-ste100` 等 Work-only 项从 Work 切到 Code 后隐藏，切回 Work 会恢复选择；fork 和子会话复制选择。ChatAgent 不提供这套入口，停用的扩展也不会被发现或调用。
- 内置能力选择按会话保存，最多 32 项，不写入扩展安装列表。运行、准备发送、等待审批/回答或任一子任务忙碌时不能修改。当前 Agent Profile 允许 `use_skill` 且无需交互审批（包括默认读取策略）时，选中的 Skill 正文可在首轮系统提示中受控预载，总额最多 64,000 字符；权限为 ask、deny，或能力不可用、超出预算时只保留精确 ID，后续仍由 `use_skill` 走真实审批。插件 ID 不交给 `use_skill`，也不因选中而获得连接、登录、启动服务或调用工具权限。

`office_document verify` 先做包结构与内容检查。若本机已安装且可用的 Microsoft Office 被当前策略允许，WorkAgent 还可请求 Excel COM 重算或 Word/Excel/PowerPoint 导出 PDF 做渲染检查。该实机验证只可能发生在 WorkAgent、完全访问、宿主执行且不是子 Agent 的会话中，并要求 Office 已安装、进程空闲且未被隔离/组织策略阻止。应用不会自动安装 Office，也不会复用或控制用户正在编辑的文档。

验证不可用、失败或被拒绝时，结构检查结果仍保留，并明确显示公式重算、PDF 渲染或逐页视觉检查未验证。package 生成成功、公式写入成功、Excel 实际重算和 PowerPoint/Word 页面排版是不同证据；报告不得合并这些状态。Office COM 也不能证明所有 Office 版本、字体、DPI、打印机驱动或第三方扩展都一致。

### ChatAgent 边界

ChatAgent 仅提供对话、用户主动上传附件的只读解析，以及可由会话开关控制的 `web_search`、`web_fetch` 两个联网工具。它不加载自定义 Agent 配置，也不开放本地路径读取、文件创建/修改/删除、命令、终端、浏览器点击或登录、GitHub 操作、MCP、Skills、Hooks、自定义工具和子 Agent。即使模型尝试调用被禁工具，主进程也会在执行前拒绝并记录为错误，不会因为 `workspacePath=null` 就从其他路径补读文件。

附件只使用用户主动提供的字节内容：图片按模型视觉能力处理，PDF、Word、Excel 和 PowerPoint 使用应用的本地只读解析；需要原模态时再按所选供应商能力发送。附件中可以包含敏感内容，发送前请确认当前供应商的数据政策。ChatAgent 可以给出文字、代码或公式建议，但不能声称已在本地保存文件或执行外部操作。

## 快速开始

### 打开软件

从桌面或开始菜单打开 Mingshen Harness。首次启动会显示服务协议、隐私政策和免责协议，点击标签阅读正文，分别主动勾选三项同意，并至少停留五秒后点击“同意并继续”。不同意可退出。确认后自动打开这份内置手册，不需要外部网页。以后可随时点击标题栏的书本图标，或进入设置 → 关于 → 使用手册。

点击手册的“开始使用”或关闭按钮后，首次引导完成；后续正常启动不再自动弹出协议或手册。若同意后尚未完成手册步骤就关闭/重载，下次会恢复手册，不重复要求勾选。是否首次使用依据当前 Windows 用户数据目录中的完整同意记录判断；保留旧数据的重装会沿用记录，安装到新目录不等于新用户。不要删除已有数据来测试首次流程。

书本入口中可切换“使用手册”和“更新日志”。[更新日志](CHANGELOG.md) 记录 1.2.1 至 1.3.4 的变化，两份文档均内置，断网也能查看。

## 错误自动重试

1.2.9 起，模型请求遇到连接中断、流提前结束、HTTP 408/409/425/429 或 5xx 临时错误时，会自动等待后重试当前请求。默认**每次断连最多重连 5 次**，首次请求不计入。设置 → 运行与集成 → 模型请求自动重试可保存 **0–20** 的整数；0 关闭，20 表示每次断连最多连续重连 20 次。设置搜索“重试”也能定位此页。

次数按每次断连分别计算，**不是整段对话、整个任务或同一条流式回复的累计上限**。例如本次断连使用了 3/5 次并恢复，之后再次断连仍从 1/5 开始。新文字、思考或工具参数继续向前推进时重置计数及退避；仅建立连接、空响应、心跳、用量统计或重复返回相同未完成片段不会重置，连续失败仍会在本次上限停止。正常完成的模型请求之后，下一请求也有独立额度。

普通对话、子 Agent 和定时任务共用这条执行链路。等待时显示“正在自动尝试重连（当前次数/上限）”，展开可查看错误及等待时间；恢复后继续原任务。重试采用约 1、2、4、8、16、30 秒的退避，后续最多 30 秒，服务端要求的等待最长按 5 分钟处理。点击停止可取消请求和等待，无需等待计时结束。此功能要求应用仍在运行，不会在退出后自动恢复后台任务。

只重新发送失败的模型请求，保留已完成工具及其结果；失败尝试的部分文字和未完成工具参数会被丢弃，不执行未完成的工具调用。审批权限、隔离、写入锁和安全恢复屏障仍生效。工具自身失败、未知副作用或永久配置错误不会因本功能而自动反复执行。401/403、无效地址/参数、证书错误和内容策略限制需先修正，重试耗尽后保留完整最终报错及脱敏日志。

审批与压缩模型也支持传输重试，继续遵守已有主备模型顺序；有效拒绝不会为了获取通过而重审，无效裁决或摘要仍按原备用逻辑处理。每个审批模型保留 45 秒总时限，每个摘要片段保留 300 秒总时限，包含重试及等待，因此可能在次数耗尽前转备用或人工处理。重试会重复发送当前请求给同一供应商，可能增加 API 用量。ACP 外部编辑器无法撤回已发送的片段，会显示明确的丢弃/重试分隔提示。

### 受控工具执行链

当下一步工具动作已经完全确定时，Mingshen 可以让模型在一次回复中声明 2–8 个静态动作，并按依赖和文字条件顺序执行。这只省掉已经确定动作的重复模型往返，不是跨任务缓存模型判断。每个动作仍单独校验参数、请求审批、进入隔离环境、取得写入锁、记录活动和检查点；诊断、计划变化、拒绝、取消或未知副作用会停止后续动作并交回模型。不会重放已执行的写入、命令或 MCP 副作用，也不会缓存测试、构建或复杂命令。

### 项目记忆

创建新项目的首个会话时，先选择工作目录，再在“项目记忆”中选择“原生 Memory”或“TencentDB Agent Memory（本地核心）”。同目录的新会话、分支、实际子 Agent 及关联 worktree 继承项目选择。设置 → 项目指令与信任可手动选择工作区，查看并修改其记忆后端，无需先创建会话；修改前需结束该项目及子任务和正在运行的记忆维护。一个项目同一时刻只启用一种方案；显式切换保留两套目录，不删除、改名、迁移或合并数据。选中子任务或关联 worktree 时，设置会解析到顶层主会话的工作区，并显示实际记忆归属工作区。旧项目的双目录或配置冲突仍会阻止继续，需在此明确选定后端后恢复；配置读取、所选目录或核心初始化失败会显示错误，不会悄悄切换。

选择 TencentDB 时，可为该工作区设置“记忆分析模型”和可选“备用记忆分析模型”。主模型留空使用当前主会话模型，也可仅设置备用；主备不能是同一个显式模型。必要的对话文本和候选记忆会发送给所选供应商并产生 API 用量，备用可能使用不同供应商。主模型调用失败或结构化结果无效时，备用从头重做整次提取与冲突判断；有效的空结果表示无新增，不触发备用，也不会回退为原文摘录。

原生 Memory 在选定工作目录维护可见的 `.harness-memory/`，包括 `preferences.md`（精简偏好）、`memory.md`（任务结论）、`index.md`（关键词索引）和 `archive/`（旧日记摘要）。短期上下文只留在当前会话；新一轮优先加载偏好，历史日记按需检索。成功任务会生成约 50–100 字的事实摘要，摘要不应复制原始对话、临时上下文或秘密，可能产生额外模型用量。

两种方案都支持 `/remember 内容`、`/forget ID或短语`、`/memory search 关键词` 和 `/memory stats`。原生 Memory 可直接捕获明确的“以后/始终”偏好，引用块和代码示例不会直接当成用户偏好；主聊天模型通过记忆工具保存推断偏好时必须先询问用户确认。TencentDB 不使用上述规则捕获，改由独立语义分析提取自动记录，需按下述方式核查。设置 → 项目指令与信任 → 项目记忆可查看、编辑、搜索、删除、刷新和关闭自动维护。关闭后下一次模型请求不再新增自动记忆注入，也不自动提取任务记忆；仍可主动使用命令管理文件。此前已发送的记忆快照、工具结果和摘要仍属于原聊天历史；关闭、编辑、删除源记忆或 `/forget` 不会追溯擦除这些历史。需要不再携带旧内容时开始新会话，并按需删除原会话。设置保留各标签草稿，外部修改会触发版本冲突而非静默覆盖。

只有主 Agent 能通过记忆工具写入；实际 Subagent 的普通编辑工具拒绝修改记忆目录。子任务命令在原生 MXC 和 Docker 中均以整个工作区只读的方式运行，记忆目录尚未创建时也生效；修改普通项目文件可使用审批后的受管文件工具，记忆目录除外。主会话命令规则不变，宿主自定义工具、Hook、LSP 和 stdio MCP 不向子任务开放。远程只读 MCP 仍属于用户信任的第三方服务，其只读声明不是独立安全认证。只读 Plan 不自动创建记忆或生成日记。记忆属于可纠正的项目数据，优先级低于当前用户、安全规则和项目指令。

原生 Memory 的偏好上限 6 KiB；活跃日记超过 50 KiB 时将较旧的任务摘要移到归档，保留完整内容，不截断结论。检索一次最多返回 5 条、合计 3000 字符；归档最多 40 份，检索源合计最多 2 MiB，超过边界时提示人工清理。去重按规范化内容精确匹配，不会猜测相似但可能不同的决策。旧条目已是任务摘要，归档不会再次调用模型改写原文。索引可根据文件重建，预览上限 256 KiB；达到预览上限不删除记忆，检索仍覆盖保留的全部来源。支持直接用编辑器纠正记忆。

TencentDB 本地核心内置上游 v2.0.3 的 L1 记忆流程：提取调度、质量筛选、候选召回与冲突判断、记录写入和 SQLite 全文检索。分析模型运行固定上游的通用对话提取与冲突提示，将有价值的事实提炼为 `persona`、`episodic` 或 `instruction`，再选择 `store/skip/update/merge`；不再把完整回答或 `Assistant result excerpt` 直接作为自动记忆。不加载腾讯工作/团队提示。宿主原子保存的 `.harness-tencent-memory/records.jsonl` 是权威快照，最多 2000 条 / 2 MiB；上游产品存储回退已禁用，全文索引临时在内存重建，不额外保存 SQLite 数据库。偏好上限 6 KiB，检索最多 5 条 / 3000 字符、每条最多 800 字符。该预设不自动归档旧记录，达到上限时在设置中删除或精简；删除会移除当前快照中的条目。

提取与冲突判断的系统提示词和用户模板均逐字复用固定提交的官方 `chat` 原文，不追加宿主规则或当前主 Agent 的指令。输入范围、容量、来源校验和已确认偏好保护仍由宿主执行，存储与备用模型属于本项目适配。

TencentDB 设置编辑器显示现有记录的 `{id,type,content}` JSON 数组：可改 `content`、移除条目，保留现有 `id` 和 `type`；新增请用 `/remember` 或批准的记忆工具。不要把原生 Markdown 粘入该编辑器。自动分析记录可以更新或合并，已确认的 `persona` / `instruction` 偏好不进入自动冲突处理的可变记录，不能被该流程改写或删除。只在真实变更保存后报告保存；重复或有效空结果显示无新增及存量。错误、无效结果、取消、配置变化或版本冲突不覆盖已保存快照，也不令原任务失败。升级或切换后端不批量清理、改写旧摘录；后续语义维护仍可更新或合并未受保护的旧记录，也可在设置中核查、修正或删除。

无需腾讯账号、TencentDB 服务或 OpenClaw。此预设不加载腾讯业务流程、云端/团队服务、遥测、L0 原始对话归档、完整 L0–L3 流水线或向量/embedding API。它使用上游 L1 语义流程与本地存储，并非完整腾讯产品；模型请求发送给你配置的供应商。

自动维护只在成功的主任务结束后尝试；原生 Memory 摘要继续使用当前模型并保留30秒总时限，TencentDB 使用工作区配置的分析主备模型。模型生成的记忆可能不准确，也无法保证识别全部敏感内容或固定节省 Token；请核查记忆，勿存放密钥和原始私密对话。正常聊天仍调用配置的模型，偏好和检索片段可作为上下文发送。本地存储不表示模型分析离线；必要的对话和候选记忆会发送给分析供应商，备用可能扩大接收范围。项目记忆不接入 Mingshen 或腾讯记忆服务；目录是工作区普通文本，用户的 Git、同步及备份工具可能包含它，发布仓库前应检查。

### 任务工作台

1.2.7 起，活动计划全部完成或取消后会保留本轮结果供查看，在下一条普通消息开始时自动清空。新请求仍涉及未完成工作时，当前模型先判断是否沿用旧计划：相关任务保留进度，无关或已被替代的计划清理后按需新建。判断期间显示静态“待确认沿用”，不会把旧步骤当成正在执行；模型用 `review_plan` 提交判断，清理不需要你额外审批。判断失败会显示错误并保留旧记录，可重试或在编辑计划中清空步骤。

“从恢复点继续”是明确续跑入口，保留未完成计划及完成状态；普通“继续”文字由模型结合当前请求判断。中断不自动等于废弃。用户另存的项目计划库、聊天中的历史工具记录及不确定副作用安全屏障不参与活动计划清理。

左栏以主会话计算每个文件夹最近三条。主会话右侧、三个点左边的箭头展开或收起其子 Agent；子任务使用不同 worktree 时仍归属于父会话。右键任意会话可打开同一个操作菜单，搜索子任务会显示父会话上下文。会话标题由本地数据库增量索引，启动按页加载，使用“加载更多”继续读取；较长列表使用虚拟滚动，只绘制可见行。搜索覆盖全部未归档记录，不需要先展开所有文件夹。

“任务计划”显示 Agent 使用 `update_todos` 建立的待办、进行中及完成状态：简约位于聊天顶部或协作右区，光轨位于右下“计划”页。可编辑步骤与依赖、勾选完成或添加新步骤，简约的紧凑任务带另可展开/收起。保存时使用计划版本检查，避免覆盖其他窗口或 Agent 刚更新的计划。依赖不能成环；依赖完成后才能开始下一步。每个步骤的暂停按钮可设置断点，Agent 将其标记为进行中后、执行下一工具前暂停。暂停计划会停止当前执行，继续计划后可使用“从恢复点继续”；已保存计划在重启和完整分支聊天后保留。

计划编辑尚未保存时，切换到其他会话、进入 ChatAgent、新建会话，以及归档当前会话或其祖先会话都会被阻止，任务区会展开并回到“计划”页，提示先保存或取消；同一会话内的 CodeAgent / WorkAgent 切换仍可进行。保护不会自动保存或放弃编辑，未保存的计划编辑不承诺在重启后恢复。

只有会话确实运行、计划未暂停的进行中步骤才显示转圈。停止或中断后显示静态“已中断”，暂停计划显示“已暂停”，等待审批或回答显示“等待用户处理”，失败显示“任务失败”；本轮结束但步骤尚未完成时显示“待继续”。这些是执行状态提示，不会把未完成步骤改成已完成，也不会清空待办进度。

“项目计划库”可将当前计划命名保存，再在同一工作目录的其他会话中“绑定到此会话”。默认保留已完成步骤，原进行中步骤回到待开始；勾选“绑定时重置完成状态”可从头执行。保存的计划独立于源会话，删除源聊天不会删除它；可在计划库单独删除。计划有未开始步骤时，Agent 必须调用 `begin_plan_step` 选择符合依赖的步骤，应用才允许继续产生副作用，断点会在该步骤开始前暂停。

“Agent 任务树”显示父任务与实际创建的子任务，包括运行、排队、等待用户、已中断和失败状态，以及运行期间的工具活动。子任务左侧箭头展开/收起内嵌输出窗口，保持主会话不切换；点击 Agent 名称才进入完整子会话。展开区展示真实近期文本、思考摘要和可折叠工具输出，流式内容随运行更新，结束或重载后仍可读取本地记录，也可手动刷新。输出较长时只展示有界的近期内容并提示，完整内容在原子会话查看；收起后不继续加载预览。并发上限仍在设置中配置，子 Agent 不可递归创建子 Agent。

展开箭头会在任务树内部露出该子任务，不移动主聊天记录；输出区独立滚动，默认查看最新输出，上滑后暂停预览跟随，滚回底部恢复。紧凑窗口中工作台限高，不覆盖输入区；思考摘要和工具输出可单独展开检查。

新增 Code Review / Review Worker（只读代码审查）、Operations / Operations Worker（运维与只读调查）、Inspiration（创作）、Brainstorm（只读头脑风暴）。Operations 的命令和修改即使在完全访问模式也要求人工确认。创建会话及顶部菜单包含所有已启用内置和用户自建 Agent；说明区可滚动，禁用项不出现，隐藏只影响 `@` 提及。

代码工作可使用 `code_index` 查询 JavaScript/TypeScript、Python、Go、Rust、Java、C/C++ 和 C# 的定义、引用、调用者、被调用者与导入关系。解析器随应用提供，按文件指纹增量更新；结果包含路径、行列和上下文片段。它提供语法候选证据，动态派发、重载及跨语言绑定仍需 LSP 或源码确认。默认最多扫描 10,000 个代码文件、深度 32；可通过 `max_files` / `max_depth` 调整至 20,000 / 64。目录项、单文件及符号数仍有保护上限，达到上限会报告；索引读操作受当前审批及隔离约束。

相同文件内容在同次运行、同一摘要边界内复用已确认内容，缓存命中返回简短引用；仍校验真实内容并执行审批，不跳过隔离读取。并发相同读取合并执行，写入后失效。需要再次返回全文时可使用 `read_file` 的 `refresh: true`。严格匹配的运行时版本查询可短暂复用；简单字面 `Get-Content -LiteralPath`、`Get-ChildItem -LiteralPath`、`Test-Path -LiteralPath` 通过结构化读取校验依赖后复用结果。测试、构建、安装、复杂 Shell 表达式和有副作用命令不缓存。

`read_file` 可用 `start_line` 和 `limit` 指定行范围，也支持 `end_line`；长单行可按首行内的 `char_offset` 接续。输出标注实际行范围，未读完时返回下一次读取的 JSON 参数；偏移按 UTF-16 字符计数。缓存按读取范围区分，仍核对整个源文件的哈希，写入前的外部修改检查不会因分页而跳过。

模型配置启用“并行工具调用”时，同一回复中相邻、独立的内置读取最多并发3个，包括文件、文档、图片、目录、搜索、代码索引与网页读取。每个调用仍单独使用当前权限、审批、隔离和预算；命令、写入、执行链、浏览器、MCP 及自定义工具不参加这个批次。

长命令可用 `exec_command` 启动，在尚未结束时返回 `command_session` 标识，随后以 `write_stdin` 读取新增输出、发送输入、关闭 stdin 或停止。纯轮询不重复请求命令执行批准；输入仍按当前策略检查。会话绑定原聊天和本轮运行，不跨聊天或重启复用；停止或任务结束会停止相应受管进程并等待清理。清理未确认时保留写入屏障和 lease；当前清理失败不会自动重试，恢复可能需要重启应用，解除屏障前仍须确认进程或容器已停止并核实副作用。它使用管道而非 PTY，不能保证需要 TTY 的全屏终端或交互程序可用；宿主主动脱离进程树的后台程序也不保证自动回收。右侧命令面板仍是执行记录视图。

完成代码工作后进入显式验证阶段，执行项目声明的 `test`、`lint`、`typecheck`，真实失败最多反馈三轮供 Agent 修正。所有检查均走原命令工具和当前权限/沙箱，缺配置或拒绝执行不会显示成检查通过；普通文档不触发类型诊断。每条检查及输出保存在运行记录中。

JavaScript/TypeScript 项目优先读取 `package.json` 的检查脚本及 `packageManager`。没有该清单时，Rust 项目使用 `cargo test/clippy/check`，Go 使用 `go test/vet`，Python 的 `pyproject.toml` 项目尝试 `pytest` 与 `ruff`；运行环境缺依赖时会报告真实失败，不静默安装。其他项目或需要定制命令时，可在工作目录根部放置 `mingshen.verify.json`，声明 1–6 条非空检查命令，例如：

```json
{
  "commands": ["npm run test -- --run", "npm run lint", "npm run typecheck"]
}
```

声明的命令可执行项目代码，应先审查来源。未能读取或解析配置会明确反馈，不能视为验证成功；长驻开发/监听命令不适合作为检查，单条验证命令最多等待 120 秒。验证失败最多自动反馈三轮，剩余环境或代码问题仍需人工核查。

多个会话或 Agent 修改同一个文件时，应用询问保留原写入者还是停止原任务并转交当前任务。转交后待执行修改不会执行，应用强制要求先重读再重算；目录写入权转交则要求先 `list_files` 检查目录。子任务不能停止父任务或祖先任务夺权。命令、可写 MCP、自定义工具与插件 Hook 保守占用工作区写入权。内置文件写入若发现内容自上次读取后发生变化，会询问重读或停止，保留外部修改。此机制不是阻止任意外部程序写文件的操作系统锁，外部工具也可能操作工作区外或远程资源。

冲突需要你决定时，若未在前台查看对应会话，Windows 会提醒“需要处理修改冲突”。点击通知或“处理冲突”回到该会话，再在软件内选择写入者或重读；通知本身不会停止其他 Agent、转交写入权或覆盖文件。

“本会话同类批量批准”按当前工作区内读/写类别或简单命令前缀放行后续同类请求，同时处理同会话已排队的同类审批；不改变权限模式、不传播到其他会话，重启后失效。显式人工策略、危险操作、Shell Hook 不参与该授权。批准前可悬停查看具体范围。

从恢复点继续不会新建聊天或重置计划。主 Agent 会收到当前持久化的计划版本、步骤 ID、完成/取消/进行中状态、依赖与断点，包含你在停止后手动保存的修改；已完成的步骤继续保留，只恢复计划的暂停开关。后续每次模型请求重新读取最新计划，旧工具记录不能覆盖你的新修改。恢复不自动完成或重放子 Agent，也不撤销不确定操作的核实要求。

中断后“从恢复点继续”保留完整历史与计划，恢复到最近保存的工具边界。引擎按已确认工具及参数指纹阻止直接重复执行；未确认执行中的操作会阻止后续副作用，重启或重试不能清除这个屏障。Agent 须先使用读取工具核查状态，再以真实检查调用 ID 和摘要调用 `resolve_interrupted`，由你确认后继续。MCP 取消/超时可能只停止传输，远端仍可能执行；同工作区会暂停新的写入，确认前先在远端核实已停止。任意外部操作不保证恰好执行一次，也不能仅凭不同参数的相似命令判断已执行与否。

分别勾选三项并确认，表示您已完整阅读、理解并接受三份协议，承诺遵守其中的约定，并理解使用模型、执行命令和修改文件等操作的后果、责任及影响。在法律允许的范围内，您自主使用、选择和授权产生的责任由您承担，不转由开发者或新哲文院算法社承担；依法不得免除的责任仍依适用法律处理。协议修订后，软件会要求重新阅读并确认。

右上角可切换中文/English、最小化、最大化和关闭。拖动标题栏空白处移动窗口。窗口使用自定义标题栏和原子图标。

### 连接模型

填写供应商名称、Base URL、协议和 API Key。默认名称 `Chatgpt Pro` 只是可编辑示例，不附带 ChatGPT 订阅或额度。

```text
名称：我的模型服务

协议：OpenAI Responses
鉴权：Authorization: Bearer
API Key：在供应商控制台获得的密钥
```

保存后拉取模型列表，选择模型，填写上下文、输出上限、模态和思考等级。测试连接会真实发送最小消息，可能产生供应商费用。

新建会话并选择模型、工作目录。首次选择目录会询问信任，未知仓库先保持未信任。优先使用请求批准。普通文件任务不要求 Git，但 Git 审查、撤销与 worktree 需要 Git 仓库。

先尝试只读任务：

```text
阅读这个项目，解释启动方式与关键模块。

```


运行中可看到读取、命令、编辑和子 Agent。审批时核查完整参数；完成后审查 diff 和实际检查结果，不要只凭模型文字判断完成。

## 配置供应商与模型

| 协议 | 在 Base URL 后追加 | 适用服务 |
| --- | --- | --- |
| Anthropic Messages | `/messages` | Anthropic 兼容服务 |
| OpenAI Responses | `/responses` | Responses 兼容服务 |
| OpenAI Chat Completions | `/chat/completions` | Chat Completions 兼容服务 |
| Google Gemini | `/models/{Model ID}:streamGenerateContent?alt=sse` | Google 原生 GenerateContent |

通用 Base URL 填到 `/v1`，不要重复添加端点。Gemini 原生使用 `https://generativelanguage.googleapis.com/v1beta`，鉴权选 `x-goog-api-key`；Gemini 官方 Chat Completions 使用 `https://generativelanguage.googleapis.com/v1beta/openai`。DeepSeek 官方还支持对应协议的根地址、`/beta` 或 `/anthropic/v1`，具体匹配见[供应商提示缓存](#供应商提示缓存)。一个供应商只使用一种协议；同一地址支持多协议时建立独立记录。鉴权支持 Bearer、`x-api-key`、`api-key`、`x-goog-api-key`、自定义头。公网优先 HTTPS，本地 HTTP 只连接可信服务。

Gemini 原生模型 ID 填纯名称（如 `gemini-2.5-flash`）或 `models/` 前缀；拉取列表会读取分页并只列出支持 `generateContent` 的模型。新建原生模型默认思考档为 `auto`，留空或 `auto` 都沿用 API 默认。Gemini 2.5 使用 `auto`，Flash 可增加 `none` 以关闭思考，Pro 不支持关闭；Gemini 3 及以上按具体模型支持填写 `minimal,low,medium,high`，不会映射为猜测的 token budget。工具能力和上下文上限仍需按模型配置。支持文字输出，以及模型已启用的图片、音频和原生 PDF 输入；其他文件沿用提取文字，输出媒体暂不支持。

原生接口按原顺序保存返回的 Part 和 `thoughtSignature`，工具结果按对应调用续接；只有服务端返回调用 ID 时才在原生请求中回传 ID。截断、安全拦截、取消或畸形结果不执行该轮工具。原生供应商自动采用 Gemini 隐式缓存策略，不创建显式缓存资源；Vertex AI 和 Google Interactions 不在本协议范围内。使用网关时，地址须以 `/v1beta` 或 `/v1` 结尾并确认其实现原生 GenerateContent，不能直接填 OpenAI 兼容地址。

每个模型单独配置精确 Model ID、显示名、上下文长度、最大输出 token、输入模态、工具调用与并行能力。限制必须以供应商实际支持为准。模型 ID 可能有大小写、前缀或后缀，不能用显示名代替。

新增模型（手动输入或从列表选择）首次匹配以下前缀时预填一次，之后可修改；同一新增草稿改 ID 不会反复覆盖，编辑已保存模型不触发预填。这是填写预设，不是对供应商实际能力的检测：

| Model ID 前缀 | 上下文 | 最大输出 | 输入 | 思考档 |
| --- | --- | --- | --- | --- |
| `gpt-6`（含 `gpt-6.1`） | 1000000 | 128000 | 文本、图片、文件 | `none,low,medium,high,xhigh,max` |
| `deepseek-` | 1000000 | 384000 | 文本、图片、文件 | `low,high,max` |

GPT 上述系列的新增表单显示“GPT厂商是否开启了长上下文计费？”，默认不勾选。主动勾选将上下文设为200000，取消勾选设回1000000；输出保持已填写值（初始128000）。这只是本地输入控制，不检测或更改供应商计费，保存的是实际上下文数值。

上下文和最大输出支持 `K/k`（1000）、`M/m`（1000000）：`100k`、`100K` 都是100000，`1.5M` 是1500000。仅支持这两个十进制单位，换算后须为安全范围内的正整数；保存时按整数处理。输出仍不能超过上下文。

已保存供应商可在“连接”标签修改名称、Base URL、API 协议及鉴权头，点击“保存连接”。原有供应商、Key、模型及会话引用保留；任何会话仍在运行时，地址/协议/鉴权修改会被拒绝并保留草稿，名称可单独修改。这些连接配置改变后会清理该供应商会话的旧上下文用量校准并重新估算，保留已有摘要、原始历史和累计用量。协议变化时不兼容的缓存模式/时长重置为自动/5分钟，可在下方重新配置。

Responses 协议可保留供应商实际返回的加密推理/压缩项，以及助手消息的 `commentary`（进展）和 `final_answer`（最终答复）阶段。原生状态随本地消息保存，只有供应商、模型、端点匹配且可见文字/工具调用仍一致时重放；切换配置不会把不透明状态发往其他模型或端点。官方端点会请求加密推理状态，兼容网关是否返回及接受相关字段由其实现决定，未返回时使用普通历史。加密项是供应商签发的不透明内容，不代表应用能读取原始隐藏思维链，也不保证任意网关兼容或无限上下文。

上下文估算不把 reasoning/compaction 的密文字符串长度当作 tokens：每项预留1024，合计最多8192且不超过当前模型窗口的5%，实际请求后仍按供应商 usage 校准。这是有界估算，不能推算密文包含多少原生状态或保证精确 token 数。

思考档按顺序逗号分隔，如 `none,low,medium,high,xhigh,max`，聊天中据此生成滑条。不支持的档位不要添加。Anthropic 使用 adaptive thinking 与 effort，可配置 none 行为，不要求手填 token budget。

不同供应商可以配置同名模型，聊天菜单按供应商折叠。一个供应商可保存多账户 Key，管理标签、优先级、活动状态、替换与删除。完整密钥不回显；轮换不代表免费或无限额度。

在设置中编辑供应商、Key 或模型时，可以连续输入、使用中文输入法和选中文字替换。后台会话和审批状态刷新不会将焦点移到关闭按钮；更改完成后点击对应的保存按钮。Esc 或右上角关闭按钮可退出设置，尚未保存的草稿不会自动提交。

模型菜单按供应商展开，在窗口上下可用区域内显示；供应商或模型较多时在菜单内滚动，不需要移动整个设置页。可用方向键、Home/End 浏览，Enter 选择，Esc 先关闭菜单。Skills 引用、CTX 详情、`/` 与 `@` 列表也支持限高滚动，窗口缩放和输入框增高时会重新定位。

### 供应商排序与星标模型

设置 → 供应商与模型中，长按供应商名称行或排序手柄，再拖到目标位置松开。模型选择菜单中的供应商标题行也能这样排序，设置与各菜单共用同一顺序。可将焦点放在排序手柄，用 Alt+↑/↓ 调整前后位置；横向供应商列表也可用 Alt+←/→。拖动时靠近滚动区域边缘可继续滚动，按 Esc 可取消。

在供应商的“模型”标签，点击模型旁的星形图标收藏或取消收藏。聊天、新建会话、自动审批、上下文压缩、子 Agent 模型及 TencentDB 记忆分析等模型菜单顶部都有可折叠的“星标模型”组，显示“模型 ID（供应商名）”；该组和普通供应商组都能直接点星形图标，操作不会选中模型或关闭菜单。点击模型本身才会使用该模型，并沿用原入口的保存方式。

星标绑定具体模型配置。不同供应商使用同一 Model ID 时可分别收藏；删除后重新建立的配置需要重新收藏。星标组只显示该入口允许选择的模型：禁用模型不参与选择，记忆分析仍要求文字输入/输出，备用记忆模型仍排除已选主分析模型。暂时不符合条件不会清除星标，重新可用后会再次显示；删除模型或供应商会清理对应记录。星标按供应商展示顺序及该供应商原有模型顺序排列。

排序与星标自动保存在本机，切换页面及正常重启后保留，新供应商追加到展示列表。它们只影响展示，不改变当前会话、默认或备用模型、子 Agent 继承及 API Key 优先级；“使用主会话模型”“使用当前模型”和清除备用模型等操作继续沿用原有含义。取消星标也不会清空已经选定的模型。偏好读取或保存失败时会显示原因和“重试”，重试成功后才视为保存完成。

## 会话与工作目录

左栏按工作文件夹分组，点击折叠。点击文件夹旁加号会立即在该目录创建并选中新会话，继承该目录中最近更新的未归档主会话的供应商、模型、思考档、Agent、权限、隔离模式、系统提示、仅补丁设置和已引用的技能/插件，不再弹出工作目录配置框。聊天记录、审批授权、标题与运行状态不复制。需要更换工作目录或重新选择配置时，使用左栏上方的“新对话”。来源模型或 Agent 已失效时，先修复原会话配置后重试。

可收起整个侧栏扩大聊天区。多个会话可以并行运行，状态各自保存。

每个文件夹默认只显示最近打开或更新的 3 个会话，其余暂时折叠；点击“展开全部”查看全部，再点击“收起，仅显示最近 3 个”恢复紧凑列表。搜索会检索全部未归档会话，包括折叠的记录。打开较早的会话后，它会进入最近使用列表；展开全部后仍按置顶和父子关系组织。折叠不停止任务，也不删除记录。

将鼠标移到左栏的某条会话，点击右侧省略号，可重命名、分支聊天、置顶/取消置顶、归档或删除。置顶会话排在同一工作文件夹的前面。删除前会要求确认，并先停止该会话及其子任务；删除聊天记录、子会话和应用保存的对应快照，不删除工作目录中的文件。

选择“在资源管理器中打开”，可在 Windows 文件资源管理器中打开该会话的工作目录，不需要先切换会话，运行中也可使用。本次启动中已创建隔离 worktree 时打开实际编辑目录，否则打开会话配置的目录，不会为了此操作创建 worktree。未设置工作目录时该选项置灰；目录已删除或无法访问时会在软件内提示，不会自动创建目录或改动文件。

### 按文件夹批量管理

进入 **设置 → 会话与数据 → 按文件夹管理会话**，选择工作文件夹。列表包含仅有归档记录的文件夹，以及“未选择文件夹”的会话；读取完整会话列表，不受侧栏已展开或已加载数量限制。选择“未归档”“已归档”或“全部”，再按主会话标题搜索。

逐条勾选主会话，或使用“全选匹配会话”选择当前筛选结果的全部主会话，包括其他页；每页显示50项，列表可独立滚动。翻页保留勾选，切换文件夹、会话范围或搜索内容会清空勾选。子会话随所属主会话一并处理，即使它使用独立的 worktree 目录，也不需要另行选择。

点击“归档”或“删除”后，确认框会列出本次主会话及子会话的实际数量。归档前须结束相关运行任务，归档保留消息和草稿、暂停关联定时任务；在“已归档”范围勾选后可批量恢复，定时任务仍需自行重新启用。永久删除会先停止并等待相关任务，删除消息、草稿、附件及应用快照，无法撤销，工作文件夹中的项目文件保留。

批量执行期间设置页会保持打开，完成后显示成功数量和每项失败原因。确认后若会话的子任务范围、工作文件夹或归档状态变化，该项会停止处理并提示刷新，避免将新增或移动的会话一并删除。成功项不会因其他项失败而恢复；失败项继续保持勾选，处理原因后可直接重试。

### 分支聊天

在输入框输入 `/fork` 后发送，或从左栏会话省略号菜单选择“分支聊天”。软件创建新的独立会话并立即切换过去，复制全部已保存消息（含附件、思考摘要、工具调用与结果）、模型、思考档、Agent、系统提示、权限/自动审批选择、隔离模式、扩展引用、待办及有效的压缩摘要。原聊天保持原样；后续两边的消息、重命名、归档和删除互不影响。分支不是子 Agent，不占用子 Agent 并发名额。正在运行时需先等待或停止；有未配对工具调用的历史不能在中间截断复制。

分支不复制临时审批授权、待审批项、定时任务、文件快照或正在执行的任务，也不自动创建磁盘/Git 分支。使用同一个工作目录时，两边仍可修改相同文件；需要独立文件目录时使用 Git worktree，并留意其未提交文件不会自动复制。

### 输入框的斜杠菜单

输入 `/` 会打开命令菜单，继续输入可筛选，方向键选择，Enter/Tab 执行，Esc 收回。中文输入法正在选词时 Enter 不执行命令。菜单支持以下操作，命令本身不会作为普通聊天发给模型：

| 命令 | 操作 |
| --- | --- |
| `/rename` 或 `/rename 新名字` | 打开应用内重命名框，或直接更名 |
| `/compact` | 立即压缩一次完整历史，无需达到 85% |
| `/archive` | 确认后归档，可在设置恢复 |
| `/fork` | 复制当前完整上下文为独立聊天 |
| `/skills`、`/plugins` | 搜索并引用已启用的本地技能/插件，无已安装项时可进入管理页 |
| `/status` | 查看当前上下文和模型详情 |
| `/plan` | 切换到已启用的只读计划 Agent |
| `/mcp` | 打开 MCP 设置 |

项目/全局 Markdown 自定义命令继续显示，选择后可补充参数再发送；与内置命令重名时以内置命令为准。普通文字中的 `/` 和文件路径不会触发菜单。执行聊天命令前请移除附件；运行中的会话先等待或停止，再压缩、分支或修改状态。

归档会隐藏该会话及其子会话，永久保留记录，不参与自动清理。运行中的任务须先停止才能归档；相关已启用的定时任务也会暂停。进入设置 → 会话与数据 → 按文件夹管理会话，选择对应文件夹和“已归档”范围，勾选后点击“恢复”即可回到左栏继续对话。恢复会刷新最后打开时间，定时任务需自行重新启用。

设置 → 会话与数据可选择“永不删除”（默认）或填写未打开天数，范围为 1 至 36500 天。保存自动清理设置需要确认。应用在启动后的首次检查及其后每小时清理超期的普通会话；已归档、当前打开、有待发送草稿、正在运行/等待批准、正在准备发送及关联已启用定时任务的会话会保留。父会话有需要保留的子会话时也不会被连带删除。清理按最后打开时间计算，后台工具或状态更新不会延长保留期。自动清理永久删除会话记录和对应快照，重要记录请先归档或导出。

会话可恢复继续。上下文达到 85% 时自动摘要压缩，原始历史仍在本地保留；触发时机和模型选择见下节。

会话中可选择模型、思考、权限、目录、Agent、系统指令与扩展。消息支持复制、编辑、重试。编辑/重试会替换该消息之后的历史，操作前认真确认。

已完成回复下方的复制图标可复制该条回复的完整 Markdown 正文，保留列表、链接与代码围栏；不混入思考摘要、工具日志或其他消息。每个 Markdown 代码块右上角也有独立复制图标，只复制该块代码，保留缩进、换行与特殊字符，不带语言标签和围栏。代码块在生成过程中也可复制当前已输出内容；整条回复复制按钮在消息保存后出现。复制成功显示勾选反馈，失败可点击重试；复制不会修改对话。

### 待发送草稿

新会话、已有聊天及子会话都自动按会话保存输入框草稿，无需开启设置。完整文字（包括空白）、原文/格式状态和待发送附件保存在本机用户数据目录；切换到其他会话或正常退出、重启后，重新打开原会话即可恢复。附件保存实际内容，原文件被移动或删除也不会让已保存的附件消失。草稿保存不会调用模型，也不会提前发送给供应商；格式显示继续遵循外观设置。

只有消息被应用接收并写入历史，或你手动删除输入、移除附件、删除会话时，才消费相应草稿。发送前出错会保留；模型在消息已接收后运行失败，消息已经在历史中，不再重复恢复成未发送草稿。旧发送结果不会清空你后来输入的新内容。归档或自动清理不会移除待发草稿。

正常退出与重载会先等待正在读取的附件和草稿写入。保存或恢复失败时输入区显示错误和重试图标；保存失败会取消退出，处理原因并重试保存后再退出。草稿属于本地应用数据，迁移时应正常退出后备份整个数据目录。

### 历史问题导航

同一会话发送至少两条问题后，聊天区右侧出现一列短横线，每条代表一条已发送的问题。鼠标悬停可预览问题开头、正文片段和附件名称，点击即可跳到原消息。较长、较亮的标记表示当前阅读的问题，随页面滚动更新。概要直接来自本地消息，不会额外调用模型或产生 API 用量。

问题很多时，可在导航条上滚轮查看其余标记；也可按 Tab 聚焦标记，使用方向键、Home/End 选择，Enter 跳转，Esc 收起预览。任务输出中跳到历史问题会暂停底部跟随，不会被新输出拉走；手动滚回底部后恢复跟随。切换会话使用各自的问题列表；编辑/重试替换历史后，相应旧标记随之移除。仅发送附件的消息也可以跳转。

### Agent 主动向你提问

遇到无法从现有资料判断、会影响方案或交付结果的需求，Mingshen 会调用 `ask_user` 显示提问面板，而不只是发一段问题后结束任务。普通工作、Plan 以及用户自建的独立 Agent 会话都能使用；模型必须已开启工具调用，Agent 配置也不能禁用提问工具。是否调用仍取决于模型判断。你也可以说“有不清楚的地方先用提问功能问我”。

- 每题最多四个选项，每项都有标题与描述；软件额外提供一个“其他”，可填写自己的回答。
- 单选题只能选一个选项，或选择“其他”自填。多选题可同时勾选多个选项，也可附加“其他”内容。选中“其他”后必须填写内容才能提交。
- 一次通常一题，最多三个相关问题。多题可用上一题/下一题回看并调整；全部回答后统一提交。没有合适选项的开放问题可直接输入文字。
- 等待时显示“等待回答”，普通消息输入区暂时收起，停止按钮保留。选项较长时在面板内滚动；单选/复选框支持键盘，文本框内 Ctrl+Enter 可提交。切换会话或重载可恢复待回答问题，尚未提交的选择不作为正式回答。
- 点击“提交回答”后，软件将每题的选择与自填内容返回当前模型，自动继续原任务，无需再次点击发送。问题、回答及后续执行可以从相应工具记录查看，原聊天上下文保留。
- 回答提交失败会显示错误，保留当前选择以便重试；五秒仍未确认时恢复按钮。停止任务会取消问题，不会自行猜答案。完全访问、自动审批和本会话授权均不会代你回答。

提问是澄清需求，不是文件、命令或 MCP 审批。回答不会提高项目权限，不要在“其他”中填写 API Key、密码等秘密。回答会随当前会话发送给所选模型供应商。实际委派的子 Agent 将需要用户决定的事项报告父 Agent，由父 Agent 汇总后提问；直接选择 General/Explore 或自建 Subagent 配置创建的独立会话不受此委派限制。

如果此时软件在后台、最小化到托盘或你正在查看其他会话，会收到 Windows 提问提醒。点击通知或“查看问题”回到对应会话，在原提问面板选择并提交；通知不替你作答，也不将关闭通知视为回答。前台已显示该会话时只保留软件内面板。设置 → 外观中的“Agent 提问与修改冲突提醒”可控制这两类通知。

## 上下文与自动压缩

上下文是模型一次请求能够容纳的信息，包括系统提示、工具定义、聊天消息和工具结果。输入框下方的 CTX 显示当前使用百分比。点击可展开用量，例如 `32.5K / 128K tokens`，以及计数来源、85% 自动压缩阈值、当前模型和最近压缩时间。K 表示 1000 tokens。有供应商用量时结合实际输入和输出 token 校准，没有时按实际请求内容估算。不同供应商和多模态的实际 token 计算可能不同，请正确填写模型的上下文长度。

**重启后无需先发消息：** 打开已有会话时恢复本地保存的有效用量，详情显示“已从本地记录恢复”；旧版缺少模型标识的记录会尝试结合对应供应商用量修复。新会话、分支、已修改历史或切换模型后，使用当前模型、有效摘要/历史、内置提示及本地已知工具计算估算值，标注“本地上下文估算”。新会话也有提示词与工具成本，因此不一定是 0%。这一恢复过程不调用模型、不启动 MCP 或项目脚本，不产生模型 API 用量。未打开的历史会话按需恢复，避免启动时遍历全部聊天。

本地估算不是精确 tokenizer；尚未加载的项目指令、技能全文和动态工具可能有差异，下一次真正请求时按实际内容重新校准。切换模型后不会冒用另一模型的用量。仅当当前模型已删除或配置无效、无法计算时仍显示未知，请重新选择可用模型。恢复数值不会自行触发压缩，85% 自动压缩仍在下一次模型请求前检查。

当占用达到当前对话模型上下文窗口的 **85%（含）**，软件在下一次请求模型前自动压缩。如果本轮回答已经结束，不在后台额外请求模型，而是在下一条消息开始时触发；如果任务仍在调用工具，则等待当前工具结果返回，在下次请求前触发，不拆开尚未完成的工具调用与结果。

压缩期间输入区上方显示“正在压缩上下文”，并说明可能需要几分钟、原始记录会保留。自动压缩时任务保持运行，完成摘要后自动发送当前指令并继续工作，不需要重新点击发送。可以切换会话或向上阅读，重新加载界面可恢复正在压缩的提示，也可以停止任务。

**手动压缩：** 完成至少一轮对话后，输入 `/compact`，或在 `/` 菜单选择压缩；也可点击 CTX → 立即压缩。无论是否达到 85%，都会尝试对可压缩的完整历史生成摘要，沿用该会话当前/全局/指定模型及备用模型规则。手动压缩不添加用户消息、不启动工具/MCP、不额外生成普通回答或任务完成通知。完成后等待你的下一条消息，原始消息仍可查看。可停止、重试；无可压缩历史、摘要未缩小或上游错误时明确提示，不保存半截结果。

成功压缩后，CTX 立即按“摘要 + 保留的近期消息 + 系统提示与工具成本”重新估算，百分比和 K-token 数值同步刷新并保存，重启仍可恢复；不会用整段原始聊天或压缩前的校准值填回。固定提示/工具较大时仍会占用窗口，数字不保证降到某个比例。下一次真实模型请求会再用供应商用量校准；它表示当前上下文，不是累计消费 token。

点击 CTX → 压缩设置，或打开设置 → 上下文与压缩，可设置：

| 配置 | 行为 |
| --- | --- |
| 全局未指定模型 | 默认使用各会话当前模型 |
| 全局默认压缩模型 | 继承全局的会话使用此模型，聊天模型不改变 |
| 会话：继承全局默认 | 使用全局模型；未设置时使用当前会话模型 |
| 会话：始终使用当前会话模型 | 即使设置了全局模型，也使用该会话当前模型 |
| 会话：指定压缩模型 | 使用此会话单独选择的供应商与模型，优先级最高 |

选择后点击对应的“保存全局配置”或“保存会话配置”。模型菜单仍按供应商分组；直接复用该供应商已保存的 API Key。新会话默认继承全局配置；同文件夹加号和子 Agent 继承来源会话的模型选择，摘要与历史不复制。

同页可选择“备用压缩模型（可选）”并点击“保存备用压缩模型”。该备用设置作用于全部会话，无论主模型来自当前会话、全局还是会话覆盖。主模型网络失败、超时、断流、空摘要、返回错误内容或摘要无法缩小上下文时，提示正在使用备用模型，并从原始历史和上一份完整摘要重新生成，不使用失败主模型留下的半截结果。主、备各进行一个逻辑尝试；1.2.9 起每个尝试内部可按全局配置重试传输错误，仍受总超时约束。备用与实际主模型相同时不重复调用。保存的全局主备不允许选择同一模型。清除备用选择后仍需保存。

压缩的总输出上限同时受当前主会话模型窗口的 **15%**、压缩模型配置的 `maxOutputTokens` 和可用上下文约束。较小压缩窗口会为历史输入与滚动摘要预留空间，额度可进一步降低；发送前再根据实际请求输入与安全余量收紧。例如主窗口为 **200,000 tokens** 时，最多允许 **30,000 总输出 tokens**，实际额度可能更低。**推理和摘要正文共享总输出额度**，不保证全部额度用于正文。主、备压缩模型均遵守此规则，提示词同时明确摘要总上限和本次正文目标，为推理预留空间。

遇到输出额度耗尽时，软件会提示正在要求更简短的摘要、缩小历史片段，并降低本次正文目标；每个压缩模型最多进行 **4次有界恢复**。每个片段请求最多5分钟，包含该请求的传输重试等待；每个压缩模型最多128次逻辑摘要请求。传输重试与输出耗尽恢复分别受各自限制。恢复仍失败、取消或停止时，保留原始消息和上一份完整摘要，不采用截断或半截结果；可检查最大输出与思考设置，或更换压缩模型。

较早历史生成摘要后，当前指令和可保留的最近工具步骤继续传入模型，原始消息和工具记录不从聊天中删除。更小的压缩模型可通过分段合并处理历史，但上下文或输出上限过小、单条输入过大、固定提示本身过大时仍可能无法完成。可解析文档与文本附件在摘要中最多取前 120,000 个字符并标明截断；旧会话附件也会尝试本地解析。未解析的二进制附件只摘要元数据和路径，不假设已理解其内容。重要图片或其他附件必要时重新提供。摘要可能遗漏细节，请核查重要事实。

压缩请求会向所选供应商发送较早的消息、工具内容和文本附件，可能产生额外 API 用量。使用独立供应商前请确认其数据政策和资料授权。HTTP 错误、空摘要、工具调用或未能缩小上下文的结果不会替换已有摘要；界面保留错误和原始记录。原上下文仍可容纳请求时继续当前任务，同一次运行不反复重试，下一轮重新尝试；已无法容纳时明确报错，请检查压缩模型、缩小输入或更换更大窗口的聊天模型。停止或退出时不保存半截摘要。

## 权限和执行环境

ChatAgent 固定使用受限聊天策略：只开放搜索、网页读取和上传附件解析，不提供本地路径读取、文件修改、命令、MCP、Skills、Hooks、浏览器自动化或子 Agent。它没有可提升到“完全访问”的本地工具入口。CodeAgent 与 WorkAgent 继续使用原有“请求批准 / 完全访问”和隔离设置；WorkAgent 的办公工具不会扩大这些权限。可选 Office COM 只在 WorkAgent、完全访问、宿主执行、非子 Agent、Office 已安装且策略允许时尝试，失败时降级并标注未验证，不自动安装 Office。

### 请求批准

Agent 文件、命令和 MCP 操作需审批，可单次、限时、会话允许或拒绝并填写原因。核对批准范围，不要因提示频繁而盲目允许。

“本会话允许”只记住界面所示的路径/命令范围，不代表整个项目完全访问；下一个不同路径或命令仍可能需要审批。处理一条审批后，新审批不会被上一条的回执清除。切换会话或重新加载界面时，待处理操作会从主进程恢复；其他会话的审批保留在对应会话中。

审批和 Agent 提问都会在窗口重新获得焦点、切换会话及每三秒的后台同步中恢复，不必停止任务后重新生成。提交审批后显示“正在提交审批”；如果五秒后后台仍未确认，会重新显示当前请求及可重试提示。提交失败会恢复操作按钮，旧请求的迟到回执不会隐藏下一条请求。出现“正在恢复待处理请求”时，也可点击“刷新请求”立即同步。新的审批或提问会回到输入区的可视位置；软件不会为了恢复界面自动批准操作。

### 自动审批

1. 进入设置 → 权限与安全 → 自动审批模型，按供应商选择已经配置的模型，点击“保存审批模型”。API Key 使用该供应商当前可用的 Key，无需重复填写。
2. 在会话权限菜单选择“自动审批”，或在审批面板点击“自动审批”。未配置模型时会显示应用内提示，可直接打开设置；不会自动放行当前操作。
3. 软件逐项发送拟执行的工具名、命令、路径和参数给审批模型。文件操作参数可能包含拟写入内容；不会附带整段聊天记录或向审核模型开放执行工具。请确认该供应商可接收这些数据；审核可能产生额外 API 用量。
4. 审批提示要求固定 JSON 裁决，`decision` 仅为 `allow` 或 `deny`，`reason` 可使用任意语言。也兼容单一明确的中英文裁决、大小写、JSON 代码块等常见返回；多条冲突裁决、缺少原因或含糊回复不会自动批准。通过后仅执行当前一项，不通过则把原因返回主 Agent；活动记录保留实际结论。
5. 审核期间仍可单次允许或拒绝，也可停止任务、切回“请求批准”。切回手动后，迟到的审核结果不会继续放行。后续新操作继续按当前选项处理。

在同一设置块选择“备用审批模型（可选）”，点击“保存审批模型”一起保存。主模型网络错误、超时、断流或裁决无效时自动尝试备用一次；主模型的有效拒绝立即生效，不会转备用寻求通过。主备模型使用自己的供应商地址、协议和凭据，优先选择配置中可用的较低思考档，每次审核最多等待 45 秒，主备合计可能接近 90 秒。审核期间可手动处理；停止、切回手动或更改审批配置会取消旧审核。操作参数过长、Shell Hook 或明确要求手动的策略不会因备用配置绕过人工处理。

两次审核均失败时仍显示审批面板，错误保留主备来源和 HTTP 信息；返回格式错误时提供脱敏且限长的原始回复预览，便于判断是否为供应商错误、输出截断或格式问题。不会把未知语言的自由文本猜成通过。`Upstream HTTP/2 stream failed` 表示上游或网关流传输失败，不能仅凭该提示判定是本机网络。必要时检查供应商状态、配置独立供应商的备用模型或手动处理。

备用审批会收到相同操作数据，备用压缩会收到相同历史与工具内容，都可能产生额外 API 用量。配置前请确认资料允许发送给主备双方。备用默认关闭，不需要时清除并保存；不会在每次成功调用时额外请求备用。

自动审批仍属于请求批准的隔离模式，沙箱、Plan 只读限制、致命命令硬保护继续生效。Shell Hook 和 Agent 配置显式要求手动批准的操作仍需手动确认。模型可能误判；高风险操作仍应人工复核。配置审批模型不会自动启用所有会话；文件夹加号继承来源会话的自动审批选择，子 Agent 继承父会话选择。

默认采用 Windows 原生进程沙箱（基于固定版本的 Codex Windows MXC 执行器），文件工具和命令在选定工作目录范围内运行，命令子进程继承隔离，关闭命令网络访问。主程序负责审批、模型联网、凭据、快照和界面，这些可信服务不属于命令沙箱。原生隔离只在系统支持时可用；环境缺失或不兼容时停止执行，不静默回退宿主机。

当前 MXC 需要较新的 Windows 11 24H2/25H2 系统补丁（24H2 至少 26100.9278、25H2 至少 26200.9278）。Windows 10 或旧版 Windows 11 可选择 Docker 隔离；运行主界面与满足 MXC 条件是两件事。设置 → 运行与集成 → 检查依赖会实际启动探针检测。

宿主机自定义脚本、斜杠命令 shell 预处理、自动 Formatter/LSP 和 Hook 在保护模式受限；项目检查应通过批准的隔离命令执行。第三方 MCP、浏览器和用户主动操作的终端具有独立边界。批准启动本地 MCP 会允许该第三方进程使用你的 Windows 账户权限，启动提示会说明这一点；不能把它理解为已进入沙箱。

### 完全访问

允许更广泛文件操作与命令，无需逐项审批。固定致命命令保护保留，但模式本身高风险；仅用于可信仓库和任务，不要把命令正则当作恶意代码检测器。

审批面板的“此项目完全访问”会通过应用内确认框说明范围，确认后立即处理当前待审批操作，并将同一工作目录的现有会话和后续新会话设为完全访问，无需停止当前任务。可在权限菜单切回“请求批准”，同一目录权限会同步恢复。没有选择工作目录时只改变当前会话。此选项不会批准 Shell Hook 或覆盖 Agent 配置中显式手动确认的规则；致命命令硬保护始终保留。

### Docker

在运行与集成检查依赖，可从官方源安装 Docker Desktop。Windows 需要虚拟化、WSL2，可能需要管理员确认或重启。Docker 有独立许可和订阅条件，不能承诺所有电脑无需系统配置。

在会话的“隔离”菜单选择 Docker。默认 PowerShell Linux 容器只挂载 `/workspace` 对应的工作区，容器根只读、移除 capabilities、无 Docker socket，并限制内存、CPU、进程数。受保护命令关闭网络。容器不自动包含全部开发工具，可按项目配置镜像或 Dockerfile。原生沙箱与 Docker 是可切换的执行后端，两者都叠加应用审批；并非把 Docker 引擎整体嵌套在 MXC 中运行。

### Git worktree

已有提交的 Git 仓库可创建独立 detached worktree，每会话隔离编辑，适合并行任务。它不是安全沙箱；主目录的未提交改动不会自动复制。含未提交改动的 worktree 不会被自动强删。

## 运行任务与审查修改

活动行展示真实工具事件，编辑参数流入时出现的行数是估计，最终以实际 diff 为准。文件可点击在右栏预览，命令可展开看完整输出。运行轨迹保留于本地。

发送后立即显示“思考中”和已运行时间；不足一分钟显示秒，随后自动进位为分、时，例如 `1 分 5 秒`、`2 小时 3 分 8 秒`，超过一天继续累计小时。工具执行、等待批准、完成、中断或失败会更新状态。聊天区、左栏和修改汇总显示当前或最近一轮的耗时，完成后停止计时；切换会话或重新加载后可恢复最近一轮记录。耗时是实际经过的时间，不代表模型内部思考内容。

模型输出时，停留在聊天底部会跟随新内容。向上滚动查看前面的思考摘要或工具记录后，界面会保持阅读位置，后续输出和任务完成不会强制拉回底部。手动回到底部后恢复跟随；滚轮、滚动条和键盘翻页均可使用。

暂停跟随后，聊天区右下侧会出现一个向下箭头，悬停提示“回到底部并恢复自动跟随”。点击会立即回到最新内容并恢复自动跟随，按钮随之收起；再次向上滚动即可暂停。箭头位于正文侧边留白，与历史问题导航条错开，减少遮挡文字。任务完成后仍可点击查看最后的回复，也支持 Tab 聚焦和 Enter 操作。

简约实时编辑进度默认只显示一行，新一轮任务重新默认折叠；光轨默认显示执行记录时间轴。点击具体记录查看完整详情或文件修改预览，可随时收回，后续修改不会强制展开已收起的记录。完成后的最新修改汇总仍可展开查看 diff。

创建、修改、删除文件后出现汇总及 `+/-`，展开检查具体行。模型输出的本地文件链接在侧栏打开，网页链接交默认浏览器。不可信可执行文件不应直接运行。

回答中的数学公式支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`，以及将单个 `$` 单独成行的公式块。代码块与行内代码保留原始字符，不作为数学公式解析。

新输入默认以原文编辑，粘贴、普通键入、输入法组合和快捷键都不会自动切换到格式预览；只有手动点击眼睛图标才进入 Markdown/LaTeX 预览。原文/预览选择会随草稿保存并在正常恢复时保留，发送始终使用原文。设置 → 外观与语言 →“在输入区显示 Markdown 和公式预览开关”只控制底栏是否显示原文/预览按钮，立即生效并自动保存。支持公式分隔符、标题、加粗、列表、表格与代码。也可在预览中按 Esc 或直接输入继续编辑，Enter 沿用原有发送行为，Shift+Enter 换行。Ctrl+A 会转到原文并只选中当前草稿；预览中的第一次 Ctrl+X 只转入原文，确认选区后再剪切。右键预览会切回原文并打开原有编辑菜单。

格式预览只改变显示，发送保留原始 Markdown/LaTeX 及内部空白，沿用原有首尾空白清理。预览不会打开链接或加载远程图片；图片粘贴仍作为附件。超过 30,000 字符、1,024 个解析节点或 128 个公式的草稿会保留原文编辑，完整内容仍可发送。没有公式分隔符的任意 LaTeX 片段不会自动猜测为公式；不完整或无效的公式可切回原文修正。

Git 面板支持单文件/全部撤销，先备份文件和暂存区，重启后可恢复；恢复前再备份当前状态。HEAD 改变时拒绝恢复旧暂存区。撤销会影响你自己的未提交内容，先确认再操作。

文件快照最多 1 GiB、100,000 个文件，忽略 `.git`、`node_modules`、构建缓存等，不是整盘备份。恢复会移除快照后新建的受管理文件，并预先创建安全快照。重要项目仍应提交 Git 和外部备份。

## 附件和多模态

输入区加号可上传或引用技能，支持把文件拖进窗口。每条消息最多 10 个附件，单文件最多 25 MiB，合计最多 50 MiB；数量、单文件和累计大小会在读取文件内容前检查。图片、已有音频、视频、文档、代码能否直传取决于模型和协议，不支持的模态会禁用或提示。

### ChatAgent 只读附件

ChatAgent 可主动上传 PNG/JPEG/WebP/GIF/BMP/TIFF/AVIF 位图、PDF、Word（`.doc`/`.docx`）、Excel（`.xls`/`.xlsx`）和 PowerPoint（`.pptx`）做只读问答。应用只处理你选入输入框的上传字节；消息中的任意本地路径、网络共享路径或 `file://` 文本不会触发读取。主进程会核对图片声明的 MIME 与文件头签名，SVG、伪装成图片的内容和旧版二进制 `.ppt` 不会作为已支持附件传入；旧 `.ppt` 请先用 PowerPoint 另存为 `.pptx`。每条消息限 10 个附件、单文件 25 MiB、合计 50 MiB；解析能力、部分读取、不支持模态和视觉模型限制与普通附件相同。

附件不会因为进入 ChatAgent 就获得文件编辑能力：模型只能基于已解析或已发送的只读内容回答，不能在本地创建、覆盖或删除文件，也不能调用 Office、命令、MCP 或 Skill 完成操作。若需要实际生成 Word、Excel、PowerPoint 或修改本地项目，请切换到 CodeAgent/WorkAgent 并使用对应工作区。

复制截图或图片后，点击对话输入框按 `Ctrl+V`，或在输入框右键选择“粘贴”，即可加入待发送附件；可连续粘贴多张图片，也可逐张移除。普通文字仍粘贴到光标位置，图片链接不会自动下载。粘贴不会自动发送，每张图片同样受 25 MiB 限制；发送前需选择支持图像输入的模型。右键菜单还支持剪切、复制和全选。应用只在你主动粘贴时处理剪贴板内容，不在后台监控剪贴板。

对于已在工作区中的截图、生成图片或文档页面图，支持图像输入的模型还可调用 `view_image` 查看实际像素。支持 PNG、JPEG、WebP、GIF，单图最多20 MiB；不接受 URL 或 SVG。图片经过现有路径、读取批准与原生 MXC/Docker 网关后作为工具结果随消息保存在本地，并在后续请求中发送给所选视觉模型；仅文字模型不提供该工具。工具成功返回图像不等于模型的视觉判断必定正确。

无实时录音承诺。上传 PDF、DOC/DOCX、XLSX/XLS、PPTX、ODT 和常见文本/代码文件时，应用直接从附件内容读取，随消息传给所选模型；无需提供文件路径，不要求安装 pandoc、Office 或 PowerShell 压缩库。Word 97–2003 二进制 `.doc` 和现代 `.docx` 均支持文字提取，不运行宏，不保证还原图片或排版。

PDF 自动选择读取方式：模型配置启用“文件”且协议为 Responses / Anthropic Messages 时发送原 PDF；否则启用“图像”时发送带页码的页面图像，可交给当前视觉模型识别扫描件、手写、图表和公式；纯文本模型自动使用随包的离线简体中文/英文 OCR。`read_document` / `read_file` 也能在批准读取后本地 OCR，无需另配第三方识别 Key。模型配置必须符合供应商实际能力；手写建议选择 PDF 或图像视觉模型，OCR 对潦草手写、公式、复杂表格可能不准确，重要内容请对照原文核实。

每份提取文字最多 120,000 字符；PDF 本地最多检查前 200 页，页面图像与 OCR 各最多处理 20 页，图像总量最多 20 MiB，单页长边最多 2,000 像素，解析最长 180 秒。超出会注明读取范围，请拆分大文档后重传。原生 PDF 的远端页数限制由供应商决定。解析期间可以停止任务；加密、损坏或超出安全解压限制会明确报错，不自动调用外部解析程序。其他二进制按原模态/路径规则处理。提取文字随本地消息保存，可进入配置的压缩模型；页面图像仅在请求和有限内存缓存中生成，不另存数据库。切换模型会按新能力重新准备 PDF。

## 制作文档

在聊天中直接要求 Agent 制作文档，或明确调用 `create_document`，即可在当前工作区生成 `.docx`、`.pptx` 或 `.pdf`。输出格式由目标文件扩展名决定。可用内容包括标题、段落、列表、表格、分页、幻灯片、讲者备注，以及工作区内经单独批准读取的 PNG/JPEG 图片；DOCX 保持 Office 可编辑文本与表格，PPTX 保持可编辑幻灯片内容，PDF 保持可选中文字。

生成不需要 Office、Python、pandoc 或网络资源。应用使用内置 Chromium 离线排版 PDF，Office Open XML 作者库生成 DOCX/PPTX；默认字体是系统 `Microsoft YaHei`，缺失时由系统替代。旧 `.doc` / `.ppt` 不是输出格式；已有 DOCX 支持下述局部编辑，不保证所有 Office 文件无损往返。

1.3.1 可把 LaTeX 转为 DOCX 原生可编辑公式，包括常见分式、根式、上下标、积分、求和、矩阵、分段与对齐公式；支持独立公式和段落内的行内公式。也可直接提供 Markdown，转成标题、列表、表格、代码、引用、链接和公式。DOCX 还支持脚注、目录域、页眉页脚、页码、边距；DOCX/PPTX 支持原生图表和内嵌数据工作簿。目录的准确页码需要在 Word 中更新域。

1.3.2 支持在 DOCX 表格单元格中放置多段内容、混合格式文字、Markdown、列表、代码、引用及原生可编辑公式，也可生成对应的 PDF 排版。要求 Agent 使用 `table.rows` 的 `{"blocks":[...]}` 单元格即可；原有字符串单元格继续按纯文本输出，不猜测其中的 Markdown 或公式符号。PPTX 表格仍仅支持纯文本单元格。每个结构化单元格最多 50 个块、合计 20,000 个文字字符，并计入整份文档的容量限制；完整示例见 `docs/DOCUMENT_TOOLS.md`。

1.3.3 可直接修改没有占位符的 DOCX 旧稿。要求 Agent 先用 `read_document` 的 `structure:true` 读取原稿结构和 SHA-256，再用 `create_document.edit` 精确替换普通段落内文字、表格单元格文字、完整正文段落/表格区段，或只调整段落格式。小范围替换保留周边 run 格式，整块替换可插入公式、富表格、图片和图表；默认另存。源文件变化、定位不唯一、操作重叠或选区涉及书签、批注、修订、跨段字段、分节等保护结构时明确拒绝，不把全文提取后重建当作无损修改。未选内容及无关包部件保留，正文 XML/ZIP 会重新序列化，改字仍可能改变分页。

排版可设置段前/段后间距、行距倍数、首行和左右缩进、两端对齐、与下段同页、段中不分页及段前分页。表格支持 `column_widths:[1,3]` 等相对列宽，DOCX/PDF 均适用；旧稿可用 `format_paragraph` 改段落排版，保留文字、run 和公式。PPTX 暂不接受这些新排版参数。参数单位和完整例子见 `docs/DOCUMENT_TOOLS.md`。

WorkAgent 的 `office_document` 进一步覆盖结构化办公工作流：`create_spreadsheet`/`edit_spreadsheet` 创建或修改原生 XLSX，`edit_presentation` 对受支持的 PPTX 形状、表格和备注做基于源 SHA 的受控编辑，`inspect` 检查 DOCX/XLSX/PPTX 结构和公式状态，`verify` 执行结构验证并可选调用已安装 Microsoft Office。WorkAgent 会先按受众、决策、提纲、输入/计算/输出和视觉网格组织内容，再检查排版、可编辑对象、公式状态与渲染结果。

Office COM 是可选增强，不随应用自动安装或打包 Office。只有在 **WorkAgent + 完全访问 + 宿主执行 + 非子 Agent**，且 Microsoft Office 已安装、相关进程空闲、系统/组织隔离策略允许时，Excel 重算和 Word/Excel/PowerPoint PDF 渲染才会尝试运行。应用使用临时副本，不直接接管用户正打开的文档；Office 版本、字体、DPI、打印机驱动和宏/第三方扩展差异仍可能影响结果。请求批准、Docker、子 Agent、Office 缺失或 COM 失败时只保留结构检查，并明确标注公式重算或渲染“未验证”；不会把无缓存公式、普通文件成功写出或文本提取当成 Office 已重算/已渲染。

需要沿用现有 DOCX 模板时，可提供唯一且独占普通段落的 `{{body}}` 等标记，要求 Agent 另存填充结果；模板读取单独批准，受保护结构、缺失或重复标记会拒绝。PDF 支持公式排版，但不是 Office 可编辑公式；PPTX 暂不支持原生公式块。未知数学语法明确报错，不偷偷转成图片，完整 TeX 宏包和任意旧稿无损修改不在当前范围。公式回读仅提供线性文字摘要，不能代替实际排版检查。参数示例和能力矩阵见仓库 `docs/DOCUMENT_TOOLS.md`。

生成仍受当前 Agent 的 Plan、patch-only、权限 profile、审批、隔离、文件 lease、外部修改检查和取消规则约束。默认不覆盖已有文件；需要覆盖时必须明确 `overwrite:true`，软件会先读取当前文件并核对版本。图片只从当前工作区读取，不从 URL 下载。已有 Agent 配置沿用 `write_file` 的工具资格及限制，图片还须满足 `read_file` 策略；只读 Plan 和 patch-only 会话不提供文档生成。

可选择 A4 或 Letter 纸张及横竖方向，默认 Letter；PPTX 为 16:9。单次文字最多 500,000 字符、内容块合计最多 1,000 个、生成参数最多 1 MiB、输出最多 25 MiB、图片总计最多 20 MiB、幻灯片最多 100 张，模板填充也受相同容量限制。PPTX 自动检查文字/表格框能否容纳内容，超出时要求减少内容或拆页。PDF 渲染 60 秒超时，可停止；普通失败或取消保留原输出，不提交半成品。强制结束进程或系统崩溃可能留下临时文件。

## Skills 与插件

本地目录或子目录必须存在 `SKILL.md`；支持嵌套、YAML 多行 description、脚本与资源。Codex 插件识别 `.codex-plugin/plugin.json`。导入后保存本地副本，不持续同步源目录。

每个本地扩展最多 20,000 个文件，技能市场安装每个技能也最多 20,000 个文件，总计最多 64 MiB。本地扫描和复制忽略 `.git`、`node_modules`、`.cache`、`dist`、`out` 目录；市场预检按远端目录中的全部文件保守计数。文件数包含 `SKILL.md`，恰好达到上限可以继续检查大小，超过上限会在复制或下载前拒绝。

Skills 默认只发现名称、描述等元数据，不把技能全文在启动时注入上下文。实际需要时由 `use_skill` 按需读取，单页最多 32,000 字符，并可用 `char_offset` 继续读取；单个可加载的 Skill 文本资源最多 2 MB，二进制资源不能作为指令加载。旧的 120,000 字符扩展全文启动注入已取消，文件导入数量与模型上下文预算分别管理。

CodeAgent 和 WorkAgent 会为内置 Skills/Plugins 与全部已安装且启用的 Skill/插件建立轻量能力索引。输入框左下角加号的“引用”面板可分别查看内置 Skills、内置 Plugins、已安装 Skills 和已安装 Plugins；手动选择按会话保存并优先，未手选的启用项仍可由 Agent 按任务关键词搜索，再以返回的精确 ID 加载。手动选择不会关闭自动发现。以“停用”“禁用”状态保存的扩展不会进入搜索或读取，ChatAgent 也不具备此索引。

内置能力选择最多 32 项，不占用或改写已安装扩展引用。当前内置 Plugin 元数据包括 GitHub API 与内嵌浏览器入口；选择它们只表示当前会话的工具偏好，不会自动连接 GitHub、登录浏览器、启动服务或绕过审批。Skill 正文是否能在首轮系统提示中预载，取决于当前 Agent Profile 是否允许 `use_skill` 且无需交互审批（包括默认读取策略）；预载总额最多 64,000 字符，ask、deny 或其他项只保留精确 ID，后续照常按需加载并审批。

安装、启用或自动发现只提供 Skill/MCP/命令的发现能力；插件 Hook 必须先把该插件引用到当前 CodeAgent / WorkAgent 会话，且不会因后台自动发现而隐式执行。内置 Plugin 的元数据选择也不能把某个已安装插件自动加入 Hook 列表。

左下角加号引用所需扩展。技能和仓库提示不可覆盖安全授权。市场分开显示 OpenAI 官方仓库和 Composio Awesome Claude Skills，每页最多 20 个。安装前核查来源、许可、脚本；市场不是安全认证。

### 本地插件开发市场

原生插件使用 `.mingshen-plugin/plugin.json`，还可包含 Harness 适配技能、Markdown 命令、MCP 声明和受控 Hook。插件根目录、`marketplace.json` 市场根和安装后的本地副本彼此独立；修改源码不会热更新已安装插件，必须刷新市场并点击“更新”。

开发完成后，在 **设置 → Skills 与插件 → 本地插件开发市场** 点击“添加市场”，选择市场目录或 `marketplace.json`。界面会校验插件清单、名称/版本、Skill 入口、路径和声明文件；通过后点击“安装”，再用卡片开关启用。安装或更新期间若任何 Agent 任务仍在活动，主进程会拒绝修改；先完成任务或手动停止。更新保留插件 ID、会话引用和原有启用/停用状态，并在下一轮或新任务生效。

安装并启用插件后会进入可发现范围，但不会自动把 Hook 变成全局监听。需要在当前 CodeAgent / WorkAgent 的输入框加号菜单或 `/plugins` 中引用该插件，Hook 才会在事件发生时由宿主检查。常规动作型 Hook（`PreToolUse`、`PostToolUse`、完成后的 `Stop`、`SubagentStop`）只在**主 CodeAgent / WorkAgent + 宿主执行 + 完全访问 + 已信任项目 + 当前会话已引用已启用插件**时尝试；请求批准、Docker、ChatAgent、实际 SubAgent 和只读配置均不执行。MCP Hook 仍须逐次人工审批，Shell Hook 还须已开启、项目已信任并逐次审批。`Interrupt` 是用户显式停止后的独立清理期通知，使用最多约 1.5 秒的独立信号并 fire-and-forget；它仅发送 `prompt` 文本活动通知，声明的 Command/MCP 动作一律跳过，绝不审批、启动进程或恢复工具。ChatAgent、实际 SubAgent、请求批准、Docker 和应用关闭时不会触发 `Interrupt`。

CodeAgent/WorkAgent 内置 `skill-creator`、`plugin-creator` 和 `harness-plugin-api` 按需技能。可以让 Agent 创建标准 Skill 或完整本地插件，但模型没有安装、更新、启停或卸载权限；它只能使用受限的只读 `local_plugin` 执行 `inspect`、`validate` 或 `list_markets`。主 Code/Work 的宿主 Windows 会话在请求批准和完全访问模式下都可使用该工具；`inspect`/`validate` 继承 `read_file` Profile，只接受工作区内真实绝对目录，并在请求批准模式下按目录审批。Docker、worktree、ChatAgent 和实际 SubAgent 不能调用。宿主校验不要求系统 Node/PATH，随包 SDK 只是用户可选的开发预检。完整清单示例、SDK 命令、手动安装、Hook 安全和故障排查见[本地插件接口](LOCAL_PLUGINS.md)。ChatAgent 不加载插件、Skill、MCP 或 Hook。

## MCP 和 GitHub

可配置 stdio/HTTP MCP，填写启动命令、参数、环境变量或 URL、鉴权头、超时。敏感值加密保存。启用后先测试，“发现工具”不等于每个工具实际执行都已通过。

| 服务 | 需要配置 |
| --- | --- |
| Wikipedia | 网络，无 API Key |
| GitHub | PAT 或 Device Flow Client ID |
| Notion | 集成 Token，且将目标页面分享给该集成 |
| Browserbase | API Key 和 Project ID |
| BrowserDo | 自带 MCP；官方安装 Embiody |

Plan 只获得已知只读 MCP 工具。请求批准下审查每次调用，可会话允许服务器。第三方服务拥有其自身权限，不会因在 Harness 启用而自动变为沙箱服务。

GitHub 是 API/MCP 集成，不是浏览器书签。PAT 在 GitHub Settings → Developer settings → Personal access tokens 创建，按所需仓库和操作授予最小权限，粘贴专用输入框，不能发进聊天。注册 Client ID 和设备授权详见 [OAuth 说明](GITHUB_OAUTH_SETUP.md)。

点击“使用浏览器授权”后，Harness 会先在设置页显示 `XXXX-XXXX` 格式的设备验证码和复制按钮，再打开 GitHub 页面。在 GitHub 输入的是 Harness 提供的这个码，GitHub 不会反过来给你一个新码。授权后返回 Harness 等待连接成功。切换设置页或关闭再打开设置，可继续看到尚未过期的验证码；取消授权或退出应用会终止本次等待。不要把验证码或 Token 发给他人。

## 浏览器

内置 Chrome/Edge 兼容页由 Electron Chromium 提供，在工作区右栏与 Agent 共享，支持导航、结构读取、点击、输入、滚动和截图。不是操纵已有个人 Chrome/Edge 标签。

`browser_screenshot` 截取当前可见页面，按比例将最长边限制在2048像素，PNG最多8 MiB；成功后保存本地 PNG，并通过 `tool_result.images` 把实际像素传给下一次支持图像的模型请求，以检查布局和页面状态。当前模型未配置图像输入能力时，工具明确提示图片未发送；切换到图像模型后重新截图。工作区图片使用 `view_image`，其单图20 MiB限制与浏览器截图分别计算。

在浏览器工具或地址栏中输入当前会话工作目录内的 Windows 路径、`file://` 地址或相对文档路径时，会以本地文件预览，不会被强制改成 `http://`/`https://`。普通域名仍按网页打开，带空格的文本仍按搜索处理。为防止越权读取，本地预览只允许当前工作区内的文件；工作区外路径、网络共享、设备路径和不安全协议会被拒绝。

BrowserDo 是使用 Embiody 的独立 MCP 浏览器，不保证显示在内嵌侧栏，不共享个人 Chrome/Edge 配置。首次可能下载约百余 MB，适用独立 EULA，禁止未授权重新分发，因此不塞进 Mingshen 安装包。

密码、验证码、支付等由用户亲自处理，不应让模型记录或发送敏感登录信息。

## Agent 与项目检查

Mingshen 默认每轮用户任务允许最多 750 轮模型工具调用，并允许最后一次纯文本总结；继续发送新消息会开始新的运行计数，不累计整段历史。设置 → Agent 配置可为具体 Agent 调整“最大工具轮次”（1–10000），留空使用 750，已有明确自定义值继续保留。多工具同一模型回复按一轮计数，每个工具仍执行权限检查。上限不是任务完成保证，运行中始终可以停止。

Agent 配置默认同时适用于 CodeAgent 和 WorkAgent，并在编辑页显示 CodeAgent / WorkAgent 两个“适用模式”复选框。可以只保留其中一个适用模式，至少保留一个；从旧版本升级的配置默认继承两种模式。当前会话切换模式时，若当前配置不适用于目标模式，应用会选择已启用的兼容配置；没有兼容配置时拒绝切换，不会静默放宽权限或使用不匹配的提示。ChatAgent 固定不使用自定义 Agent 配置，也不显示该配置入口。

配置主 Agent、只读 Plan、Subagent 的提示、模型、工具、权限与轮数，消息开头 `@名称` 手动调用。子会话可单独查看并返回父会话，默认并发 3、最大 8，禁止继续创建下一层。

在设置 → Agent 配置中，角色为 `Subagent` 或“主 Agent + Subagent”的 profile 会显示“子 Agent 模型”。默认“使用主会话模型”；选择具体模型后，该 Agent 每次被 `@` 调用或被 `spawn_subagent` 委派时使用自己的模型。每个 profile 独立保存，切换主会话模型不会覆盖独立选择。主 Agent 和只读 Plan 不提供这个子任务覆盖；它们即使保留了旧配置字段，运行时也始终使用父会话模型。指定模型不可用时会明确报告配置错误，不会静默改用主会话模型。

主界面的 Agent 菜单显示简短用途，鼠标悬停可读当前 Agent 的说明；首次配置及新建会话提供全部已启用角色的可滚动介绍。基础四种角色中，Mingshen · 通用负责日常任务和改代码；Plan · 计划 · 只读负责分析与规划；General · 通用子任务处理可独立执行的多步骤任务；Explore · 探索 · 只读子任务用于检索文件和梳理结构。另有上文六种审查、排障与创作配置。子 Agent 通过 `@` 或主 Agent 委派使用，仍受并发与权限规则限制；自定义角色以实际配置为准。

新建会话的“执行 Agent”与聊天顶部菜单可选择全部已启用配置，包括十个内置 Agent 及用户自建 Agent。直接选择 Worker、General 或 Explore 创建的是独立会话；通过 `@` 或委派创建的才是父会话下的子任务。只读配置、并发上限及禁止子 Agent 递归规则不变。禁用项不显示，初始优先 Mingshen。说明区可滚动查看全部用途。

用户在设置中新建的 Agent 同样显示，不限于内置角色；主 Agent、Plan、Subagent 和“主 Agent + Subagent”类型都可直接选择。保存后立即出现在新建会话、聊天顶部菜单及用途说明中，名称和描述使用用户填写的内容。“在 @ 引用菜单中隐藏”仅影响 `@` 候选，不隐藏直接会话的选择入口；禁用的配置仍不显示。

主 Agent 会根据任务选择可独立推进的检索、实现或审查工作，调用 `spawn_subagent` 派出后台子任务，同时继续自己的独立工作，并用 `wait_subagents` 获取真实结果后汇总。SubAgent 没有固定 10 分钟总运行寿命，不会因累计时间达到十分钟而被强制中断；它持续运行到明确完成、失败、用户停止或父任务取消。单次模型请求、工具、命令、网络和具体服务超时仍然有效，不能把“无固定总寿命”理解成任何外部调用都不会超时。是否委派取决于模型判断和工具支持，不保证每条消息都会创建子 Agent。设置 → 运行与集成中的子 Agent 并发上限对整个应用生效，自动委派、手动 `@` 和已存在子会话的继续运行都共用限制，超额任务排队。只读 Plan 只能委派只读子 Agent。停止父任务会取消其关联子任务；共享目录下应避免同时修改同一文件。

可写的实际子任务可以通过 `request_verification` 排队最多6条项目根目录检查命令。它只登记待验证工作，不在子任务内执行；子任务结束后，`wait_subagents` 收集请求，当前模型轮的全部工具结果保存完毕，父会话再按自己的 profile、审批、隔离、计划与写入锁顺序执行，并保存独立的验证工具结果，保持调用与结果配对。父会话仍有运行中命令时，检查继续等待，须先轮询或停止这些命令。只读子任务不能申请此转交；子任务自己的命令工作区仍为只读，不因此获得可写 Shell 或额外授权。排队、拒绝或未执行的检查不得报告为通过。

设置 → 快照与轨迹可选择要查看的会话，展开其运行轨迹、回放步骤或导出；文件快照可恢复并通过安全快照撤销本次恢复。该页面在紧凑窗口中按可用宽度排列，长会话标题不会挤压说明文字。

自动发现用户、祖先目录与项目的 `AGENTS.md` 等指令。先检查项目 MCP、Hook、脚本再信任未知仓库。OpenCode/Mingshen 项目 JSON 与项目 Markdown Agent 只会在项目已信任后加载；项目配置通过 `{file:...}` 引入的提示文件使用工作区内受限读取，必须位于当前工作区且不能经过链接。项目 `build` 创建独立项目 Profile，不会覆盖内置主 Agent；撤销信任会清理对应项目来源。LSP/诊断也只能查询当前工作区内、经过路径边界检查的真实文件。

自动类型诊断只针对适用的现存代码或配置文件。普通 `.txt`、Office、PDF 等文档不会自动触发代码检查；显式配置对应文档语言服务器时除外。未配置适用检查器时自动跳过，不显示成功诊断记录；已配置诊断器的启动失败、命令缺失和真实检查失败继续显示。检查跳过或没有诊断时，不向模型发送要求修复的消息。请求批准和 Docker 模式仍禁止宿主机自动执行 Formatter/LSP，需要检查时通过已批准的隔离命令运行。

全访问宿主模式可检测并运行 Formatter/LSP。TypeScript 自带语言服务器，Python、Go、Rust、C/C++、Java、C# 等需有相应语言服务器或配置项目命令。可用性以检测为准。请求批准下检查应在容器内运行，不自动执行宿主脚本。

## 定时任务和托盘

选择已有会话、分钟周期和任务提示，仅应用存活时触发。请求批准下后台任务等待用户审批，全访问按授权前进。

叉掉窗口会问最小化到托盘或彻底退出，可记住选择，并显示正在运行的会话数（含准备发送、等待审批和运行中的子会话）及已启用定时任务数。托盘能打开软件、快捷 Chat 小窗口、进入最近五个未归档会话、彻底退出。设置中可重置关闭偏好。默认 `Ctrl+M` 切换快捷 Chat，窗口已显示时再次按下会收起；默认 `Ctrl+Alt+L` 切换主界面/托盘。两项均可在设置中录制并自定义，支持三个 `Ctrl`/`Shift`/`Alt` 修饰键加主键的三键或四键组合，同时保留上述默认二键组合；两项不可冲突，保存时实际注册，被占用或注册失败时保留原有效绑定并显示错误，也可恢复默认。快捷键未注册时仍可用托盘。退出后任务失效，不承诺关机或未启动应用时运行。

## 任务完成通知与快捷回复

### 识别刚完成的任务

后台会话完成一轮任务后，左侧会话显示绿色勾选和“已完成 · 未读”。工作文件夹折叠时，文件夹旁也会有未读圆点。Windows 任务栏应用图标显示数字，表示尚未查看的已完成会话数量；同一会话多次完成只计一个，角标超过 99 时显示 99。正在前台查看的会话完成后不增加未读数。任务失败或被停止不会被当作完成通知。

点击该会话，或重新聚焦正在显示该会话的窗口，标记和数字会清除。关闭再打开软件仍会保留未读记录。后台自动子 Agent 的完成结果由父会话汇总，避免父子任务重复弹出通知。

### 从 Windows 通知继续任务

完成时会发送 Windows 原生通知，默认显示会话标题和回答摘要。点击通知可回到原会话。在通知的回复框输入补充要求，再点击 Windows 提供的发送按钮，即可向原会话继续发送，沿用该会话的模型、工作目录和权限模式。需要审批的后续工具仍须批准，快捷回复不会扩大权限。

若通知收起，可在 Windows 通知中心查找；是否显示横幅、声音、锁屏内容和任务栏徽章取决于 Windows 通知设置、任务栏设置及勿扰状态，软件不修改这些系统设置。快捷回复需要软件仍在运行，包括最小化到托盘；不要在彻底退出后依赖通知恢复任务。

如果快捷回复未被接收，软件会打开原会话、保留失败原因并将文字合并到输入框现有草稿。多条失败回复在本地排队，保存合并内容后才确认处理，不重复追加；重启后仍可恢复。检查原因、修改后手动发送或主动清空即可。网络错误发生在消息已经接收、任务开始之后时，按普通聊天错误处理，不自动重复发送。

### 调整提醒

进入设置 → 外观的通知设置，可分别开启或关闭 Windows 原生通知、待审批通知、Agent 提问与修改冲突提醒、任务栏未读数字、标题与摘要预览、通知声音。Windows 原生通知是总开关；待审批与提问/冲突提醒各有独立开关，关闭其中一项不会关闭其他类型。提问与冲突提醒默认开启。关闭原生通知仍保留应用内未读标记、审批及提问面板。共享屏幕或处理敏感内容时建议关闭预览；关闭后只显示通用状态，不显示会话标题、问题或冲突内容。未读标记、设置和失败回复草稿均保存在本机，不新增云端通知服务。

### 从 Windows 通知批准或拒绝

会话等待人工审批时，如果软件没有前台显示这条会话（包括最小化、托盘或正在查看另一个会话），会发送待审批通知，提供“批准”和“拒绝”两个快捷按钮。正在前台查看的审批只显示软件内面板；之后切走或最小化，仍可收到一次提醒。自动审批模型正在审核时不重复弹窗；主备模型失败并转回手动处理时会通知。

“批准”只允许该通知对应的这一次操作，不记本会话规则、不切换完全访问；“拒绝”将拒绝结果和简短原因返回原会话，Agent 可据此调整。点击通知正文会打开对应会话查看完整参数，但不自动批准。需要本会话允许、完全访问、逐项核对完整命令或填写拒绝原因，请在软件内审批面板操作。通知仅展示限长摘要，不附带完整拟写文件内容。

在软件内处理、停止任务、请求取消或自动审核重新开始后，对应通知会清理；重复点击和旧通知不能决定后来的请求。快捷审批需要软件仍在运行，彻底退出再启动后旧审批通知不会自动恢复或执行。关闭通知、系统勿扰或通知失败不会放行操作，仍在原会话等待处理；发送/处理失败记入本地运行日志。系统通知界面采用 Windows 原生样式，随系统设置变化。

### Agent 提问与修改冲突提醒

需要你回答问题或处理多 Agent 文件修改冲突时，后台、托盘及非当前会话会发送 Windows 提醒。通知显示限长、脱敏后的会话标题与问题摘要；关闭预览后不显示这些内容。点击正文或“查看问题 / 处理冲突”打开准确会话，完整问题、选项与冲突处理仍使用软件内的日夜主题面板。提醒不会替你回答、批准操作或转交写入权。

已回答、取消、停止或删除会话后，旧通知不再关联有效请求；重复点击不能处理后来的问题。软件彻底退出后也不能依赖旧通知恢复任务。关闭提醒、收起横幅、系统勿扰或发送失败均不会使任务自动继续，仍可在原会话手动处理；通知错误写入本地运行日志。通知是否展示横幅或锁屏内容由 Windows 设置决定。

## 本地服务和数据

运行与集成可显式启动回环 API，仅 `127.0.0.1`，随机 Bearer Token。无头 API 创建会话沿用正常流程的供应商、模型、Profile、工作区和配置校验，不再绕过界面检查。不要分享管理 Token 或转发到公网。SDK/ACP 为实验集成，需按编辑器验证；同一 ACP 会话已有运行时拒绝并发 prompt，`run_failed`/`run_interrupted` 会结束当前请求，不再永久等待。`session/cancel` 的 abort 请求默认最多等待 10 秒；HTTP 失败、网络错误或超时会明确返回“远端停止未确认”并清理本地请求，而不是假报取消成功。只读分享链接限时有效，持有链接者可能读取会话。

本地存储不等于离线：所选模型、MCP、浏览器和下载源仍接收必要数据。凭据平台加密不能防御同一 Windows 账户已失陷。升级前退出应用并备份数据目录，不要把数据库或密钥提交仓库。

## 故障排查

### 导出运行日志

进入 **设置 → 运行日志 → 导出运行日志**，选择保存位置，得到可发送给开发者的 JSON 文件。建议同时附上问题发生时间、复现步骤和会话名称。日志按时间、模块、会话/运行/模型 ID 记录异常，包含网络与 HTTP 状态、模型列表及连接测试、审批主备失败与无效裁决、压缩主备失败、MCP、工具、更新/依赖和界面错误；即使备用模型恢复成功，主模型失败仍有记录。

日志仅写入当前用户数据目录的 `logs` 子目录，设置页显示实际路径。最多保留 30 天，五个轮换文件总计约 10 MiB；高频异常超过写入队列时会记录省略数量，避免日志阻塞任务。没有自动上传，导出不附带完整聊天、附件或源文件。密钥、鉴权头、Cookie 和已识别的模型输入字段会脱敏或省略，但第三方错误仍可能包含本地路径或其他敏感信息，分享前请检查。未导出的旧日志会按期限/容量清理；需要保留故障证据时及时导出。

| 现象 | 检查 |
| --- | --- |
| 401/403 | Key、模型权限、组织策略、IP 限制 |
| 404 | Base URL、协议、精确 Model ID |
| 429 | 限流、余额、并发和额度 |
| 502/503 | 上游异常，保留 Request ID，重试或联系供应商 |
| fetch failed | DNS、代理、TLS、网络及 cause |
| 工具未出现 | 模型工具能力、MCP 启用和测试、Plan 限制 |
| 命令报红 | 展开查看退出码与输出；退出码 0 的 stderr 提示正常显示，非零、超时或启动失败需处理；实际子任务的命令工作区只读，修改普通文件请使用受管文件工具 |
| 文本文件读取失败 | 检查路径和文件类型；支持 UTF-8 BOM 及带 BOM 的 UTF-16 LE/BE，目录用 `list_files`，Office/PDF 用 `read_document`；列举可直接指定单个文件 |
| 工具参数无效 | 查看 `TOOL_ARGUMENTS_INVALID` 的必填字段提示，按工具 schema 修正完整 JSON 参数；该调用未通过参数校验 |
| 项目记忆目录冲突 | 设置 → 项目指令与信任中选定工作区并明确保存记忆后端；保留两套目录，只启用所选方案。选中路径不是正常目录时需先修正该路径 |
| 上下文压缩未完成 | 展开压缩错误，检查所选供应商 Key、模型上下文、最大输出及思考设置；推理与正文共享输出额度，缩短恢复耗尽后仍保留原始消息和完整摘要，下一轮可重试 |
| 审批返回格式无效 | 查看脱敏回复预览、主备模型错误；明确裁决使用固定 JSON；双失败继续手动处理，不自动放行 |
| Docker 不可用 | 引擎、WSL2、虚拟化；不会宿主回退 |
| BrowserDo 未就绪 | 依赖状态、官方安装进度、下载与许可 |
| 无法快照 | 1 GiB/文件数限制、磁盘空间，先 Git 提交 |
| 项目脚本不执行 | 信任、权限和受保护模式限制 |
| 没有任务完成横幅或声音 | 软件内通知开关、Windows 应用通知与勿扰设置；应用内未读标记仍可使用 |
| 任务栏无数字 | 软件内任务栏未读数字开关及 Windows 任务栏徽章设置；已查看的任务不计数 |
| 通知回复没有继续 | 确认软件仍在运行，查看原会话报错及保留的输入框草稿，不要反复发送同一条通知 |

HTTP 错误显示状态、端点、请求 ID 和正文，尽量脱敏密钥，超大正文明确截断。分享前仍检查私人信息。

鉴权、策略及外部供应商错误仍会明确显示，需根据错误修正配置或联系服务商；不要反复重试永久错误或重放已执行工具来消除红色状态。

发生异常先停止任务、保留证据、审查 diff 与快照再恢复。安全反馈通过仓库公布的私密报告渠道，不要公开敏感内容。通过测试不表示不存在漏洞，也不代表企业安全认证。

## 给新用户的逐步操作

### 1. 准备模型账户

Mingshen Harness 是操作模型的桌面工具，不内置免费额度。你需要从自己选择的服务商获取三项信息：API 地址、API Key、模型的精确 Model ID。网页聊天订阅与 API 额度可能分别计费。请向供应商确认，不要把网页登录密码当 API Key。

### 2. 新建供应商

1. 点击设置，进入供应商页面，选择添加供应商。
2. 名称填便于区分的名字，例如“公司模型服务”。
3. Base URL 填服务商提供的 API 基础地址，通用地址以 `/v1` 结束；Gemini / DeepSeek 官方例外见“供应商提示缓存”。不要重复带 `/responses`、`/messages` 或 `/chat/completions`。
4. 选择服务商支持的协议。只支持 Messages 就选择 Anthropic；不要凭模型名称猜协议。
5. 按服务商要求选择鉴权方式。大多数 OpenAI 兼容服务使用 Bearer；如果对方要求 `x-api-key` 或自定义头，请相应设置。
6. 在 Key 专用输入框粘贴密钥，设置便于识别的标签并保存。不要把 Key 发到聊天中。
7. 同一个服务可继续添加其他账户 Key。删除 Key 前确认还有可用凭据；已隐藏的 Key 可替换，不能查看原值。

### 3. 添加模型并测试

1. 点击拉取模型；列表为空时可手动输入 Model ID。
2. 每个模型分别设置上下文长度与最大输出 token。上下文是一次请求可容纳的总信息量，输出上限是单次回答最多生成的量，两者不同。
3. 只勾选供应商实际支持的图片、音频、视频和工具调用能力。不确定时先启用文字与已确认的工具能力。
4. 思考等级按供应商文档填写，例如 `none,low,medium,high`。聊天滑条只显示这些等级。
5. 发送连接测试。测试会产生真实请求，成功时显示返回内容；失败时保留 HTTP 状态、请求 ID 和响应正文。401/403 优先检查 Key 与权限，404 检查协议、地址和模型。

### 4. 建立工作文件夹

“工作目录”是 Agent 处理的本地项目文件夹。推荐为每个项目单独建立目录，不要选择整个 C 盘、Windows 目录或存放全部凭据的个人主目录。

新建会话时选择工作目录。首次会出现信任提示；只信任来源明确并已检查的项目。左侧同一文件夹下可创建多个会话，点击文件夹名称折叠，点击旁边加号创建该文件夹的新会话。切换会话不会自动停止其他正在运行的任务。

### 5. 第一次让 Agent 修改文件

选择“请求批准”和“Windows 原生沙箱”，确认依赖检查通过。发送一项小任务，例如：

```text
请在当前工作目录创建 hello.txt，内容为 Hello Mingshen。
完成后读取该文件检查内容，不要改动其他文件。
```

看到审批时，核对工具名称、路径、命令与参数。单次允许只批准这一步；会话允许或限时允许扩大后续授权。拒绝时可填写原因，让 Agent 调整。允许后在聊天中展开文件 diff，点击文件名在右侧预览，核对实际内容。

如果原生隔离不可用，查看运行依赖详情。系统不符合条件时可在会话中选择 Docker，等待引擎启动；不要为了继续运行而盲目切换完全访问。

### 6. 理解执行过程

“正在思考”表示正在等待模型；“运行命令”表示执行工具；“等待批准”表示需要你的决定。展开命令查看完整命令、输出和退出码。退出码为零通常表示命令成功，但仍要核对输出。

修改统计在参数流入时逐步更新，最终以真实文件 diff 为准。最新一轮运行完成后仍可展开变更和命令；轨迹页可查看步骤摘要并导出。模型声称“已完成”不是验收依据，应核对文件、测试和实际运行结果。

运行中可停止任务、发送当前任务的补充引导，或把独立的后续任务加入“下一轮队列”。停止后已写入的文件不会自动撤回。编辑旧消息并重试会覆盖其后的对话历史，但不会自动把磁盘文件恢复到当时状态。

主界面 CodeAgent、WorkAgent、ChatAgent 及快捷 Chat 的模型任务运行时，可在输入区填写纯文字并点击“发送运行中补充”图标，或按 Enter；Shift+Enter 换行，输入法选字时不会发送。它不会取消当前模型回复、正在执行的工具或子任务；当前回复和工具批次结束后，补充信息按加入顺序接入同一次运行的后续模型请求。正在传输的请求不能中途改写，已开始的操作也不会撤回。状态显示“等待接入”“已接入”或“未应用”；已接入表示交给后续模型请求，不保证模型已经完成相应工作。手动压缩、独立 AutoDrive 和实际 SubAgent 会话不提供此入口。

引导只发送文字；有待发附件或临时指令时，请先处理这些内容，或使用下一轮队列。每条引导最多8,000字符，最多10条等待接入，同次运行的引导总量最多32,000字符。发送失败会保留草稿；发送期间后来输入的新文字不会被旧回执清空。停止、失败或重启后尚未接入的内容明确保留为未应用，不会自行变成新任务。引导沿用当前会话的权限、联网开关、审批、隔离及上下文压缩；正文中的斜杠命令或`@`引用按补充文字处理，不切换模型、模式或权限。

“下一轮队列”用于当前任务结束后的后续消息，可以包含附件。队列不重启正在执行的模型轮次；当前任务正常完成且后台清理结束后，最早加入的一项会自动开始下一轮，不需要逐项点击发送。

主界面的 CodeAgent、WorkAgent 与 ChatAgent 主会话都使用“下一轮队列”，每个会话最多保存 10 条待发消息，队列附件合计最多 50 MiB；单文件仍按 25 MiB 验证。消息严格按加入顺序发送，可编辑文字、整体替换附件或删除，但不支持上移、下移或插队。编辑开始时整个队列暂停；编辑期间若任务被停止或失败，保存或取消只结束编辑，队列仍暂停。附件替换失败时保留原附件快照并暂停队列，避免自动发送未经确认的旧内容。任务正常完成会自动发送首项；手动停止、运行失败、自动发送失败或应用重启时，队列保留并暂停，可通过队列栏显式恢复，或让同一会话后续一轮正常运行成功后自动从首项接续。等待审批时不会越过当前任务，也不会提前派发队列。Agent 模式、工作目录、Agent 配置、供应商、模型、权限、审批或执行环境与排队时不同会阻断整个队列，上一项派发状态未确认时也不会跳过首项；需要按提示处理或删除后重新加入。fork 不复制队列，删除会话会清理队列；快捷 Chat 和 SubAgent 不提供“下一轮队列”，也不能通过 IPC 绕过界面入队或继续。

### 7. 撤销不理想的修改

使用 Git 的项目，打开 Git 面板，先查看差异，再选择单文件或全部撤销。该操作会影响自己的未提交修改，操作前看清范围。软件保存撤销备份，可从恢复入口找回，HEAD 已变化时可能拒绝恢复旧暂存区。

没有 Git 时，使用运行快照查看与恢复。快照管理项目文件而非整盘，超过 1 GiB 或文件数量上限会明确提示，不能作为唯一备份。恢复前先检查快照时间和工作目录。

### 8. 加附件、技能与插件

输入框左下角加号提供附件、内置能力与已导入扩展入口。上传也可把文件拖进窗口；每条消息最多 10 个附件、单文件最多 25 MiB、合计最多 50 MiB。模型不支持的模态会提示或禁用。对于仅发送路径的文件，Agent 仍需要使用文件工具读取。

本地技能导入时选择包含 `SKILL.md` 的文件夹，或包含多个技能子文件夹的上级目录。导入后启用，并在输入框加号引用。市场选择 OpenAI 或 Composio 来源，翻页浏览，每页最多 20 个；下载后核查技能脚本和许可证。技能是说明和资源，不能越过你的权限设置。

### 9. 连接 GitHub

打开 GitHub 插件设置，默认 Client ID 已配置。点击浏览器授权，复制软件显示的短码，在 GitHub 官方设备授权页输入并确认。返回软件等待连接状态。OAuth 应用必须启用 Device Flow；组织可能要求管理员批准。仓库是否公开不决定 Device Flow 是否可用。

也可在专用输入框填写 PAT。获取地址为 https://github.com/settings/personal-access-tokens/new ，只授予所需仓库与权限。启用 GitHub MCP 后点击测试，再在会话中使用。撤销 GitHub 端授权后需要重新连接。

### 10. 添加自己的 MCP

进入 MCP 设置添加服务器。HTTP 服务填写 URL 与鉴权；stdio 服务填写命令、参数、目录、环境变量。API Key、Token 等敏感值放专用配置中。编辑时留空的已声明密钥会保留旧值，删除密钥名会删除对应秘密；未声明的额外秘密字段会被拒绝。OAuth token 请求不能跟随 HTTP 重定向，避免凭据被转发到另一来源。测试成功后启用。需要本地程序的服务器可能要求安装语言运行时或供应商依赖，不能仅凭“已启用”判断能执行。

Wikipedia 通常不需要 Key；Notion 需要 Token 与页面分享；Browserbase 需要账户信息；BrowserDo 需要 Embiody。请求批准模式会单独询问本地进程启动和工具调用。未知服务器和脚本不要批准。

### 11. 安排后台任务

在定时任务页选择会话、周期、提示并启用。先手动运行一次，确认模型和工具可用。关闭窗口时选择最小化到托盘，软件才能继续。请求批准任务会等待你处理审批。关机、彻底退出、未启动软件时任务不执行，也不会在下次打开后盲目补跑所有历史周期。

### 12. 更新软件与处理依赖

启动后及每 24 小时检查一次新版本，设置 → 关于可手动检查。1.2.6 起支持 ZIP 自动更新，发布者从 1.2.7 起提供 HTTPS ZIP 直链、ZIP 的 SHA-256 和大小。发现较新版本后选择“自动下载并安装”，软件会后台下载、校验并解压，随后退出并运行安装程序。可点击“后台继续”关闭弹窗，在顶栏更新入口或设置 → 关于查看实际进度、失败原因、重新下载或取消。未确认不下载，旧版下载网页仍可手动打开；缺少哈希时不会自动运行。

若还有主会话或子 Agent 运行，会显示等待数量，结束后才安装；审批等待也算运行中，可先完成/停止任务或取消更新。安装程序沿用正常 Windows 提示，不绕过 SmartScreen、管理员确认或组织策略，也不会自动重启电脑。ZIP 只能包含根目录下唯一、版本匹配的 `MingshenHarness-x.x.x-x64.exe`，大小上限 2 GiB；断网、取消、哈希不匹配或异常压缩包都不会执行。退出时取消未完成下载，下次需重新确认下载，不会后台静默续装。ZIP 包装不保证消除无签名程序的系统警告。`8.8.8` 等测试发布同样会触发版本提示，发布者应停用测试记录。

本地数据库升级永久包含在程序内，每次启动按 SQLite `user_version` 检查并逐级迁移，保留 schema 1–8 的全部历史步骤；无需导出再导入，也不根据版本名称清空数据。当前为 schema 9，新增 Code/Work/Chat 会话模式、聊天分组和 Agent 配置适用模式，保留既有供应商、模型、会话、原始消息、配置、归档、同意记录与凭据密文。每步事务失败回滚，不跳过失败步骤；新于当前程序的数据库会拒绝打开，不能降级覆盖。更新前仍建议退出应用并备份完整用户数据目录；更换 Windows 账户/电脑时加密凭据可能需要重新输入。

首次同意协议后会自动检查 Docker、WSL2 和 Embiody，缺失时启动官方安装，界面显示下载进度或错误。Windows 可能要求管理员确认、开启虚拟化或手动重启，软件不会自动重启。失败可在设置 → 运行与集成重试。已安装但不能运行时应查看详情，避免重复安装；Windows 组件和第三方软件不等于直接嵌入单个应用文件。

### 13. 隐私、迁移与反馈

会话、配置和快照默认保存在本机；发送任务会把必要内容传给你选的模型，网页和 MCP 也有各自网络请求。不要上传无权分享的资料。API Key 在本地加密保存，但无法防御已经控制当前 Windows 账户的攻击者。

导出会话可选择 Markdown 或 JSON。分享或提交日志前检查内容和凭据。迁移整个数据目录前退出应用并备份；Windows 加密凭据可能不能在另一台电脑直接解密，需要重新输入。

遇到问题，记录操作步骤、错误时间、HTTP 状态或工具退出码，在项目仓库反馈。不要公开密钥、私人代码或完整敏感日志。

## Token Saver 内置插件

### 开启与调整

进入 **设置 → Skills 与插件 → Token Saver**，也可搜索“Token Saver”或“节省”。这是随应用提供的本地功能，不需要下载安装扩展。修改后点击“保存 Token Saver”，请求精简与回复规则从下一次模型请求生效，系统提示模块从下一轮用户对话重新加载；关闭总开关即可停止新增精简。不会删除或重写原始消息，不改变审批、沙箱、文件权限、工具调用顺序或失败处理。

新配置默认保留最近 **5 轮**原文、**关闭按轮次提前摘要**，回复档位为“自动”；升级不会改写已有明确选择。一轮从用户消息开始，到下一条用户消息前结束。主动开启提前摘要后，达到 **12 轮总阈值**且待摘要部分至少 **2048 估算 tokens**，才调用现有上下文压缩模型生成结构化续接摘要；可以调整三项限制，触发轮数必须大于保留轮数。阈值按可见文字和有界媒体估算，不把 base64 或供应商不透明状态逐字符当作普通文字。摘要保留目标、决定、偏好、安全约束、错误、未完成工作与原消息标识，但仍是有损处理，请核对重要事实。

按轮次摘要和 **85% 窗口保护**并存。压力保护必要时会纳入更近的完整历史，以免超出窗口；停止、主备模型失败、空摘要或未缩小上下文时，仍沿用原失败与保留原文规则。已有摘要不会因关闭插件自动撤销，原消息仍可查看和召回。摘要调用会增加用量，短会话未必净节省。

### 供应商提示缓存

选择 Google Gemini 原生协议时，模型体系固定为 Gemini，Base URL 使用 `/v1beta`（或网关支持的 `/v1`），自动采用隐式缓存。以下官方兼容地址的识别规则继续适用于其他协议。

供应商可复用之前请求中完全相同的前缀，减少重复输入的处理成本；这与本地读取结果去重不同。Mingshen 保持固定系统规则和工具定义顺序，把计划、记忆、权限、诊断及按需代码提示等变化按时间追加为宿主状态，不把新的随机运行标识放进系统提示。最新状态优先，实际审批、隔离和计划版本检查始终由执行层核验，历史状态不会授予权限。

Token Saver 会保留已经发送过的历史请求表示。最近五轮窗口向前移动、新问题改变相关性或再次出现重复内容时，不会回头精简或改写这些已发送消息；新历史按当前策略处理。更改插件配置、改写历史、切换模型/工具或生成新摘要时，可以重新建立前缀，首次请求的命中率下降属于预期取舍。原始消息与原文召回保留，界面的“最近请求精简估算”不等于供应商缓存率。

用于复用的源消息哈希、精简替换片段及按时间追加的宿主状态快照保存在本地数据库。快照包括当时使用的计划、记忆片段和诊断，可随后续请求作为旧历史发送；最新状态优先但不会擦除历史文字。回退改写或删除会话会清理对应快照和请求表示，已有原消息及摘要按各自规则保留。关闭自动记忆只阻止新增自动注入，不清除先前发送的聊天内容。

新建供应商时即可选择模型体系和缓存方式；已有供应商打开 **设置 → 供应商与模型 → 选择供应商 → 连接 → 提示缓存**。按供应商文档选择，点击“保存缓存配置”，从下一次运行生效：

- **供应商模型体系**：可选 OpenAI、Claude、Gemini、DeepSeek 或“其他或混合模型”。自动识别按完整官方地址及协议匹配，不凭供应商名称或模型 ID 猜测。除原有 OpenAI / Claude 官方 `/v1` 地址外，新增 Gemini Chat Completions 的 `https://generativelanguage.googleapis.com/v1beta/openai`，以及 DeepSeek Chat Completions 的 `https://api.deepseek.com`、`/v1`、`/beta`，Responses 的根地址或 `/v1`，Anthropic Messages 的 `https://api.deepseek.com/anthropic/v1`。地址末尾可带 `/`；未知网关需手动指定体系，并确认它透传相应原生字段。体系不会切换模型、翻译协议或证明网关兼容；混用模型建议拆成独立供应商。
- **不发送缓存参数**：省略客户端缓存提示，不会关闭供应商自身隐式缓存。
- **OpenAI 兼容缓存键**：仅在网关明确支持 `prompt_cache_key` 时选择；同一会话使用稳定不透明键，不发送会话正文作为键。
- **Claude 自动缓存 / 显式缓存断点**：供应商与已配置模型须支持对应方式。固定工具、系统、有效摘要前缀和动态历史共同使用最多4个标记；显式方式不发送顶层自动标记。默认5分钟，可主动选1小时，但需要支持且缓存写入可能更贵。

**Gemini / DeepSeek 推荐使用“自动”缓存方式。** 二者依赖服务端隐式前缀缓存，应用保持系统、工具和已发送历史稳定，不自动添加 OpenAI 缓存键或 Claude 断点，也不创建有存储费用的 Gemini 显式缓存资源。缓存方式中的 Claude 保留时间不控制二者的服务端有效期；使用网关前按其文档确认能力。

1.3.2 同时保留工具续接所需的原生响应：Gemini 原生 Part 及签名、Chat Completions 消息/工具签名，DeepSeek 的 Chat `reasoning_content`、Responses 明文 reasoning 项和 Anthropic thinking 内容块。只保存 API 实际返回且通过格式、容量和完成状态校验的内容；工具顺序不变，不把聊天界面的思考文字补造成原生状态。续接须匹配原供应商配置、模型、协议、端点及鉴权方式，并核对可见正文及工具标识、参数和顺序；切换或编辑后不匹配的状态不重放。Token Saver 不精简或去重这些消息，独立文本摘要不透传 `provider_state` 或不透明签名。DeepSeek 返回的明文推理、Gemini 返回的思考摘要及不透明签名随会话本地保存，不属于凭据加密，数据处理范围见[隐私政策](PRIVACY_POLICY.md)。

DeepSeek Chat 在选择思考等级时显式发送开关：`none` 关闭，其余已配置启用等级开启并发送 effort；Responses 使用 `reasoning.effort`，Anthropic 使用 thinking / effort。未选择等级时不强制覆盖服务端默认行为。当前官方文档规定 Chat 中 `thinking` 优先于 `reasoning_effort`，省略或为 null 时按 effort 判断，二者都省略时默认启用；请以所用模型和网关的最新文档为准。不要仅为追求缓存命中改变任务所需的思考等级。

升级不会为旧历史补造缺失的签名或推理状态，旧会话不一定立即改善；可在相同配置的新会话中，连续进行包含真实工具续接的请求，再到 CTX → Token Saver 对照缓存读取、报告覆盖及前缀诊断。无缓存字段表示未知，明确返回 0 才表示零命中。实际最低长度、有效期和服务端路由由各模型决定，不在软件中写死，也不保证固定命中率。研究依据和协议范围见仓库内的[供应商缓存适配说明](PROVIDER_CACHING.md)。

不支持的参数可能导致请求失败，遇到参数错误请依据供应商文档改回自动识别或不发送参数；软件不会隐瞒错误、自动猜测网关能力。实际命中受最小缓存长度、有效期、路由和模型/配置变化影响。相同 API Key 并不保证不同客户端达到相同命中率，本软件不承诺90%或固定账单节省。

同供应商/同模型压缩时，优先复用本进程最近实际发送的纯文本请求前缀，保留系统、工具及推理配置，追加专用摘要指令与可召回的原消息索引，并禁用工具选择。历史、配置、完整工具边界、脱敏和窗口检查均须通过；重启、缺少/超大快照、任何附件或带图工具结果、独立/备用模型及不兼容输入仍走原分段摘要。网关明确以400/422拒绝工具选择或思考等复用参数时，可受控改用同模型原分段路径；认证错误、取消和模型返回工具调用不走此兼容重试。摘要仍产生用量，压缩后的续接也形成新前缀，不保证摘要命中。最多保留8个会话快照，按序列化大小合计限2 MiB，仅用于内存，不额外写入完整聊天磁盘副本；不等于整个进程堆内存上限。

**使用独立低价压缩模型时：**主会话固定系统规则和工具不会换成压缩模型的提示。第一次压缩建立摘要基线；后续优先只总结新增的旧历史，较早摘要按原文、顺序和标识保留，新摘要追加在其后。较早摘要只给压缩模型作参考，新分段应记录变化和完成结果而不重抄旧结论；主模型按时间采用最新进度，用户约束仍保留。Token Saver 只重建首次变化后的历史表示，不重写仍匹配的连续前缀。

摘要最多8段，合并摘要的估算总预算不超过当前主会话模型窗口的15%，追加前预留本次摘要和安全余量；每次生成另受压缩模型的配置输出上限与可用上下文限制，小窗口还会预留历史输入和滚动摘要空间，推理与正文共用生成额度。达到段数/预算、压缩模型窗口不足或发现需重新脱敏的凭据时，合并生成新基线。输出耗尽时按上述规则要求更简短摘要并缩小历史片段；异常超长返回、无效结果、非缩小摘要或取消不会替换上次完整摘要，备用模型从原始待压缩历史和完整旧摘要重做。段落随现有摘要保存在本地，重启、分支仍可使用，原始消息不删除。

这能保留较早摘要的缓存机会，但主模型与压缩模型的缓存相互独立；不同模型不能共享缓存命中。被替换的原始历史及其后续仍会失去相应前缀，合并基线也会重建摘要部分。缓存还取决于供应商有效期、最小长度和路由；不要为追求命中率无限保留旧历史。活动区会说明追加分段或重建基线；CTX → Token Saver 查看主会话/压缩各自的已报告用量与前缀诊断。

### 精简策略与回复

- 默认开启精确重复内容引用与结构化精简，仅处理较早历史。JSON 不改字符串、数值字面量；YAML 仅在可安全转换时精简，有注释、别名、标签、特殊键或不安全数值时保留原文。
- 默认精简运行时 JSON，按任务选择代码提示；核心、安全、权限、工具定义、用户/项目指令、已引用技能内容保持。不是通过删除安全规则省 tokens。
- 回复支持极简、自动、标准、详细，新配置默认自动，按任务复杂度提供完整工作与验证证据；已有明确档位保留。用户明确要求完整/详细时优先，代码、文档交付和工具参数不能为简短而截断。合适时使用表格、列表、差异或有效引用，不强行把所有内容变成表格。
- “高级摘录”默认关闭，可分别启用较早低相关助手解释、助手长 JS/TS 代码的 AST 提纲、成功工具长结果的首尾摘录。它们可能遗漏细节，原文引用会提示模型先调用 `recall_context`；未提供召回能力时不进行这些摘录。近期轮次、用户约束、错误与工具调用/结果配对受到保护。
- 含原生 Responses / Gemini / DeepSeek 状态或带图工具结果的消息保持完整，不做可见文字的结构化精简、摘录或去重，避免改变原生状态重放与图像证据。对应源哈希包含状态作用域和图像内容摘要，不在替换记录中另存不透明状态或图像字节。

代码任务优先使用已有的代码索引/符号查询、函数或行范围、现有 diff 和报错周围内容；不够时仍须读取源码。已经确定的 2–8 步工具动作可使用受控执行链；每步仍分别审批、隔离和检查，不自动合并未知命令，也不缓存重放修改副作用。

### 用量、记录与原文

点击输入区 **CTX → Token Saver**，或在插件设置查看当前会话：

- “累计已报告用量”从此功能加入后累计，包括对话/工具推理、压缩、模型审批、项目记忆摘要、标题生成，以及失败/重试中实际返回的用量。未报告/部分报告另列，未报告部分不补估算，不能代替供应商账单。
- 缓存读取与写入显示供应商明确返回的 token 数及报告覆盖范围。命中率为有有效缓存读取报告的请求中“缓存读取 token / 输入 token”，不混入未报告缓存的请求；明确返回 0 才视为零命中。没有报告时显示未知，旧记录也不会凭估算补成零。缓存写入单列，收费规则由供应商决定；缓存读取和写入仍占用模型上下文，CTX 不扣除这些 token。
- 1.3.2 兼容 DeepSeek 的缓存命中/未命中计数，以及 Gemini 原生接口或网关透传的 `usageMetadata` / `usage_metadata` 与缓存计数字段；有效标准 usage 优先，明确的 0 不被原生备用值覆盖，冲突或无效字段不拼成命中报告。Gemini 原生输出计数在有报告时包含思考 token，不把缓存命中重复加到完整输入中；不保证每个网关都返回这些字段。
- “最近请求精简估算”比较同一请求在相同提示、工具下，精简前后的输入 token 估算。百分比不是未使用插件的真实计费对照，不包含全部提示裁剪收益，也不抵扣摘要的额外开销；没有安全精简机会时可以为零。
- “缓存前缀诊断”比较同会话同用途最近实际请求：首次观察、重启、供应商/协议/地址/模型/认证变化、工具或系统变化、历史改写/截短、仅追加或一致。生成参数与缓存策略单独提示，移动断点不等于改写正文。历史块不是tokens，最多细比2048块；超限无法确认时明确提示。结构一致不证明缓存未过期或路由相同，未报告不代表零命中。
- “最近请求优化记录”显示策略、估算前后值并可查看原文。原文只读、按段翻页，包括超过 16,000 字符的单行；模型仅可召回当前会话原文，不访问其他会话、工作区或绕过权限。最新请求记录最多展开 100 项，更多项给出数量。
