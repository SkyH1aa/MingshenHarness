# MingshenHarness 桌宠图生视频完整指令集

日期：2026-11-21。版本保持 1.3.5。面向现有黑发、水青色科技服饰桌宠，提供 36 段动作视频的制作指令及对应交互方案。

本文保留 36 段动作的视频制作指令，供重新生成和修订素材参考。当前版本已接入用户提供视频处理后的内置动作播放器和右键菜单，实际状态与限制见[桌宠动画说明](COMPANION_ANIMATIONS_1.3.5.md)。这里的文件名是素材交接约定，不是应用支持的视频包自动导入协议。

## 1. 按这个顺序开始

1. 用原图准备并认可一张标准正面母图，保留角色原有画风。不要在每个动作中重新设计角色。
2. 先生成 `idle_breathe`、`greet_wave`、`pat` 三段试片，检查脸、手、衣服、背景和画幅是否稳定。
3. 三段过关后，完成思考三段、工作三段、等待、成功、异常，得到第一批 12 段素材。
4. 再做睡眠三段、拖动三段，最后补行走和其他互动。完整目标为 36 段，不要求一次全部生成。
5. 每次图生视频只提交一个动作：**标准母图/动作锚点图 + 通用提示词 + 对应动作提示词 + 负面提示词**。
6. 保留原始视频。最终再统一抠像、配准、裁段和编码；不要只保存 GIF，也不要逐帧自动裁边。

不需要让模型生成八宫格或把全部动作装在一段视频中。此前的[序列帧素材指南](COMPANION_ANIMATION_ASSET_GUIDE_1.3.5.md)保留；本手册是直接生成连续视频的路线，两者的源帧率和切段方式不要混用。

## 2. 所有动作共用的规格

| 项目 | 统一要求 |
| --- | --- |
| 参考角色 | 原图的脸型、年龄观感、头身比例、黑灰短发、水青色挑染与眼睛、非对称发饰、黑白外套、胸前圆形装置、手套、腰带挂件、宽松裤装和鞋子 |
| 画幅 | 优先全部 1024×1024、1:1；工具不支持时，一开始选定同一种原生画幅，整批保持一致，并预留统一方形安全区域 |
| 帧率 | 源视频优先 24 fps；平台只有 30 fps 时整批统一 30 fps，不反复插帧变速 |
| 时长 | 默认按 5 秒源视频写；动作段明确标注 6 秒时以该段为准。平台只有其他档位时，按比例放慢节奏、留足停顿，后期裁段，不强行倍速压短 |
| 镜头 | 固定全身镜头，固定光照、透视与角色大小；不能运镜、放大脸部或自动追踪 |
| 位置 | 方形母版站姿脚底中点约 `(512, 900)`、头顶约 `y=160`；四周至少 64px 安全余量。跳跃/抬手需要的空间事先留好 |
| 运动 | 原地完成动作；行走素材也在原地踏步。桌面平移、鼠标拖动由程序控制 |
| 单次动作 | 通常前 0.5 秒、后 0.5 秒保持可衔接姿态，动作在中间完成；不要每段结尾重新变脸 |
| 循环动作 | 从已经进入状态的姿态开始，首尾姿势、道具、运动相位与速度应能衔接；不把进入/退出动作做进每一轮 |
| 音频 | 不需要配乐、语音或音效；保留安静的视觉素材 |

这些坐标是母版配准目标，不代表生成工具会精确服从。用实际画面核对；角色位置明显漂移时重做，不逐帧缩放掩盖。坐姿降低身体高度，不能把坐姿放大成站姿高度。悬空动作使用胸腹锚点，不能每帧按脚底贴齐地面。

### 背景和透明度

多数图生视频平台输出普通 MP4，不能只凭“透明背景”四个字得到真正 Alpha。支持真实 Alpha 时直接保留；不支持时建议先试 **纯洋红 `#FF00FF`** 背景，整批采用同一颜色，后期用抠像或分割蒙版处理。

本角色有黑白服装及青色细节，黑幕、白幕、蓝幕或青色幕都容易误删角色；绿幕也要检查青色发梢。洋红只是一种候选，若出现明显染边应改用分割蒙版并修边，不能以牺牲服装颜色换透明。不要生成棋盘格、地板、阴影或背景反射。真正透明以文件 Alpha 和实际叠在浅色/深色桌面上的效果为准。

可交付透明 PNG 序列或经实际测试可在 Electron 中正确显示 Alpha 的 WebM；原始 MP4 同时保留。GIF 只用于预览。新素材仍需统一画布、缩放与内容锚点，并检查与现有视频播放区域的匹配。

## 3. 标准母图和动作锚点

### 3.1 先生成标准正面母图

上传已有桌宠参考图，使用下面的生图指令。已有合格的全身抠图也可以直接配准成母版，不必重画一次。

```text
以我上传的图片为唯一角色身份参考，制作同一角色的桌宠动画标准母图。

严格保留原角色脸型、年龄观感、原有头身比例、黑灰短发、水青色挑染与眼睛、非对称发饰及所在身体侧别。保留原有黑白科技外套、胸前水青色圆形装置、手套、腰带及挂件、宽松黑裤、鞋子与全部服饰配色。保持原来的精致二次元插画风格，不进一步幼态化，不转写实、三维或像素风，不重新设计服装。

角色全身自然站立，面向与原图一致，目光温和看向观看者。双臂自然下垂，肩膀放松，双手结构清楚，鞋底与发梢完整。画面只有一个角色。固定柔和光照，无场景、地板、投影、文字、图标、气泡、水印或大面积发光特效。

使用 1024×1024 方形画布。脚底接地中点约在 x=512、y=900，头顶约在 y=160。固定人物大小，为抬手与小跳预留空间，不裁切身体。输出真正透明 PNG；如工具不支持透明，改用均匀纯洋红 #FF00FF 背景，不能画棋盘格，背景颜色不能染到头发、衣服或轮廓上。
```

### 3.2 认可八张锚点参考图

先锁定 `FRONT`，其余可由母图生成，或从已通过的动作视频中提取清楚的实际画面。一个锚点只保留一个认可版本。平台支持首尾帧控制时，把这些实际图片放进相应首尾帧位置；不支持时作为参考上传，并通过反复试片选择最接近的片段。

| 锚点 | 文件 | 姿态与约束 |
| --- | --- | --- |
| FRONT | `reference-front.png` | 标准站姿、双臂放松、目光朝前；大多数单次动作从这里出发并返回 |
| THINK | `reference-think.png` | 同尺度、同地面，角色右手轻托下巴、头基本端正；思考进出与循环共用 |
| WORK | `reference-work.png` | 同尺度站姿，左前臂抬于胸腹前，右手食指停在原有左腕水青色装置附近；不新增屏幕、平板或文字 |
| SLEEP | `reference-sleep.png` | 在同一地面线自然盘坐，双手放腿上、闭眼微低头；坐姿实际变矮，不放大 |
| AIR | `reference-air.png` | 相对 FRONT 抬高约 40–60px，膝盖放松、双臂略张开、双脚自然悬空；用胸腹位置配准 |
| LEFT | `reference-left.png` | 身体朝画面左侧的认可侧面步态连接姿势，双脚处于双支撑相位；服装左右身体侧别正确 |
| RIGHT | `reference-right.png` | 身体朝画面右侧、与 LEFT 独立生成的连接姿势；不能水平镜像改变挂件侧别 |
| BOOK | `reference-book.png` | 正面站姿，双手持同一本小型深灰封面无字笔记本，目光微向下；书本大小、封面固定 |

锚点补图通用指令：

```text
使用已认可的 FRONT 标准母图锁定角色身份、画风、画布、尺度、地面线与光照，只改变为下述目标姿势：[粘贴表格中的姿态与约束]。这是后续动作视频的固定连接帧，不做场景插画。保持全身可见、服装非对称细节的身体侧别不变。除目标姿势明确需要的小型道具外，不添加物件。背景与母图一致。输出单张同尺寸 PNG。
```

不要只用一句“回到原姿势”来判断连接成功。必须把实际末帧和下一段首帧叠加核对。循环中途退出也需要调度到连接相位或制作短过渡；仅做交叉淡化可能出现两张脸、两只手，不能保证自然。

## 4. 每次图生视频都粘贴的通用指令

下面的通用指令与第 5 节的一条动作指令组合使用。若平台有单独的负面提示词输入框，将负面约束放入该框；没有就接在正文后。

```text
以我上传的标准母图锁定唯一角色身份，以本次动作的首尾锚点图锁定姿态。制作一段用于透明桌面宠物的全身动作视频，只执行我在“本次动作”里写出的一个动作。

严格保留原角色的脸、年龄观感、头身比例、黑灰短发、水青色挑染与眼睛、非对称发饰、黑白科技外套、胸前水青色圆形装置、手套、腰带挂件、宽松裤装和鞋子。沿用原来的二次元插画质感，不重新设计角色。发饰与挂件保持各自所在身体侧别，转身只产生合理遮挡，不镜像服饰。

固定全身镜头、光照、画布与人物尺度，优先 1024×1024、24fps，默认源时长 5 秒；动作段明确标注 6 秒时采用 6 秒。人物始终完整位于画面安全区内，不运镜、不推拉、不裁切。站姿脚底中点约在 (512,900)，头顶约 y=160；坐下、悬空和跳跃按动作说明改变高度，不通过放大缩小整个人模拟动作。除跳跃、拖起、落地外，脚掌接地时地面线固定。

身体按关节真实运动，手脚结构稳定，衣角、头发和挂件只做轻微自然跟随，不把整张立绘左右摆动或弹性拉伸当作身体动画。原地完成动作，不让角色在画面中横向走出位置。道具造型、位置与遮挡连续，不能突然出现、消失或融入手掌。

如果是单次动作，前后各保留约 0.5 秒的连接姿态，动作有准备、执行、缓冲、归位；如果是循环动作，从已经进入状态的姿态开始，结尾回到同一动作相位和可衔接的运动速度，不重复进场退场。循环是否自然以实际首尾画面为准。

背景优先真实 Alpha；平台不支持时，整段固定均匀纯洋红 #FF00FF，不画棋盘格、场景、地面、投影或色彩反射。只保留角色和动作明确需要的小型道具。不生成文字、台词气泡、菜单、软件界面、百分比、水印、音乐或旁白。
```

共用负面提示词：

```text
变脸，换发型，改变年龄与头身比例，换衣服，服装细节漂移，发饰和挂件左右反转，多人，多余四肢，多余手指，手指融合，关节反折，站立时脚底无故漂移，行走时步态紊乱，手掌忽大忽小，身体橡皮拉伸，整张图片平移缩放冒充动画，轮廓抖动，画面闪烁，突然变色，道具闪现或消失，穿模，裁切头发和手脚，镜头运动，特写，背景场景，透视地板，地面投影，棋盘格，背景染边，巨大光晕，激光，粒子遮脸，运动残影，运动模糊，字幕，文字，水印，用户手掌，鼠标，右键菜单，按钮。
```

## 5. 36 段动作的独立提示词

每个代码块都是接在通用指令后的“本次动作”。文件名暂按普通源 MP4 举例；真正带 Alpha 的源文件保留实际格式和编码，用同一动作 ID 加真实扩展名，例如 `idle_breathe.webm` 或 `idle_breathe.mov`，不改后缀冒充 MP4，也不为了命名丢掉 Alpha。

### A. 日常与互动：10 段

#### 01. 待机呼吸 `idle_breathe.mp4`

类型：循环；FRONT → FRONT。默认站姿素材。

```text
本次动作：安静自然的待机呼吸循环。整段从 FRONT 站姿开始，不做入场或挥手。
0–2 秒：缓慢吸气，变化集中在胸肩和衣领，幅度很小，头部与双脚稳定。
2–4 秒：缓慢呼气，发梢和衣角轻微跟随；期间只做一次自然眨眼，不连续眨动。
4–5 秒：回到起始呼吸相位，肩膀、表情、衣角和头发位置接近首帧，形成平顺循环。
保持聪明、安静、亲近的气质，不整个人上下漂浮，不用全图等比例缩放模拟呼吸。末帧与首帧的呼吸方向应连续。
```

#### 02. 看看周围 `look_around.mp4`

类型：单次；FRONT → FRONT。随机小动作或菜单触发。

```text
本次动作：好奇但克制地看看周围。0–0.5 秒保持 FRONT；0.5–1.8 秒先让眼睛看向画面左侧，再带动头部小幅转动，肩膀不跟着大幅转身；1.8–3.2 秒目光缓缓经过正面看向右侧；3.2–4.5 秒头部和目光回正；4.5–5 秒恢复 FRONT。
只转头约十几度，保留双眼与原来脸型，不突然出现完全不同的侧脸。双臂自然下垂，双脚不移位，不产生问号或搜寻界面。
```

#### 03. 挥手招呼 `greet_wave.mp4`

类型：单次；FRONT → FRONT。开启桌宠、打招呼。

```text
本次动作：温和地向用户打招呼。0–0.5 秒保持 FRONT；0.5–1.5 秒角色自己的右前臂抬到脸旁，掌心朝向观看者；1.5–3 秒手腕小幅来回挥两次，肘部稳定，配合自然微笑；3–4.5 秒手臂平缓放下、表情收回温和状态；4.5–5 秒回到 FRONT。
手掌不遮住整张脸，五指结构清楚，不把左右手换来换去，不做大幅摇摆。衣袖自然跟随抬手，不改变袖口或手套设计。
```

#### 04. 轻轻点头 `nod.mp4`

类型：单次；FRONT → FRONT。认可、回应。

```text
本次动作：认真听到要求后轻点头确认。0–0.5 秒保持 FRONT；0.5–1.5 秒眼神专注、头部缓缓低下少许；1.5–2.5 秒自然抬回，完成一次清晰的小幅点头；2.5–4.5 秒维持温和目光、轻微呼气并归位；4.5–5 秒恢复 FRONT。
颈部自然运动，不把脸压扁，不连续鞠躬，不增加对勾、文字牌或字幕。此动作只表达回应，不显示任务完成结果。
```

#### 05. 轻轻摇头 `shake_head.mp4`

类型：单次；FRONT → FRONT。轻度否定的动作预览。

```text
本次动作：温和地小幅摇头一次。0–0.5 秒保持 FRONT；0.5–1.5 秒头部向一侧轻转；1.5–2.5 秒缓缓转到另一侧；2.5–4.5 秒回到正面、表情恢复；4.5–5 秒保持 FRONT。
幅度克制，嘴角平和，不能变成生气、嘲讽或责备。身体、肩膀和脚底稳定，不做快速左右抖动，不加红叉或气泡。
```

#### 06. 被摸头回应 `pat.mp4`

类型：单次；FRONT → FRONT。轻拍互动。

```text
本次动作：感受到轻轻摸头后的回应，画面中不出现用户的手。0–0.5 秒保持 FRONT；0.5–1.5 秒头部略微低下、肩膀放松；1.5–3 秒闭眼露出安心微笑，发梢有极轻微弹性跟随；3–4.5 秒抬头睁眼、回到原姿态；4.5–5 秒保持 FRONT。
不要把头骨压扁、脸型变圆或全身弹性缩放。手臂自然放松，不添加爱心、文字或外来手掌，动作细腻且有明确归位。
```

#### 07. 伸展放松 `stretch.mp4`

类型：单次；FRONT → FRONT。休息提醒。

```text
本次动作：站着做一次轻松伸展。0–0.5 秒保持 FRONT；0.5–1.8 秒双臂缓缓抬起、肘部自然弯曲；1.8–2.8 秒在预留头顶空间内向上舒展，身体略微拉直，双脚仍接地；2.8–4.5 秒缓慢放下手臂、肩膀松开；4.5–5 秒恢复 FRONT。
双手、发梢和手肘不能出画。不要把躯干拉长或衣服拉成橡皮，不弯折手腕，不生成椅子或健身器械。
```

#### 08. 小幅律动 `dance.mp4`

类型：单次；FRONT → FRONT。菜单娱乐互动，不作为工作状态循环。

```text
本次动作：一次克制、轻快的小舞步。0–0.5 秒保持 FRONT；0.5–1.5 秒略向一侧重心转移，同侧前臂小幅抬起；1.5–2.5 秒向另一侧换重心，手臂自然呼应；2.5–3.5 秒原地轻踏两小步，不横向位移；3.5–4.5 秒双脚与手臂回位；4.5–5 秒保持 FRONT。
保持角色原有气质和身体比例，幅度小、节奏清楚，不旋转背对镜头、不甩头、不大幅跳跃，不添加舞台、灯球、音符或音乐。
```

#### 09. 小跳一下 `jump.mp4`

类型：单次；FRONT → FRONT。主动互动。

```text
本次动作：原地开心地轻跳一次。0–0.5 秒保持 FRONT；0.5–1.3 秒轻屈膝蓄力、手臂自然配合；1.3–2.2 秒双脚短暂离地，整体上升不超过预留安全范围，衣摆略滞后；2.2–3 秒回到原接地点，双膝轻弯缓冲；3–4.5 秒站直、衣角归位；4.5–5 秒恢复 FRONT。
地面线始终是 y=900 附近，跳起可以离开地面但不能移动地面。头发与双手不出画，不飞行、不翻跟头、不生成冲击环和灰尘。
```

#### 10. 喝一口水 `drink.mp4`

类型：单次；FRONT → FRONT。可选复杂道具动作，先确认原有侧袋能容纳小杯，并认可取出、持杯、收回三个关键画面；不能通过改变衣服来补一个储物空间。

```text

本次动作：已经捧书的安静阅读循环，首帧直接采用 BOOK。0–2 秒眼神沿页面小幅移动，胸肩轻微呼吸；2–3.5 秒自然眨眼，头部略低一点；3.5–5 秒目光和头部回到 BOOK 的起始位置，形成可循环相位。
双手稳定持同一本书，书页不翻动，以便首尾严格接回。不要每轮打开合上，不改变书本厚度或产生乱码；不因阅读而改变服装、脸部比例和地面位置。
```

#### 36. 合上笔记回位 `read_exit.mp4`

类型：过渡；BOOK → FRONT。

```text
本次动作：从 BOOK 结束阅读回到 FRONT。0–0.5 秒保持 BOOK；0.5–1.5 秒目光抬向用户；1.5–3 秒双手轻合书本并沿取出路径放回原侧面裤袋的遮挡处；3–4.5 秒双手自然下垂、肩膀归位；4.5–5 秒保持 FRONT。
书本大小和款式全程相同，合书与收纳连续，不能凭空消失、变成平板或给衣服增加新口袋。最后头发、衣角、双脚和面部表情与 FRONT 相符。
```

## 6. 早期右键菜单与素材对应建议

下表是素材设计时的建议，不是当前菜单的完整功能清单。实际支持的操作以[桌宠动画说明](COMPANION_ANIMATIONS_1.3.5.md)和应用界面为准，不能由此推断已支持自动漫游、鼠标穿透或外部素材包导入。按钮、文字和勾选状态不画进视频素材。

| 菜单项/分组 | 对应素材或行为 |
| --- | --- |
| 打开 MingshenHarness | 显示主界面；可播放 `greet_wave`，不创建虚假任务 |
| 打开快捷对话 | 打开已有快捷 Chat 入口；可播放 `listen`，不自动发送消息 |
| 互动：打招呼、摸摸头、点头、摇头 | `greet_wave`、`pat`、`nod`、`shake_head` |
| 互动：看看周围、伸懒腰、喝水、小跳、律动 | `look_around`、`stretch`、`drink`、`jump`、`dance` |
| 互动：读一会儿 | `read_enter → read_loop → read_exit`，提供结束阅读入口 |
| 现在休息 / 唤醒 | `sleep_start → sleep_loop → sleep_end`；用户主动休息不能被普通任务提示立即打断 |
| 自由走动 / 停在这里 | 左右两套转向、行走、停止；实际位移由应用限制在可用屏幕范围内 |
| 锁定位置 / 重置位置 | 锁定时禁用拖动与漫游；重置到当前可用屏幕范围 |
| 置顶 | 系统窗口置顶开关，有明确勾选状态 |
| 大小 / 不透明度 | 滑块或现有设置入口，不能用视频本身变焦代替 |
| 鼠标穿透 | 交互开关；必须同时提供托盘或设置里的恢复入口，否则穿透后无法右键关闭 |
| 问候 / 闲聊频率 / 任务提示 | 沿用用户偏好，实际提醒事件可播放 `notify`，不读取正文内容来编造状态 |
| 安静一会儿 | 暂停主动闲聊与提醒，显示到期状态；不暂停 Agent 的任务 |
| 暂停动画 / 减少动态效果 | 保持清楚静帧和必要状态，避免黑屏或停在半截动作 |
| 动作预览 | 可预览所有已验收且连接链完整的动作，包含 `notify`；成功/异常也标明为预览，不修改真实运行状态 |
| 桌面体验设置 / 暂时隐藏 / 关闭桌宠 | 进入设置、隐藏窗口或停用桌宠，三者的持久行为明确区分 |

播放衔接规则：

- 鼠标轻拍播 `pat`；真正开始拖动后应取消轻拍，进入拖起/悬空。右键只打开菜单，不能顺便触发轻拍或拖动；菜单打开期间不随机切动作。
- 分批交付时按实际已验收资源开放菜单。睡眠、阅读和左右漫游分别需要完整的进入/循环/退出链；缺任意一段就隐藏或禁用该入口，不能让用户进入无法退出的动作。播放器仍需保留静态安全回退。
- 支持键盘菜单入口，例如菜单键或 `Shift+F10`，并能通过 `Esc` 关闭。菜单选项要能用键盘到达，不能只有悬停触发。
- 常规单次动作播完后恢复真实任务的状态。正在工作时不能因为摸头动画结束就把任务标成待机。
- 需要离开 THINK、WORK、SLEEP、AIR、LEFT、RIGHT、BOOK 时，先走适当的退出/落地/停止片段。不能从持书姿态直接切到空手招呼。
- 拖动、退出、窗口关闭和用户停止等事件可取消普通动作；如何从中间帧衔接需要实际播放器实现，不能只凭固定的动作优先级表保证无跳帧。
- 只预加载当前和下一段必要视频，避免每个桌宠窗口同时解码 36 段。解码失败回退静态角色图，不能卡死或抢占主任务。

## 7. 生成时直接使用的三条提交范例

### 7.1 第一条：先做待机试片

附件：认可的 `reference-front.png`。正文：第 4 节通用指令 + 第 01 条待机动作 + 共用负面词。时长 5 秒，画幅 1:1，固定帧率。

### 7.2 一条单次动作：挥手

附件：同一 `reference-front.png`。首帧与末帧都指定该图；正文：通用指令 + 第 03 条挥手动作 + 共用负面词。不要同时要求挥手、走路、说话与跳舞。

### 7.3 一组三段动作：工作

先认可一张 `reference-work.png`。分别提交三次：

1. FRONT 作首帧、WORK 作末帧，生成 `working_enter`。
2. WORK 作首尾参考，生成 `working_loop`；第一帧已经抬起双手操作腕部装置，不能重新做进入动作。

本视频路线采用角色原有腕部装置作为工作动作，免去平板的取出与收纳。旧序列帧指南中的平板方案是另一种美术方案，不要把两者的 WORK 参考图混在同一包里。

同一平台支持固定模型、版本、参考强度或种子时，记录并保持这些参数，降低批次差异；相同种子也不保证角色或首尾一致，仍然逐段验收。

## 9. 每条素材完成后的验收

1. **身份**：逐段抽查首、中、末帧，脸、发型、年龄观感、衣领、胸前装置与原图一致；不能前半像原角色、后半变成另一个角色。
2. **肢体**：手指、肘、膝、脚踝和衣服结构正确；没有穿模、增肢、手掌变形或袖口融化。大动作逐帧检查关键位置。
3. **构图**：没有运镜、裁头、切手、切鞋；整组角色同尺度、同机位。站立接地不漂，坐姿不放大，悬空锚点稳定。
4. **道具**：款式、大小与持握不跳变，取出和收回有连续路径；循环中不凭空增减物件。
5. **背景**：颜色均匀、没有影子或棋盘格；抠像后在黑、白及中灰底分别检查发梢、白衣、青色细节、手指缝与半透明边缘。
6. **循环**：连续播放至少 10 轮，核对首尾运动方向和速度。不能只比较两张静态姿势，呼吸、步态和摆动也不能突然反向。
7. **连接**：实际连播“进入 → 循环三次 → 退出”，叠加核对连接帧；有多手、重影、闪脸或道具突然消失就返工，不靠长时间淡化遮盖。
8. **小尺寸**：分别缩小到预期桌宠大小观察，表情与动作应能看清；缩小后的抖动、轮廓脏边和过亮装置依旧需要修正。
9. **格式**：普通 MP4 不当成透明文件；透明导出核对真实 Alpha。新素材的播放、占用与多屏缩放仍需在应用播放器中另外验证。

单张图可以用 SVG/CSS 增加眼睛、光效和小幅摆动；要得到这些完整的手脚动作，仍需要动作视频、序列帧或实际骨骼素材。通过提示词要求一致只是第一步，以每条实际输出和连接效果决定是否采用。
