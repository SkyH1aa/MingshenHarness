# Mingshen Harness 隐私政策

生效日期：2026-11-04；协议修订号：2026-11-04.3；当前适用软件版本：1.3.6。

Mingshen Harness 由新哲文院算法社提供。本文说明软件实际处理的信息、用途和用户控制方式。新加入的数据收集功能须更新本政策并取得适当授权。

## 1. 本地保存的信息

软件在当前 Windows 用户的应用数据目录保存供应商配置、模型配置、加密凭据、会话内容、附件、工具输出、任务、扩展副本、浏览器配置、运行轨迹和工作区快照。标准版使用 Electron 分配的 `Mingshen Harness` 用户数据目录，通常位于 `%APPDATA%`。不同发行渠道或管理员指定的数据目录可能不同。

可选桌宠的显示与行为偏好保存在本地应用设置中。启用桌宠后，主进程向桌宠窗口提供当前活动会话和运行的标识、状态、开始时间及默认显示的标题，用于工作会话面板、菜单和打开对应会话；同一会话的运行会合并，运行时长在本地计算。即使关闭工作会话面板，菜单仍可使用活动状态。标题可能包含敏感信息，也可能被附近的人看到。在“设置 → 桌面体验”关闭“显示会话标题”并成功保存后，桌宠窗口接收的标题为空，面板及右键菜单使用匿名名称；保存失败时原有标题仍可能显示，须重试并确认保存成功。除标题外，桌宠窗口不接收会话正文、文件内容、工作目录路径、命令参数或审批详情。桌宠的闲聊使用内置本地短句，不为闲聊调用模型或联网；打开快捷 Chat 后的对话仍按 ChatAgent 原有规则处理。

Responses 工具历史可包含供应商实际返回的加密推理/压缩项、助手阶段和工具调用信息，随原会话本地保存；它们是供应商签发的不透明状态，不是应用可解密的原始隐藏思维链，也不同于应用凭据的 safeStorage 加密。重放须匹配原供应商、模型和端点及可见内容；独立文本摘要不会传递这些不透明项。`view_image` 经批准读取的工作区图片可作为带图工具结果随历史保存，并发送给所选图像模型。由附件临时生成的 PDF 页面图仍沿用下述有限内存缓存规则，与主动读取后保存的图片工具结果不同。

1.3.2 的 Gemini / DeepSeek 适配还会随原会话保存 API 实际返回的原生续接字段：Gemini 原生 GenerateContent 的 Part（含返回的思考摘要、工具调用、可选调用 ID 和不透明签名）、Chat Completions 的不透明消息/工具签名，以及 DeepSeek Chat 的 `reasoning_content`、Responses 的明文 reasoning 项、Anthropic 的 thinking 内容块及可选签名。返回的文字不是凭据密文；Gemini 签名的不透明性也不等于应用凭据加密。软件不请求或补造 API 未返回的隐藏推理，不从界面思考文字重建原生状态。通过格式、容量及完成状态检查后，仅向相同供应商配置、模型、协议、端点及鉴权方式，且正文和工具标识、参数、顺序一致的后续请求重放。独立文本摘要不透传 `provider_state` 或不透明签名；普通可见文字仍按原有摘要规则处理。这些数据受会话本地保存、导出和删除规则约束，不新增云端接收方。分享数据库或会话导出前应核查其内容。

在 Mingshen Harness 生图工作台中生成的图片、画布工程和共享素材保存在本地应用数据目录。生成素材可同时保存用户输入的正面提示词、负面提示词、供应商返回的修订提示词及受限来源版本；只有具备该可信生成来源记录的素材才能在用户确认后回导提示词。外部导入或旧记录不会获得可信提示词，界面不会猜测缺失内容，回导操作也不会在取消时清空当前提示词。生图时相关提示词和明确选择的参考图会发送给所选图片供应商；提示词润色发送给所选语言模型；两者可能是不同供应商并分别产生用量。删除素材会清除素材记录及旧工作区备份中绑定的提示词；应用也会删除本地图片文件，但若文件被占用或系统拒绝清理，会明确警告且可能留下孤立图片。已发送给供应商的数据仍受对应供应商政策约束。

`browser_screenshot` 会把当前可见页面的 PNG 保存在用户数据目录的 `browser-captures` 中，并把截图像素作为带图工具结果保存在会话历史，随下一次视觉模型请求发送给所选供应商。截图最长边2048像素、PNG最多8 MiB；当前模型未配置图像能力时，图片不进入模型请求并明确提示。页面可能含敏感内容，调用前核对当前页面。

持久命令的进程句柄、stdin 和输出缓冲区仅在当前运行内存中维护；已返回的命令、输出与验证结果仍按普通工具历史保存。运行收尾停止仍受管理的命令并等待关闭/容器清理，不跨重启恢复命令会话。清理未确认时保留本地写入屏障和 lease，当前清理失败的恢复可能需要重启；清除屏障不能证明进程或容器已停止。子任务排队的验证由 `wait_subagents` 收集，当前模型轮全部工具结果保存后，经父会话现有审批与隔离顺序执行并保存独立结果，记录和模型接收方仍按原会话规则处理。

会话与工作区数据默认不上传至提供方云端。默认长期保留的历史、归档和快照会占用磁盘。删除应用不一定删除用户数据；可通过界面或在退出软件后清理相应数据目录。清理前应导出或备份需要保留的内容。

新项目默认使用原生 Memory，也可在创建时选择 TencentDB Agent Memory 本地核心；同项目后续会话、分支、实际子任务和关联 worktree 继承。设置 → 项目指令与信任支持手动选择工作区，修改其后端与分析模型，无需先创建会话；子任务及关联 worktree 解析到顶层主会话的记忆工作区。修改前须结束相关任务及记忆维护。一个项目同一时刻只启用一种方案，配置保存在现有本地应用设置中。显式切换保留两套记忆目录，不删除、改名、合并或迁移数据；旧项目存在目录或配置歧义时须在设置中明确选择，不自动切换。原生方案可能创建 `.harness-memory/`，保存用户明确要求记住的偏好、完成任务的短摘要、索引和归档。TencentDB 本地核心使用固定上游的 L1 提取调度、质量筛选、模型提取与冲突判断、写入及全文检索，不启用腾讯工作/团队提示。该预设不包含腾讯业务适配、OpenClaw、云端/团队服务、遥测、L0 原始对话采集、完整 L0–L3 流水线或向量/embedding API，也不联系腾讯记忆服务。

TencentDB 以宿主原子保存的工作区 `.harness-tencent-memory/records.jsonl` 为权威快照，最多 2000 条 / 2 MiB；上游产品存储回退已禁用，SQLite 全文检索索引仅在内存重建，不另存持久数据库，该预设不自动归档。用户可在设置以 JSON 数组修改现有内容或删除记录，新增使用主动记忆命令；删除会移除当前快照条目。两种方案均可查看、搜索、编辑、删除或关闭自动维护，优先只向当前模型提供精简偏好，历史在相关检索时按有界片段提供。成功主任务使用原生 Memory 时可由当前配置模型生成日记摘要，保留30秒总时限并记入记忆用量。TencentDB 改由工作区分析模型运行上游通用对话提取与冲突提示，提炼 `persona`、`episodic` 或 `instruction` 并决定保存、跳过、更新或合并；仅通过校验的结构化结果可原子提交，重复或有效空结果不新增记录，不回退为完整回答摘录。已确认的 `persona` / `instruction` 偏好不进入自动冲突处理的可变记录，不能被该流程改写或删除；主聊天模型通过记忆工具保存推断偏好仍须确认。升级或切换后端不批量清理、改写旧摘录；后续语义维护仍可更新或合并未受保护的旧记录，用户也可检查、修改或删除。短期上下文和原始对话不另存为记忆对话副本，原聊天仍按普通会话规则保存。

实际 Subagent 只能读取所选方案的记忆，普通文件工具不能修改记忆目录。子任务命令在原生 MXC 和 Docker 中均使用整个工作区只读的策略，即使记忆目录尚未创建也生效；普通项目文件仍可通过审批后的受管文件工具修改，记忆目录除外。主会话命令规则不变，宿主扩展和 stdio MCP 不向子任务开放。只读 Plan 不自动创建或维护记忆。远程只读 MCP 仍依赖服务提供者履行其声明，并非操作系统隔离承诺。初始化、模型错误、无效提取或取消不覆盖已提交快照，也不会静默启用另一方案。

关闭自动记忆后，后续请求不再新增自动记忆注入或提取任务记忆，已有文件不自动删除，用户主动管理命令仍可使用。此前已发送的偏好、日记片段和工具结果仍属于原会话历史，也可能保留在上下文摘要中；关闭开关、修改记忆源文件或 `/forget` 不会追溯擦除这些聊天内容或供应商已接收的数据。需要不再携带旧历史时应开始新会话，并按需删除原会话。原生归档保留原摘要，不截断或自动删除历史；TencentDB 当前快照删除不承诺清除用户自己的备份。脱敏仅覆盖可识别的凭据模式，模型生成的记忆可能出错，不保证准确性或固定 Token 节省；请核查并修正。记忆是工作区普通文本，不是加密凭据库，可能被用户自己的 Git、同步或备份工具处理，发布仓库前应检查。模型请求仍只发送给用户配置的供应商，不新增腾讯或 Mingshen 记忆云端接收方。

为保持模型请求前缀稳定，软件在本地数据库保存按时间排列的宿主状态快照，包括计划、当时使用的偏好或相关日记片段、代码提示、权限和诊断；这些已发送状态可随后续会话历史继续发送给所选模型，不是新的授权。最新状态替代旧状态的效力，但不会抹去其历史文字。Token Saver 还保存源消息哈希及精简后的替换片段，以复用已发送表示，不另建完整原始聊天副本。回退重写会话会清理这些快照和表示，删除会话也会清除对应记录；原消息及有效摘要仍按会话自身规则处理。缓存读取、写入和报告覆盖统计只在本地累计，不额外上传。

受控工具执行链只连续执行模型一次回复中已经明确的静态动作，不是跨任务的通用判断缓存。每一步仍单独校验参数、审批、隔离和记录，结果会随后续请求发送给当前模型，失败动作不会自动重放。

本地代码索引保存受授权工作区的 JavaScript/TypeScript、Python、Go、Rust、Java、C/C++ 和 C# 文件指纹、符号名称、位置、简短签名、引用/调用片段和导入关系，不另存完整源文件；查询结果可作为工具输出发送给当前模型。结构化计划、项目计划库、步骤依赖、断点、工具恢复点、已确认操作的参数哈希和待核实操作标识保存在本地。标题全文索引及变更序号用于本地分页搜索与增量同步，不新增云端存储。保存的项目计划独立于源聊天，需在计划库单独删除；会话自身恢复记录随删除清理。不确定扩展操作的工作区屏障需核实后解除。文件读取缓存及临时写入锁只用于当前应用运行。验证阶段通过当前权限和隔离环境执行项目声明的检查命令，输出按现有工具历史保存。用户仍应核查项目脚本及第三方工具行为。

缓存前缀诊断按会话与用途保存有限的带密钥摘要、变化类别、块数和已报告用量；密钥在每次进程启动随机生成且不落盘，重启后重新建立基线。诊断不保存请求正文、文件路径或 API Key，不额外上传。删除或回退重写会话清除对应诊断，已消耗用量仍保留。供应商缓存配置保存在本地；支持的缓存键或断点会随既有模型请求发送，延长保留期须由用户主动选择。Gemini / DeepSeek 自动适配只使用隐式缓存，不创建收费的显式缓存资源或自动设置其他供应商的缓存参数，服务端留存和计费仍由所选供应商决定。为同模型压缩复用的最近文本请求仅保留在有容量上限的进程内存，不另存完整磁盘副本；处理范围仍为已选压缩边界和模型，无新接收方。

## 2. 用户选择的模型供应商

独立压缩模型可把新摘要作为有界分段追加，旧摘要仍保存在现有本地摘要检查点，随同主模型后续请求发送；达到上限时合并，原始消息不因此删除。旧摘要也可能作为参考发送给已选主/备压缩模型，数据接收方没有新增。供应商模型体系属于本地缓存配置，不改变模型或协议；缓存键/标记仍随既有请求发送。模型之间不共享供应商缓存，具体保留与计费由供应商决定。

当用户发送消息时，软件向用户配置的 Base URL 发送当前任务所需的消息、系统提示、选定附件、已引用技能、工具定义、工具结果和上下文摘要。模型供应商可能在其他国家或地区处理数据，其保留、训练使用、安全和跨境安排由供应商决定。

TencentDB 自动记忆分析可使用工作区单独配置的主模型及可选备用模型；未指定主模型时，使用当前主对话实际运行的模型。完成的当前轮次最多20条用户/助手文字消息、合计32,000字符、每条最多8,000字符，经已知凭据脱敏后发送给分析供应商；不直接附带工具记录、附件、隐藏推理或更早轮次。冲突判断还会发送有界候选记忆。分析请求无可执行工具，每个模型尝试最多180秒，并记录额外记忆模型用量。主模型失败或返回无效结构时，备用从原始分析输入重做整次流程，可能将相同范围资料发送给不同供应商；有效空结果不触发备用。用户可清除独立模型或关闭自动维护。配置即选择相应分析接收方，已发送的数据无法撤回。本地记忆存储不表示模型分析离线，不新增 Mingshen 或腾讯记忆云端接收方。

这些既有请求也可包括已批准的本地图片工具结果，以及向匹配供应商配置、模型、协议和端点续接时所需的原生 Responses、Gemini / DeepSeek 状态；不新增 Mingshen 或腾讯接收方。修改配置或删除本地记录不会撤回供应商已接收的数据。

用户可主动通过输入框 Ctrl+V 或右键“粘贴”加入剪贴板图片。应用不后台监控剪贴板或读取剪贴板历史；粘贴仅加入待发送附件，不立即上传。点击发送后，图片按普通附件规则随消息本地保存并发送至所选模型供应商，发送前可移除。

PDF、DOC/DOCX 等上传文档可本地提取文字；扫描 PDF 可使用随包的离线中英文 OCR，不连接额外 OCR 服务。提取文字随消息本地保存并发送至所选聊天模型，历史压缩时也可能发送至配置的压缩模型，每份最多 120,000 字符并注明部分读取。按模型和协议能力发送原生 PDF，或在本地生成带页码的页面图像发送给当前视觉模型；页面图像只用于请求及有限内存缓存，不另存数据库。OCR 临时目录仅存随包识别语言数据，完成或取消后清理。加密、损坏或超出范围会保留具体限制；视觉和 OCR 结果不保证准确。活动计划清理不删除历史聊天或另存的项目计划。

`create_document` 可在当前工作区生成 DOCX、PPTX 或 PDF。作者输入、表格、讲者备注和目标路径仅在用户批准的当前会话中处理；PNG/JPEG 图片先经过单独的工作区读取和权限检查，不从网络地址加载。DOCX/PPTX 由随包作者库生成，PDF 由内置 Chromium 离线排版；生成文件通过现有文件写入审批、隔离、lease 和外部修改检查保存，默认不覆盖。生成正文不会自动上传到 Mingshen 或腾讯服务，但若用户把生成内容发送给模型，仍按模型供应商的数据政策处理。作者库的系统字体和布局在不同 Windows 机器上可能替代或变化。

“本地优先”不表示所有推理都在本地。使用本地模型也应核查其网络行为。API Key 用于向对应供应商鉴权；完整值不在界面回显，也不应写入聊天记录。

自动审批默认关闭。用户在设置中选择审批模型并为会话启用后，软件向该模型供应商发送待执行操作的工具名、说明、命令、路径和参数，文件操作参数可能包含拟写入的内容。审核不附带整段聊天历史，不提供可执行工具，尽力脱敏已识别的密钥和鉴权字段；脱敏不能保证识别所有敏感数据。审批模型可使用不同于当前对话的供应商，其数据保留与处理同样受对应供应商政策约束。模型的通过/不通过及原因记录在本地活动中。用户可切回手动审批、清除审批模型或停止任务；已经发送的数据仍按供应商政策处理。

上下文达到当前对话模型窗口的 85% 时，软件在下一次模型请求前向压缩模型发送较早的消息、工具参数与结果、已有摘要及文本附件内容，以生成后续任务所需的摘要。默认使用当前会话模型；用户可设置全局默认或单会话独立模型，所选供应商可能因此收到原先发送给另一供应商的历史资料。选择独立模型前请核查该供应商的数据政策与授权范围；压缩会产生额外 API 用量。摘要请求不重新发送附件的二进制内容；可解析的文档与文本附件包含最多前 120,000 字符的文字，未解析的二进制附件仅提供元数据和路径。软件尽力脱敏已识别的凭据，不能识别全部敏感信息。原始聊天记录、摘要与用量状态保存在本地，摘要不会替换或删除本地原始记录。可停止进行中的压缩或更换后续使用的模型；已经发送的数据仍按供应商政策处理。

用户还可分别配置备用审批模型和备用压缩模型。主模型连接失败、超时、断流或返回无效结果时，软件自动尝试一次对应备用模型；有效的拒绝裁决不会转给备用模型重新寻求通过。备用供应商会收到与其职责相同的操作数据或历史内容，可能不同于主模型供应商，并可能产生额外 API 用量。备用模型默认不配置，用户可清除；配置即授权在上述失败条件下向该供应商发送相应资料。停止任务、手动处理审批或返回手动模式会取消相关审批尝试。失败详情可包含经过脱敏和限长的模型响应预览，保存在本地活动或错误状态中；分享前仍须检查敏感内容。两次调用均失败时不自动放行操作、不替换有效摘要、不删除原始记录。

模型请求在网络中断、限流或服务端临时错误后，每次断连默认最多自动重连 5 次，可在设置中调整为 0–20 次；恢复有效输出后再次断连重新计数，不是整段对话的总额。重试会向同一已配置供应商重新发送当前请求，可能产生额外 API 用量；不新增数据接收方。审批与压缩保留原有主备顺序及总超时，每个候选模型内可进行传输重试；上述“两次调用”指主备两个逻辑尝试。有效拒绝不因重试而改判，已执行的本地工具不自动重放。每次失败按现有脱敏规则记入本地运行日志，任务停止会取消等待。

## 3. 浏览器、GitHub 和 MCP

嵌入式 Chromium 可保存网站 Cookie、登录态、缓存及站点数据。Chrome 兼容与 Edge 兼容是应用内配置名称，不等同于捆绑 Google Chrome 或 Microsoft Edge 产品。Agent 可以读取授权页面的内容，页面内容可能作为工具结果发送给所选模型。

连接 GitHub 后，凭据用于授权的 API/MCP 操作。第三方 MCP 可处理其参数、结果和所获授权数据；本地 stdio MCP 可能访问本机资源。用户应选择最小权限和可信来源。BrowserDo/Embiody 使用独立配置目录；Embiody 的更新、日志和网站数据受其自身政策约束。

## 4. 凭据安全

API Key、GitHub Token 和 MCP 敏感配置使用 Electron safeStorage 及 Windows 平台保护加密。软件仅显示掩码。加密保护静态存储，不能防御控制同一 Windows 账户、恶意扩展、恶意进程、操作系统失陷或用户主动复制泄露等情形。

错误显示会尽量脱敏密钥和鉴权字段，但第三方响应可能包含其他敏感信息，用户在分享截图和日志前仍需检查。

## 5. 下载、更新和依赖

访问技能市场时，软件向 GitHub 请求技能列表与文件。首次同意协议后，软件检查依赖并为缺失的 Docker、WSL2 或 Embiody 启动官方安装流程，界面显示进度或失败原因；用户也可从设置页重试。下载服务器通常可获知 IP、请求时间、资源地址和客户端信息。操作系统组件可能要求管理员确认或手动重启，软件不会自动重启计算机。

软件在启动后及每 24 小时查询 Supabase 中的最新公开版本元数据，也可手动检查。1.2.6 起，用户逐次确认自动更新后会连接发布者配置的 HTTPS ZIP 下载服务器，在用户数据目录的 `updates` 子目录暂存 ZIP 与安装程序；校验后等待会话结束，退出并启动安装程序。失败或取消清理本次缓存；成功交接的安装器为跨进程启动而保留，用户可在退出后删除该目录，程序不会重新执行旧缓存。旧版下载网页可由用户在默认浏览器手动打开。版本查询包含接口所需的公开应用密钥，不包含会话、源代码、用户 API Key 或 GitHub 凭据；下载请求不携带该密钥、模型凭据或浏览器 Cookie。Supabase 和下载/CDN 服务可获得连接 IP、请求时间及资源地址等服务日志。Docker Desktop、Embiody 及其他外部软件可能有自己的遥测与更新策略，Mingshen 不能代其承诺不收集数据。

## 6. 日志与故障报告

内置 Token Saver 在本机精简模型请求副本；新配置默认关闭按轮次提前摘要、回复采用自动档，已有明确选择保留，85%窗口压力压缩继续有效。用户启用提前摘要后，可调用已配置的主备压缩模型处理较早历史；接收方和数据范围沿用上下文压缩设置，不增加独立优化服务。摘要请求会增加模型用量。配置、按用途累计的已报告 token 数/请求数、最近请求的估算与变换类型/原消息标识保存在本地数据库，不另存完整聊天副本，不自动上传这些统计。原生状态和图片仅以摘要哈希参与前缀指纹，不复制进精简替换记录；对应消息的可见内容保持完整。原文召回只限当前会话，召回内容可随后续请求发送给该会话模型。删除会话清除对应统计和记录；重写历史清理失效展示但保留已发生的用量。可在设置关闭插件或分别调整策略；已有摘要不会因此自动撤销。

本地错误和运行轨迹用于排查。Mingshen 不默认自动上传聊天、文件或崩溃报告。只有明确启用并展示上传内容的诊断功能才可向提供方发送报告；当前未实现的上传功能不应视作已开启。未来如接入云端诊断，应限定用途、最小化并脱敏，设置不超过已公布期限的保留策略。

运行异常日志保存在当前用户数据目录的 `logs` 子目录，记录时间、错误来源、HTTP 状态、关联会话/运行/供应商/模型标识和限长错误详情，包括主模型失败后由备用模型恢复的尝试。日志最多保留 30 天，按五个文件、总计约 10 MiB 轮换；极端高频异常会限制队列并记录省略数量。软件不附带完整会话、附件或源文件作为日志，尽力脱敏凭据、鉴权头、Cookie 和已识别的请求内容字段。第三方报错可能仍包含路径或其他敏感资料，脱敏不构成完整匿名化保证。

用户可从设置 → 运行日志主动导出 JSON 到自选位置，并自行决定是否及向谁发送；导出不会自动提交给开发者或 Supabase。导出副本不受应用内轮换控制，由用户自行保管或删除。退出应用后可删除数据目录中的日志文件，后续运行可能继续生成新日志。

## 7. 分享和导出

Markdown/JSON 导出由用户选择保存位置。本地分享服务默认只监听 `127.0.0.1`，链接为只读并限时有效。链接持有者或同机能访问该服务的程序可能读取分享内容。将本地端口转发到公网属于额外发布行为，不在默认本地保护范围内。

## 8. 用户控制

用户可替换或删除凭据、关闭模型与 MCP、移除扩展、撤销项目信任、停止任务、退出应用以及删除或导出本地数据。彻底退出后不继续运行应用内计划任务。卸载第三方运行时及撤销 GitHub 端授权须在相应软件或账户设置中完成。

任务完成通知默认把会话标题和回答摘要交给本机 Windows 通知系统，可能出现在桌面横幅、锁屏或通知历史中，具体由 Windows 设置决定。设置 → 外观可关闭预览、声音、任务栏数字或系统通知。关闭预览后仅显示应用名称和完成提示。通知未读状态、回复路由和发送失败的回复草稿保存在本地；Windows 可能单独保存通知内容。通过通知输入的快捷回复按普通聊天消息传给原会话选择的模型，沿用原有权限审批，不新增提供方云端推送服务。

后台人工审批也可发送原生通知，默认包含会话标题、工具名和限长操作摘要；不将完整拟写文件内容附入通知。相同预览开关可隐藏这些内容，另有待审批通知开关。点击批准或拒绝由本机处理对应的单次审批，不新增云端审批请求；工具结果继续按原会话规则传给模型。请求与通知的临时关联仅在当前进程有效，停止、取消或处理后失效，重启不恢复旧通知授权。Windows 可能保留已经显示的内容，敏感工作请关闭预览并检查锁屏通知设置。

后台 Agent 提问及多 Agent 修改冲突也可触发本机 Windows 通知，默认预览包含脱敏、限长的会话标题和问题摘要，可能出现问题中提及的文件路径或任务信息。可通过设置 → 外观的独立提醒开关关闭，或使用共同的原生通知、预览和声音控制。点击提醒仅打开对应会话，不在通知中提交答案、转交文件写入权或增加权限；回答仍按原会话规则发送给所选模型。临时请求路由仅在当前进程保存，已回答、取消、停止或删除后失效；不新增云端推送或自动上传通知记录。Windows 可能保留已显示内容，请按需清理本机通知历史和调整锁屏设置。
