## 桌面流程

`scripts/v122-smoke.mjs` 使用临时工作目录和独立用户数据，结束后关闭其自身 Electron 并清理临时目录，不修改真实用户配置。

1. 首次协议同意后进入手册，应用信息返回 1.2.2。
2. 连续点击文件夹加号三次，只产生一个新会话且不弹出配置框；供应商、模型、思考档、Plan Agent、请求批准、Docker、系统提示、仅补丁和技能引用均与来源一致；新消息为空，目录仍未信任。
3. 文件夹可正常折叠；全局“新对话”仍打开手动配置框。
4. 书本入口切换更新日志，读取 1.2.2/1.2.1；中英文切换和日志到手册的内链正常。夜间常规窗口及白天 1040×680 均无对话框横向溢出。
5. 完全访问模式真实写入 `notes.txt`，即使目录有 `tsconfig.json` 和故意失败的 `typecheck` 脚本，也不触发无关代码检查或命令。
6. 请求批准模式经一次工具审批和原生隔离真实写入 `protected.txt`，不把跳过的宿主检查转换成诊断消息。

两次文档任务合计四次主任务模型请求，每次仅一轮写入及最终回复。检查真实文件内容、活动事件、模型请求正文和本地消息记录，未发现虚构诊断反馈。

## 边界

- 本轮没有执行 NSIS 编译、安装、卸载或升级，也没有重新运行 1.2.2 的 `--dir`；历史 1.2.1 解包验证不能替代 1.2.2 安装验收。
- 没有重测第三方 MCP 账户、BrowserDo/Embiody、真实付费网关或全面沙箱逃逸。本轮原生隔离仅覆盖实际受保护文档写入；Docker 配置继承不等于 Docker 引擎重验收。
- 本地模拟模型验证请求/工具/诊断链路，不代表所有外部模型都具备相同表现。没有宣称整套软件不存在其他 Bug。
