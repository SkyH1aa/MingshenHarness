## 本轮目标

- 新建和导入的画布保存为独立本地工程，可跨标签关闭和正常重启重新打开。
- 顶部提供新建、导入画布、重命名和关闭入口。
- 素材侧栏提供“我的画布”，支持搜索、打开、重命名、复制、删除和定位文件。
- 关闭标签与删除画布使用不同语义；复制画布复用共享素材。
- 旧版 SQLite 工作区可幂等迁移，损坏或非法工程不能阻止整个画布库读取。
- Renderer 不传任意文件路径，主进程校验画布 ID、文件类型、大小、符号链接和引用关系。
- 测试脚本连接真实主界面而不是即将销毁的启动展示页，完成首次协议流程后继续执行场景。
- 有效生成图片即使与请求尺寸不同，也按解码后的真实尺寸保存，并显示可关闭的逐张警告。
- 生成请求发出后切换到 ChatAgent 或工作站，供应商响应继续在后台等待并保存到本地素材库和当前画布。
- 参考图可由素材勾选或手动上传，图片文件可拖放到工作台快速导入素材库，拖放不会进入聊天附件草稿。
- 素材选择栏可批量 ZIP 导出、添加到当前画布或确认后删除；从素材库删除图片时一并清理绑定的生成提示词，且不会清空当前工作区提示词。
- 手动导入与拖放共用单图 25 MiB、每批 20 张、每批合计 500 MiB 预算；批量 ZIP 导出最多 200 项、源图片合计 500 MiB，并向界面报告已处理素材数和字节进度。
- Windows 安装器改将内置提示词树打入 `app.asar`，减少安装目录需要逐个复制的小文件；保留默认 7z 暂存解压及复制重试行为。

## 实现与定向证据

### 测试启动停在协议页

`creative-image-studio-smoke.mjs` 旧 CDP 选择器接受首个 `type: "page"` 目标，可能连到 `startup.html`。该启动窗口约 5 秒后销毁，挂起的求值不会正常返回，因此主界面停在首次协议页，测试没有继续勾选或进入手册。

脚本现只把 `type: "node"` 作为主进程目标，把 URL 匹配 `/renderer/index.html` 的 page 作为主界面目标，排除启动页。最终 smoke 已通过正常 UI 完成三项协议勾选、阅读等待及手册确认，再继续执行全部产品场景。此调整仅作用于临时测试 profile；正常产品没有跳过、自动接受或削弱首次协议要求。

### 尺寸偏差保留图片

- `ImageStudioGenerateResult.warnings` 返回逐张 `size_mismatch`，包括一基图片序号、请求宽高和解码后的真实宽高；匹配尺寸和自动尺寸均不产生该警告。
- 主进程先完成 Base64、格式、实际解码、数量及字节预算校验，再按真实尺寸落盘。尺寸偏差本身不再触发“图片未保存”；无效图片、超量结果、透明格式不符或远程 URL 仍按原安全规则拒绝。
- Renderer 在生成成功后显示持久、可关闭的尺寸警告和“图片已按实际尺寸保存到素材库”，不会把图片缩放后假称供应商遵从了请求。
- 服务测试使用真实 2,880×2,880 PNG 对应 3,840×3,840 请求，核对警告、素材元数据和磁盘读取；Electron smoke 使用本地合成图片核对图片显示与警告。

### 参考图、拖放与后台生图

- 参考图开关默认关闭；开启后按勾选顺序最多发送前三张，也可手动上传图片并自动加入素材库和选择。图片格式、大小、数量与主进程素材 ID 均按既有边界校验，关闭参考模式时不读取参考素材。拖放图片沿用同一套本地素材导入验证，不自动勾选参考图，也不会把附件写入当前聊天草稿。
- 进入生图工作台后，App 在本窗口生命周期内保留其 React 组件；切到 ChatAgent、对话或工作站时只隐藏并设为 inert。生图工作台仅在可见时向会话导航保护报告忙碌/未保存状态，后台生图不会阻止 Chat 会话导航。组件真正卸载时仍取消未完成请求，应用退出不会留下悬挂任务。
- 本地 Electron smoke 将合成图片供应商响应挂起，发出请求后依次切换 ChatAgent 和工作站，检查连接未断并确认隐藏组件不锁导航；释放响应后读取本地 workspace 和素材数据，验证图片已经保存到素材库且作为图层加入当前画布。结果：25 组断言、55 张截图、466 组几何、10 次本地模型/图片请求、0 Renderer 异常、0 服务夹具错误。结果文件：`.impeccable/review/v136-creative-image-1795442026990/result.json`。

### 本地画布与失败恢复

- 工程位于 `%userData%/image-studio/canvases/<canvasId>.mingcanvas.json`，共享图片继续使用素材 ID；关闭不删除，复制更换画布和图层 ID 但复用图片。
- 旧 SQLite 工作区迁移保留备份，重复迁移不覆盖已存在工程；重载读取工程内容，损坏工程在画布库中显示错误。
- 变更经过同一串行队列；文件采用临时写入、同步与同目录替换。文件或数据库提交失败时做补偿，不宣称跨文件和 SQLite 的严格事务。
- 缺失工程使用独立错误类型，缺失素材不会再误判为“工程不存在”并覆盖旧文件；素材并集超限会拒绝，不会静默丢图层。
- 关闭、删除、复制及重命名期间界面设置 `inert` 和 `aria-busy`，避免迟到编辑再次保存并重新打开已关闭画布。真实 smoke 挂起关闭 IPC，验证编辑面不可交互后再释放请求。
- 仍被已保存或已关闭画布引用的素材禁止删除。部分画布写入后若补偿也失败，`CanvasRecoveryError` 使新素材保留并明确提示人工恢复；补偿成功时仍清理本次新素材。测试覆盖第二工程写失败、第一工程回滚也失败的组合路径。

每条 `BeforeModelRequest` 的 `type: "prompt"` 可独立声明 `position: "before" | "after"` 与 `format: "context" | "plain"`。两个字段互不依赖，省略时分别取 `before` 和 `context`，兼容原有插件。`before/after` 指当前发往模型的请求内容顺序，不代表模型响应前后；`plain` 不添加插件标题、ID、来源归属或 `<mingshen_plugin_context>` 包装。示例配置为 `position: "after", format: "plain"`，会在原文 `xxxx` 后追加 `123abc`。`context` 保留低优先级、不可信标记；`plain` 是普通用户优先级内容，不提升为系统指令或权限，也不能保证模型遵循。

- 已激活的主 Code/Work 运行在每个模型请求、工具循环请求、网络重试、该运行触发的压缩/记忆请求前重新收集声明。活动父运行通过 `runSubagent` 派生的子任务首个和后续请求也覆盖在内；按需激活从下一次尚未发送的请求开始。用户消息历史不被注入文本污染，重试时不会累积重复后缀。
- `before + context` 进入插件上下文包装；其他三种形式作为请求中的用户内容型文字装配。普通输入轮次就近添加；如果末尾有多条连续的运行中引导，四种协议都会把 `before/plain` 放在第一条引导之前，`after` 保持在整个引导序列之后。Anthropic/Gemini 工具结果轮次遵守内容块协议，保持完整工具调用/结果及关联附件顺序，在工具结果内容之后添加，不会将文本插入工具调用与结果之间。其他协议按其 wire 形状添加普通用户尾消息或内容块。响应内容和已发送请求不被重写。
- `after + plain` 的文本拼接使用一个换行（`xxxx\n123abc`），不会额外插入空行；`format: "plain"` 是可复用的去归属选项，和 `before` 或 `after` 组合时都不添加插件 ID、标题、来源或 `<mingshen_plugin_context>` 包装。旧的 `format: "context"` 继续保留低优先级、不可信的插件上下文标记。
