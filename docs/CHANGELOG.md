# Mingshen Harness 更新日志

当前版本：1.3.2。

## 1.3.2

- 新增 Google Gemini 原生 GenerateContent 协议及 `x-goog-api-key` 鉴权，与现有三种协议并列。支持原生 SSE、思考、工具、图片/音频/PDF输入、分页模型发现与连接测试；所有模型入口共用配置。保留返回 Part 的边界、顺序、空文本和不透明签名，同名工具按内部标识配对，只回传服务端实际返回的可选调用 ID。未完成、安全拦截、取消或畸形响应不执行工具、不保存原生状态。
- 连接页可编辑鉴权方式及自定义头；运行期间拒绝修改端点、协议或鉴权。Gemini 默认保留 API 思考行为，2.5 使用 `auto`（Flash 可选 `none`），3 及以上按模型支持配置 `minimal/low/medium/high`；不自动猜测 token budget。原生协议沿用隐式缓存，不注入其他厂商参数或创建收费缓存。
- DOCX/PDF 表格单元格新增 `{"blocks":[...]}` 富内容，支持多段文字、行内格式、Markdown、列表、代码、引用和公式；DOCX 公式为可编辑 OMML，PDF 为排版结果。原字符串单元格保持字面文字，PPTX 表格继续仅支持字符串；每格最多 50 块/20,000 字符，内容计入全局 1,000 块/500,000 字符限制，模板填充同样受控。工具示例与双语内嵌手册同步，版本保持 1.3.2。
- 新增 Gemini、DeepSeek 供应商模型体系。默认仅按严格匹配的官方地址及协议识别，未知网关可在供应商连接页手动选择体系；体系不转换协议，也不保证网关透传。自动缓存使用二者的服务端隐式机制，不注入 OpenAI 缓存键或 Claude 断点，不创建收费显式缓存资源。
- 保留 Gemini Chat Completions 消息/工具的不透明签名，以及 DeepSeek Chat、Responses、Anthropic 三种协议实际返回的原生推理续接状态；保持工具顺序，只在供应商配置、模型、协议、端点及可见正文/工具身份与参数一致时重放。格式、容量、完成状态不符时保留普通历史，不伪造原生数据或从界面思考补造；旧记录不会自动补齐缺失状态。
- Token Saver 保护原生状态消息的完整正文和工具配对，独立文本摘要不透传 `provider_state` 或不透明签名。隐私政策同步说明 DeepSeek API 返回的明文推理与 Gemini 不透明签名作为本地会话数据保存，区分凭据加密和不透明状态，不新增接收方。
- DeepSeek Chat 按所选思考等级显式设置 thinking 开关和 effort，Responses / Anthropic 保持各自的原生映射；未选择等级时沿用 API 默认。避免把 DeepSeek Responses 当作 OpenAI 加密推理接口请求不受支持的 include。
- 用量解析补足 DeepSeek 命中/未命中计数及 Gemini 原生 usage 别名的兼容备用读取，有效标准字段优先，保留明确零与未报告的区别，拒绝矛盾或无效计数，不重复累加输入缓存。Gemini 原生输出备用计数纳入已报告的思考 tokens，保留供应商完整 total。
- 双语内嵌手册、更新日志与协议适用版本同步为 1.3.2，补充配置、诊断与官方研究来源。缓存最低长度、有效期和路由由供应商决定，不写死各模型阈值，不承诺固定命中率；升级、模型切换、压缩和旧历史缺少状态仍可能重建前缀。
- 新增 schema8 永久迁移，扩展供应商协议和鉴权约束，事务内检查外键并保留 Key、模型、会话、消息和设置。schema1–7 历史迁移及政策修订号 `2026-11-04.3` 保留。维护者已有的 1.3.1 安装包及独立发布 SQL 保留为历史材料；本轮未打包或发布 1.3.2，不能复用旧包哈希和大小。

## 1.3.1

- 供应商与模型设置支持长按拖动供应商排序，每个模型可独立星标或取消星标；聊天和所有模型选择菜单共用顶部可折叠“星标模型”组，使用“模型 ID（供应商名）”区分同名模型。菜单内同样支持供应商排序及星标，排序手柄支持 Alt+方向键，拖动可用 Esc 取消。星标绑定具体配置，展示遵循各入口的可用模型限制，禁用模型不会因星标变得可选。
- 供应商展示顺序与模型星标自动保存在本机，设置及各模型菜单即时同步，重启后保留。删除供应商或模型会清理对应偏好，新供应商追加显示；不会改动已选会话模型、默认及备用模型、继承规则或 Key 优先级。保存失败会显示错误并提供重试，具体模型配置仍按原入口保存。
- 设置 → 会话与数据新增“按文件夹管理会话”，包含仅有归档记录的文件夹及未选择文件夹的会话。可按未归档/已归档/全部和主会话标题筛选，逐项勾选或跨页全选匹配主会话，再批量归档、恢复或删除；每页50项，列表独立滚动。主会话的全部子会话（含独立worktree）一并处理，归档/删除确认显示实际主子数量。删除先停止任务，永久清除消息、草稿、附件及应用快照，保留项目文件；归档保留草稿并暂停关联定时任务，恢复不自动重启定时任务。逐项显示失败原因，已成功项保留结果，失败项继续勾选供重试；执行期间保留设置页直到处理结束。应用仍为1.3.1，不新增数据迁移。
- 扩展内置文档工具：DOCX 支持 LaTeX 转原生可编辑 OMML、Markdown、混合文字/行内公式、脚注、代码、引用、目录域、页眉页脚、页码与边距；DOCX/PPTX 增加原生图表和内嵌数据工作簿。DOCX 可受控填充唯一独占段落的模板标记；PDF 增加离线 Markdown/公式排版。工具说明、错误及打包检查同步，未知公式不会静默转成图片，既有审批和写入保护保留。能力矩阵与限制见 `docs/DOCUMENT_TOOLS.md`。
- 新增所有会话的待发送草稿自动保存：新会话、已有历史和子会话分别保存完整文字、格式状态及附件实际内容，切换返回、正常退出及重启可恢复，不依赖附件原路径仍然存在。发送被接收后只消费对应版本，发送前失败保留草稿，旧发送回执不清除新输入。手动清空或删除会话才移除未发送内容；自动清理保护有草稿的会话及其父会话。退出、更新交接和重载先等待写入，失败保留窗口并提示重试；失败通知回复排队持久保存，安全合并后确认，不重复追加。
- 输入框新增默认开启的粘贴格式显示：Markdown 标题、列表、表格、代码及 LaTeX 公式直接在输入区域渲染，底栏可切换原文编辑/格式预览。设置 → 外观与语言可关闭，立即生效并持久保存；发送继续使用原始 Markdown/LaTeX，保留原生编辑、选区、撤销/重做、中文输入和图片附件。超过 30,000 字符或格式复杂的草稿使用原文编辑；草稿预览不打开链接或加载远程图片。
- 修复工作区文件栏长列表无法滚动到后续文件的问题；文件树、编辑器和停靠命令面板保持各自的滚动区域。
- 修复光轨主题中子 Agent 展开按钮、对话菜单与会话标题重叠的问题，长标题继续保留完整悬停提示。
- 修复长压缩错误和工具详情撑宽聊天内部网格，导致历史与输入框偏移、展开再收起后移出窗口的问题。
- 优化长工具历史的渲染：折叠详情按需加载，避免输入、流式输出及计时更新反复格式化历史参数；完整命令、参数、输出和复制入口保留。
- 修复自动编辑检查将“未配置适用的项目诊断”显示为成功记录的问题：未配置适用检查器时直接跳过，实际选择诊断引擎后才显示检查进度；已配置诊断器的启动失败、命令缺失和真实检查失败继续显示。检查返回失败却没有错误输出时仍标记失败，并提示缺少错误详情。
- 应用、启动/打包入口及双语内嵌文档同步为 1.3.1；schema7、历史迁移与协议修订号保持不变。已有 1.3.0 安装包及发布 SQL 的实际哈希/大小保留，1.3.1 发布材料需重新打包后生成。

## 1.3.0

- 光轨细化标题栏、工具轨与输入区的金属层次及薄荷青/冰蓝光边，执行记录更清楚地区分当前运行与历史结果。主界面模型显示“模型名（供应商名）”，两段名称分别限宽，长名称仍保留完整悬停提示和辅助技术名称；设置中的供应商分组和模型选择行为不变。
- 运行活动、重连/压缩/审批模型诊断、最终报错及集成状态支持展开与收起，保留完整已接收内容并提供复制；修复工具活动与完整参数/结果的关联。历史工具记录分开显示命令、参数和输出，长行换行、长详情独立滚动；右侧审查、手动命令和 MCP/运行集成设置同步支持详情。展开聊天详情暂停跟随，子 Agent 有界预览提供完整会话入口；MCP HTTP/OAuth 诊断不再只留前4000字符，超过100000字符明确标记，脱敏与其它执行容量保护继续生效。
- “光轨”第二界面按预览重构为独立工作台：56px 工具轨、工作空间会话侧栏、面包屑标题、中央对话和底部状态栏；右上审查/文件/终端与右下任务/Agent 同时可见，保留 Git、浏览器、计划库和真实子任务输出入口。默认“简约”及三种工作布局继续保留，两风格按项目独立保存布局、宽度和开闭状态，共用业务功能与数据。
- 光轨消息增加身份、主/子 Agent 标记与真实时间，连续工具调用组织为可展开的执行时间轴，审查按选中文件展示真实保存的 diff，权限及隔离详情移至输入框底栏。日夜配色、金属边缘、细光轨和真实状态反馈保留，不显示大型“本地记忆引擎”卡片，记忆管理沿用现有入口。
- 设置 → 外观与语言可保存应用级界面风格，重载界面或重新启动后生效。重载先等待偏好、草稿及附件读写完成，保存失败则取消并提示重试，保存成功的待发送内容在重载后恢复。未保存的文件、消息和计划编辑仍阻止重载；主进程在运行、准备发送、手动压缩、等待审批/回答、退出清理或安装更新交接期间拒绝重载，不自动停止任务；日夜主题仍即时切换。
- 装饰动效遵循系统减少动态效果或应用“关闭”设置，隐藏窗口暂停流光。此次只调整布局、界面与交互呈现，版本保持1.3.0，schema7、永久迁移及协议修订号不变。
- 新增模型按 ID 前缀一次性预填：`gpt-6`（含 `gpt-6.1`）为上下文1000000、输出128000、文本/图片/文件及 `none,low,medium,high,xhigh,max`；`deepseek-` 为上下文1000000、输出384000、相同输入及 `low,high,max`。已有模型不覆盖，预填后可修改。GPT 新增表单的长上下文计费选项默认关闭，主动勾选设上下文200000，取消设1000000，不重置已填输出；仅为本地填写预设，不宣称实际供应商能力或计费状态。
- 上下文和最大输出支持大小写 K/M 十进制单位，保存时严格换算为安全范围内的正整数；错误保留草稿并定位输入。已保存供应商可编辑名称、Base URL 与 API 协议，保留 Key、模型及会话引用；运行中阻止地址/协议变化，不兼容缓存配置随协议切换重置为自动/5分钟。
- TencentDB 记忆改回固定上游的通用对话语义提取与冲突判断，由分析模型生成 `persona`、`episodic`、`instruction` 并选择 `store/skip/update/merge`。移除将完整回答或 `Assistant result excerpt` 直接写入的规则适配器；有效空结果表示无新增，已确认偏好不允许自动更新或合并，真实变更提交后才报告保存。
- 设置 → 项目指令与信任支持手动选择工作区并配置后端、TencentDB 分析主模型及备用。主模型留空沿用当前主会话模型，可只配备用；主模型失败或结果无效时，备用从头重做整次提取与冲突判断，不回退为原文摘录。必要的对话和候选记忆发送给相应供应商并产生 API 用量。
- 显式切换记忆后端保留两套目录，不删除、改名或迁移；同一时刻只启用所选后端。旧双目录配置需在设置中明确选择，子任务/关联 worktree 解析到顶层主会话的实际记忆工作区。配置修改需等待项目任务和记忆维护结束，取消、无效输出、配置变化及版本冲突不覆盖已提交数据。原生摘要行为、版本1.3.0、schema7 与协议修订号保持。
- Responses 保存供应商返回的加密推理/压缩项及助手 `commentary` / `final_answer` 阶段，并按供应商、模型、端点和可见内容校验后重放；不保存原始隐藏思维链，不把中途进展误当最终答复。网关未返回的状态不伪造，跨模型或端点不重放不透明状态。密文不按字符串长度计 tokens，每项预留1024、合计最多8192且不超过模型窗口5%，保留实际 usage 校准，不保证精确计数。
- 新增工作区 `view_image`，将批准读取的 PNG/JPEG/WebP/GIF（最多20 MiB）作为模型原生图像输入；沿用模型图像能力、路径、读取审批及原生 MXC/Docker 网关。
- `browser_screenshot` 保存 PNG 的同时，通过 `tool_result.images` 将实际像素放入下一次视觉模型请求，支持页面视觉检查；最长边2048像素、PNG最多8 MiB，与 `view_image` 的20 MiB限制区分。模型未配置图像能力时明确提示不发送图片。
- 新增管道式 `exec_command` / `write_stdin`，长任务可分次取得输出、输入、结束 stdin 或停止，绑定原会话与运行并在结束时清理；清理未确认时保留写入屏障和 lease，当前清理失败的恢复可能需要重启，清除屏障不等于确认进程或容器停止。不宣称完整 PTY/全屏 TUI。文本读取支持行范围、`limit` 和长单行 `char_offset` 游标，范围缓存仍核对完整源文件哈希。
- 启用并行工具能力的模型可同时执行最多3个相邻、独立的内置只读调用；命令、写入、执行链、浏览器、MCP 和自定义工具不参与，每次操作仍保留审批、隔离与预算。
- 可写实际子任务可用 `request_verification` 排队最多6条检查命令；`wait_subagents` 只收集请求，当前模型轮全部工具结果保存后，父会话再按自己的策略、审批、隔离与写入锁顺序执行并保存独立结果，避免 Chat/Anthropic 调用与结果配对错误。子任务 Shell 仍只读，排队与拒绝都不能报成通过。
- Token Saver 新配置默认关闭按轮次提前摘要、回复档位改为自动，保留已有明确选择和85%窗口压力保护。原生状态/带图工具结果消息不做文本精简或去重，阈值不把不透明或图像字节当普通正文 tokens。
- 新增可复现的六类任务基线与评分器：默认仅为离线合成夹具；显式启用独立 profile 的回环 API 才运行模型。缺失观测记为未观测，当前 API 的 wire/Token Saver 观测缺口和不完整账单范围单独披露，不把合成通过写成真实模型质量认证。
- Agent 配置新增独立的子 Agent 模型选择：只有 `Subagent` 与“主 Agent + Subagent”角色显示“使用主会话模型 / 单独指定模型”，每个 profile 分别保存；`@` 调用和 `spawn_subagent` 使用同一规则，主 Agent 与 Plan 的模型设置不会误路由到子任务。现有 `model_id` 字段及值继续保留，指定模型不可用时明确报错，版本仍为 1.3.0，schema7 不变。

- 新增内置 `create_document` 工具，可在当前工作区生成可编辑的 DOCX、PPTX 和可选中文字的 PDF。支持标题、段落、列表、表格、分页、幻灯片、讲者备注，以及经单独批准读取的本地 PNG/JPEG 图片；输出格式由目标文件扩展名决定。
- DOCX/PPTX 使用成熟的 Office Open XML 作者库，PDF 使用应用内 Chromium 离线排版，不要求安装 Office、Python、pandoc 或外部转换器。旧 `.doc` / `.ppt` 不作为输出格式，也不承诺对任意现有 Office 原稿无损编辑；默认系统字体为 `Microsoft YaHei`，不同 Windows 的字体替代可能影响版式。
- 生成写入沿用 Plan、patch-only、Agent profile、审批、隔离、文件 lease、外部修改检查和取消保护。默认不覆盖已有文件，显式 `overwrite:true` 后仍会先读取并核对当前版本；图片不从网络加载，失败不会留下半成品。版本升至 1.3.0，schema7、永久迁移和协议修订号保持不变。
