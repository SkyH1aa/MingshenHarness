# Mingshen Harness 更新日志

当前版本：1.3.7。

## 1.3.7

- 运行日志容量从约 10 MiB 提升为最多 15 MiB（五个文件各最多 3 MiB），保留期仍为最多 30 天。设置页与导出 JSON 展示当前留存记录的错误、警告、来源、操作以及已知省略/损坏数量；统计不是去重故障数或永久历史。桌面 IPC 和本地 API 的失败边界，以及后台工具、插件 Hook 和办公检查的状态诊断得到补充；新增后台诊断以有界状态/代码为主，不主动记录工具输出或文档正文。高频写入超过队列时单独计数，日志仍只保存在本机并由用户主动导出。
- 修复生图画布滚轮处理在被动监听器中阻止默认行为导致的重复警告，保留现有画布缩放交互；适配 Electron 新版控制台事件签名，避免同一 IPC 失败再由 Electron 控制台重复计入。画布引用素材时仍保留删除保护。
- 修复不稳定连接下单个模型请求的重试额度会随部分输出反复重置、导致无限重连的问题。现在同一模型请求共享固定重试预算；重试耗尽后不会把失败轮次的半截回答保存成完整消息，也不会执行未完成的工具调用。已完成的工具调用、文件操作和检查点保留，不会因重试而重放。界面现在会保留重试/丢弃诊断，并在运行时显示已完成的工具，而不是被活动记录隐藏。
- 顶栏新增“一键已读”按钮。点击后立即清除所有 CodeAgent、WorkAgent 和 ChatAgent 会话的应用内未读状态，同时清除 Windows 任务栏应用角标的未读数字，无需额外确认；已经开始的审批、提问、运行任务或通知记录不会被当作已处理，也不会因此停止或自动继续。未读状态仍按会话去重并保存在本机。
- 供应商新增独立 `OpenAI Images` 协议（选项显示为 `OpenAI /v1/images`）。新增、编辑或从模型列表导入的此类模型默认并强制为纯图片输出；即使 IPC、脚本、Headless 或旧客户端省略输出模态，后端也默认使用图片，显式文字/混合输出和工具调用仍会拒绝。该协议不显示上下文、输出 token、工具调用、思考和提示缓存字段，也不能充当聊天、审批、压缩、草稿润色或图片反推提示词的语言模型；缓存设置会被拒绝，文本协议切换到该协议时会清除旧缓存配置。Base URL 必须填写到 `/v1`，应用根据请求使用 `/images/generations` JSON 或 `/images/edits` multipart，不接受把完整端点重复填入 Base URL。既有 Responses / Chat Completions 下的纯图片模型继续兼容，但应用不会把 OpenAI Images 请求改投文本协议，也不实现第三方私有的异步任务轮询。
- 生图供应商可在 `data` 中返回 Base64 图片、远程图片 URL 或两者混合的结果。Base64 结果继续按原有安全预算直接保存；URL 结果不会直接写入素材库。为生成应用内预览，主进程先以不携带模型 API Key、Cookie 或浏览器凭据的请求，将远程图片载入有限内存并校验，此时尚未落盘素材库；用户确认后才把已验证候选保存为本地素材。关闭预览或选择“稍后”不会立即丢弃候选，仍可在约 30 分钟内重新打开；候选到期、被明确丢弃或应用退出等情况下才结束可用期。
- URL 图片预览与确认保存由主进程执行，不把模型 API Key、Cookie、浏览器凭据或其他供应商鉴权转发到图片地址；只接受无凭据的公开 HTTPS，并拒绝私网、回环、本机、保留地址、不安全重定向和 DNS 重绑定目标。每张图最多 25 MiB，单次结果最多 100 MiB，单次下载最多 90 秒；这些是 URL 生图预算，手动导入、拖放及批量导出/ZIP 的既有 500 MiB 预算另行适用。返回内容须完整解码并校验 PNG、JPEG、WebP、GIF 文件头与像素后才可保存。
- 确认保存的 URL 图片与直接返回的 Base64 图片按同一素材格式保存，并保留本次生成请求的用户正面提示词、负面提示词和供应商修订提示词，可继续使用素材回导、加入画布、下载、批量导出和删除流程。部分结果保存失败时会明确列出成功与失败项，不把未确认或尚未保存的 URL 冒充本地素材。
- URL 预览弹窗新增“在浏览器打开”，加载中、加载失败和已就绪状态均可用。Renderer 只提交不透明候选 ID 与请求 ID；主进程重新核对候选、期限、字面网络目标和 `browser.use` 策略，并对域名执行最多 5 秒的 A/AAAA 全量解析，要求所有结果均为公网地址。解析后、交棒前再次核对候选期限、operational、`network.request` 与 `browser.use`，之后才调用系统默认浏览器。该入口不等待预览队列、不取消或改变下载、不改变保存状态。外部浏览器拥有独立 Cookie、登录和验证码会话，不把其验证结果回传应用；浏览器后续 DNS、重定向和页面导航也不受应用内受控下载器的同一约束，因此不等于应用内安全校验通过。
- 生图工作台与主进程分别限制最多 3 个并发生成请求。每项独立显示状态并可单独取消，切换 ChatAgent 或工作站后继续后台执行。每个 generation 的总预算为 600 秒，包含供应商请求、响应解析和结果提交；远程 URL 预览下载仍为 90 秒，文本润色、反推提示词及其他旧请求预算独立。提交时快照正面/负面提示词、参考图和目标画布，结果合并时保留用户之后编辑的提示词和当前画布，不复活已关闭或删除的画布。
- 用户请求在附件处理、命令预处理和模型调用前先持久接纳并分配 `runId`；运行行、接纳记录和 `runtime.status` 的 `accepted` 生命周期事件同事务写入，提交后才向本机界面和事件流发布。同一会话、同一 `Idempotency-Key` 和同一载荷返回原运行，同键不同载荷返回冲突，重复请求不重复生成接纳事件。停止操作绑定准确运行。崩溃重启会把未结束运行标为中断，用户必须先核实可能副作用再继续，不自动回放模型请求、命令或已完成工具。
- 持久运行事件支持会话快照、`after` 游标、SSE `id` 与 `Last-Event-ID`，默认保留 30 天或总计 256 MiB。过期游标明确要求重新获取快照；Token 增量不持久化，最终消息、工具结果和快照为权威内容。
- 设置 → 运行与集成 → 运行治理新增模型连接等待：首个有效响应默认 5 分钟、流空闲默认 15 分钟，有效正文、思考或工具参数推进才会重置空闲计时，`0` 可关闭。心跳不续期；等待工具、审批或用户输入期间不计入；超时沿用单次模型请求重试预算，用户取消不重试，未完成工具调用不执行。该检测不是任务或 SubAgent 总运行时限。
- 新增应用策略与机器管理员策略。机器策略位于 `%ProgramData%\MingshenHarness\managed-policy.json`，与内置安全边界、应用策略、模式、项目和执行环境叠加，拒绝优先；项目、Agent 提示词和完全访问不能放宽。机器策略损坏、不可读或版本不支持时暂停新的模型、工具和扩展执行，历史、诊断、停止和清理仍可用；认证的本机 API 历史、快照、运行和有效策略查询保持只读可用，但不能借此执行写操作、认领或 Office 检查。创建交互终端会在启动 Shell/profile 前检查 `command.execute`。依赖自动探测与安装、Docker 启动、更新元数据请求、下载、签名验证、安装器执行及重启前交接也逐阶段重检策略；显式批准不能覆盖 `deny`，应用在数据库销毁前保留原始用户策略，并在实际重启安装器前重新读取机器策略，拒绝或损坏时跳过安装器。运行接纳时的 `policyRevision` 保持不变；最近一次拒绝的 revision、code、reason、scope、sources 和时间独立保存在 `lastPolicyDenial`，与拒绝事件同事务写入，并在事件保留上限清理后继续随运行查询和会话快照保留。
- 工具结果增加 `ToolOutcome`，区分执行状态、副作用确定性、结构验证、业务验证、原因码、证据和大输出恢复引用，并继续兼容 `output/isError`。运行状态迁移与生命周期事件使用同一 savepoint，事件持久化失败会回滚状态。Schema 校验在结算检查点、写入租约、PostToolUse 和成功存储前完成；大输出恢复索引原子更新，转存失败仍保留真实结果与证据缺口；检查点结算在工具执行后失败时改为副作用不确定并保留写入屏障；消息持久化失败回滚该消息，仅在安全条件下使用无图片回退，实时派发失败不会重复存储或执行。活动计划步骤新增 generation、原子认领、1 分钟心跳和 5 分钟租约；认领与心跳只接受真实 live executor，迟到旧 generation 不能覆盖新计划。
- 新增办公交付回执服务，记录 DOCX、XLSX、PPTX、PDF 的最终文件哈希、包/结构/内容/公式/重算/渲染/视觉阶段、证据和未验证项，并以独立 `formulaCoverage` 保存公式扫描是否完整、检查单元格数、公式数、未缓存数、错误数、样例上限和有界样例。结构检查与内容检查分离，非 XLSX 的公式覆盖为 `null`；达到 500,000 个非空单元格扫描上限时只能标记部分覆盖。支持默认 12 页 / 12 MiB 每批、20 页 / 20 MiB 硬上限、200 页 / 200 MiB 每文件每轮、256 MiB 渲染输出上限和 24 小时 / 512 MiB 证据缓存，并可从任务工作台继续未完成视觉批次。主 CodeAgent/WorkAgent 在宿主、完全访问且有工作区时，工具批次后的办公文件变化会自动生成回执并检查；可修复问题回到模型，按每个文件最多 3 轮修复。预算耗尽后当前运行对该文件的后续写入被阻断，缺少 Office、LibreOffice、视觉模型或页面预算时明确降级，不把写入成功当作交付通过。
- 本机 `/v1` 新增能力发现、会话快照、幂等发送、运行查询与准确停止、事件续接、有效策略，以及计划认领和办公回执的受控写入。认领支持 `claim`、`heartbeat`、`settle`、`recover`；外部 `settle` 必须提交调用方最近读取的正安全整数 `expectedVersion`，心跳推进版本后旧值返回 `409`。正文与思考增量实时显示但不带持久事件 ID，也不推进重连游标；ACP 仅接受本 bridge 创建的会话，在过滤外部会话事件前仍按全局持久事件推进恢复位置。外部办公回执只开放 `prepare`、`check`，其中 `prepare` 只接受会话工作区内相对路径。`visual-batch`、`record-visual` 仅用于桌面任务工作台的宿主内部视觉续接，外部调用拒绝提交或改写视觉证据。停止的 `202` 只表示 `stopRequested`，`cancellationConfirmed` 仍为 `false`，必须观察准确运行的终态。随包 SDK、CLI 与 ACP 使用同一运行和游标语义。服务仅监听回环地址，Bearer Token 在服务重启后轮换；Node.js 24+ CLI 不另起后台服务。
- SQLite schema 最终升至 11，顺序保留 schema 1–10 的既有供应商、Key、模型、会话、设置和凭据记录，并新增运行、请求接纳、持久事件、计划认领和办公回执记录。schema 10 升级前创建 `.pre-v11-backup-*.sqlite` 完整备份；迁移失败时主库保留在 schema 10，降级前必须恢复升级前备份。

## 1.3.6

- 生图素材库支持批量选择、添加到当前画布、ZIP 导出和确认后批量删除。手动导入与拖放共用单图 25 MiB、每批 20 张、每批合计 500 MiB 的导入预算；批量导出最多选择 200 项，ZIP 内源图片数据合计上限 500 MiB，并显示已处理素材数与字节进度。删除时会从素材清单与旧迁移备份中同步清除图片绑定的生成提示词，不修改当前工作区的正负提示词；只要有一张仍被打开或保存的画布引用，整批删除就会取消。ZIP 仅包含图片，不附带未验证来源的提示词文件。
- Windows 安装包将内置提示词和技能资源收进 `app.asar`，避免复制一万三千多个独立提示词小文件；保留默认 7z 暂存解压和复制重试。打包校验从 ASAR 回读完整提示词树并逐文件核对 SHA-256。该调整减少安装中的小文件复制工作，但不承诺固定安装时长；未在用户机器进行耗时 A/B 测试。

- 生图画布从单一工作区状态升级为独立的本地工程库，使新建和导入的画布可在关闭标签或重启应用后重新打开。参考图、拖放导入与后台生图通过本轮全量检查后，已重新生成并核验 1.3.6 安装器与 ZIP；实际结果与未覆盖范围见[1.3.6验证记录](VALIDATION_1.3.6.md)。
- 生图工作台新增“使用参考图”开关，默认关闭并随工作区保存。开启后按素材勾选顺序最多发送前三张，超过三张时只参考前三张并提示；支持预览、单独移除和手动上传 PNG、JPEG、WebP、GIF，上传文件进入本地素材库并自动选为参考。也可将图片文件拖放到工作台快速导入素材库，复用既有校验预算且不会自动启用参考图。生成请求发出后可切换到 ChatAgent 或工作站，生图工作台会在后台等待供应商返回，再将图片保存到素材库及当前画布；切换工作面不会中断请求，仍可主动取消，退出应用会结束未完成请求。GIF 和 WebP 都会只取第一帧并转换为 PNG 后发送，转换后的参考图仍受单图 25 MiB 限制，素材库原文件不变；APNG 仍不支持。无参考图时继续使用 OpenAI Images 兼容 `/images/generations` JSON 请求；启用参考图后，单图或多图均使用 `/images/edits` multipart，网关不支持编辑、多图或相关参数时明确报错，不回退为无参考生成。Renderer 只提交受控素材 ID，主进程校验、去重并读取文件；只有用户主动开启并明确选择的图片才发送给所选图片供应商。图像反推仍独立使用视觉语言模型。
- 生图素材现在可保存可信的生成提示词记录：Mingshen Harness 生成的图片分别保留用户原始正面提示词、负面提示词和供应商修订提示词，并提供“导入提示词”操作。每次有效回导都会先确认；取消不修改当前工作区。生成时明确为空白的负面提示词可在确认后清空当前负面字段，旧记录没有负面元数据时只恢复正向并保留当前负向。外部导入或历史记录缺失时明确提示无法可靠恢复，不猜测旧文本，也不清空当前提示词。素材选择栏支持全选当前搜索结果、清空选择、批量加入当前画布、最多选择素材库容量 200 张并合并 ZIP 导出（源图片合计上限 500 MiB，显示处理进度），以及确认后批量删除；删除会清理素材与旧工作区备份中的提示词，任一素材仍被已保存或打开画布引用时整批取消。
- `BeforeModelRequest` 的 `type: "prompt"` 新增可选 `position: "before" | "after"` 与 `format: "context" | "plain"`，省略时继续使用原有的 `before + context`。四种组合分别支持在模型请求原文前或后注入，以及保留插件上下文包装或仅发送普通文本；`after + plain` 可直接把 `123abc` 追加在原文 `xxxx` 后，不显示 `<mingshen_plugin_context>`、`Plugin N`、来源或插件说明。这里调整的是发往模型的请求内容位置，不是响应前后；`plain` 仍为普通用户优先级内容，不会成为 system 指令或获得权限。每次模型请求、重试、工具循环、压缩和记忆请求都会重新读取声明，临时附加且不写回会话历史。`before + context` 仍进入系统上下文；其余用户内容型注入遇到普通输入会就近追加，工具结果轮次则按协议在完整工具结果内容之后添加普通用户文本块或独立 user 尾消息，不把文本插入 tool call 与 tool result 之间，也不改写或拆开调用/结果配对。无效字段、读取失败、3 秒总预算、单条 4,000 字符或聚合 12,000 字符超限仍会使当次请求 fail-closed。
- 每张画布使用独立本地工程文件，记录画布名称、尺寸、图层、时间和所引用的素材元数据；共享图片素材继续保存在生图素材目录，不在复制画布时重复复制二进制图片。
- 生图工作台增加明确的导入画布、新建画布、打开和关闭入口。关闭标签只把工程移出当前打开列表，不删除本地文件；删除画布必须从“我的画布”显式执行。
- 素材侧栏增加“我的画布”，支持搜索、重新打开、重命名、复制、删除和定位本地画布文件。重命名和复制通过合法画布标识交给主进程处理，Renderer 不提交任意本地路径。
- 旧版 SQLite 工作区中的画布在首次使用时迁移为独立工程文件，并保留旧值备份；迁移完成后按打开列表恢复标签，重复启动不覆盖已存在工程。
- 画布文件采用临时文件、同步与同目录替换保存；损坏、格式不符、超大、符号链接或越界标识应被拒绝。需要删除素材时，应检查已保存画布是否仍引用该素材，不能静默破坏关闭的工程。
- 供应商返回有效图片但分辨率与请求不一致时，仍按实际宽高保存到素材库并可加入画布；结果附带逐张请求/实际尺寸警告，不再因尺寸不符丢弃图片。
- 修复测试启动时误连接短时启动动画页的问题，改为锁定真正的主界面后继续首次协议和手册流程；正常产品仍要求用户明确同意协议。
- 画布关闭、删除、复制和重命名期间暂停编辑，避免迟到保存重新打开已关闭标签；缺失素材会阻止覆盖旧工程，保存补偿失败时保留新素材并明确提示恢复。

- Office 结构化 Excel 请求增加累计 100,000 单元格工作量预算，拒绝 `WEBSERVICE`、RTD、DDE/EXEC 等主动函数、外部工作簿、URL/UNC 和 `EXTERNAL` 引用。宿主文档覆盖改为锁定并复核旧目标、备份、提交新临时文件、回读身份/大小/哈希及失败恢复；取消、超时或恢复未确认会明确报错并保留恢复备份，但不宣称分步重命名间无 gap 或可抵御断电。嵌入工作簿在解压前共享最多 64 个归档、4,000 个条目、100 MiB 声明解压量和四层递归预算，并扫描嵌入公式；DOCX 受控编辑拒绝外部非普通超链接关系、附加模板、子文档、OLE/ActiveX、`altChunk` 与主动字段，生成的 PNG/JPEG 增加结构和完整性校验。
- `office_document verify` 现在返回独立的整体、渲染和重算状态：`verified`、`partial`、`unavailable`、`failed`。任何非 `verified` 的整体状态都会使工具结果显式失败；超过 2,000 个检查单元格时公式扫描为 `partial`，导出 PDF、打开文档和结构检查都不能冒充逐页视觉或公式验收。Office 不可用、正在使用、策略阻止、取消或超时仍保留结构证据和未验证标记。
- MCP OAuth token 请求禁止跟随重定向，避免把授权码、refresh token、client secret 等 POST 表单转发到其他来源；编辑 MCP 密钥只保留仍在 Header/环境变量声明中的旧值，删除声明会删除秘密，未声明的新秘密会被拒绝。内嵌浏览器本地文件预览改为绑定当前会话工作区的授权令牌，不再全局放行任意 `file:`；无头 API 建会话复用正常模型、Profile、工作区与配置校验。
- ACP 请求处理 `run_failed` 和 `run_interrupted`，同一会话拒绝并发 prompt，旧事件不能覆盖新请求；`session/cancel` 的 abort 请求有 10 秒默认上限，HTTP 失败、网络错误或超时会明确拒绝当前 prompt 为“远端停止未确认”并清理本地 waiter，不会假报取消成功；实验启动入口每次核验固定原生沙箱并先构建当前源码，避免删除文件、配置变化或产物缺失时误用旧构建；本地插件 SDK 的 `marketplace.json` 更新使用同进程串行队列、跨进程锁、随机同目录临时文件和原子重命名，写入后回读核验。正常写入最多等待 15 秒；锁超过 60 秒时不再按 mtime 自动回收，而是报告锁路径并保持清单不变，要求确认无 writer 后人工删除锁文件，避免释放竞态误删另一进程的新锁。
- 版本、启动/打包提示、SDK 默认版本、当前适用文档和发布材料说明同步为 1.3.4；历史 1.3.3 安装包、ZIP、SHA-256、大小、发布 SQL 和验证记录保持不变，不能复用于新版本。

## 1.3.3

- 新增 CodeAgent、WorkAgent 与 ChatAgent 三模式。主界面标题栏直接切换；CodeAgent/WorkAgent 共用原有会话和工作目录，可在同一对话内改变下一轮模式，历史、目录、草稿、附件、计划和摘要保留。运行、准备发送、等待审批/回答或压缩期间前后端共同锁定模式修改；完成或手动停止后才可切换。ChatAgent 使用独立分组对话页，不与 Code/Work 会话直接互换。

- CodeAgent 和 WorkAgent 会为内置 Skills/Plugins 与所有已安装且启用的 Skills/插件建立按需能力索引。输入框加号的“引用”面板可按会话手动选择内置能力或已安装扩展，选中项优先；其他启用项仍可通过 `discover_capabilities` 按任务上下文搜索，再用精确 ID 加载相关 Skill 正文和只读参考。手动选择不会关闭自动发现。停用扩展不出现在结果中，ChatAgent 在发现和加载两层均被拒绝；发现不执行脚本，MCP/Hook、审批与隔离权限保持不变。

- 新会话拥有独立聊天记录和运行状态，不复制原会话的消息、标题、置顶状态或审批授权。来源配置已失效时显示错误，不静默替换模型或提高权限。顶部“新对话”仍可用于手动配置新工作区。
- 顶栏书本入口增加“使用手册 / 更新日志”切换，内嵌中英文文档，断网时仍可阅读。
- 服务协议、隐私政策、免责协议和用户手册的中英文内嵌版本统一标识当前软件版本 1.2.2；协议修订号保持 `2026-11-03.3`。

### 修复

- 修复请求批准或 Docker 模式跳过宿主检查时，仍将执行提示误当作诊断错误发送给模型的问题。
- 普通文本、Office、PDF 等文档编辑不再自动触发代码类型检查。没有实际诊断时，不向模型插入要求修复的消息；用户显式配置的文档语言服务器仍可工作。
- 自动格式化只接收适用的现存文件，过滤不支持的文档和已删除文件，避免无关检查干扰任务。
