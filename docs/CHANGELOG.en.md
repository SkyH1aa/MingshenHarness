# Mingshen Harness Changelog

Current version: 1.3.6.

## 1.3.6

- The asset library supports bulk selection, adding selected images to the active canvas, exporting one ZIP, and confirmed batch deletion. Manual import and drag-and-drop share a 25 MiB per-image, 20-files-per-batch and 500 MiB per-batch import budget. Export selection is capped at 200 assets, source image data in one ZIP is capped at 500 MiB, and the interface reports processed asset and byte progress. Deletion removes each asset's bound generated prompt metadata from both the active asset index and the legacy workspace backup, without changing the current workspace prompts. If any image is referenced by an open or saved canvas, the entire batch is rejected. ZIP exports contain images only, not unverified prompt sidecars.
- The Windows package embeds built-in prompts and Skills in `app.asar`, eliminating the copy of more than 13,000 individual prompt files to the install directory. The default staged 7z extraction and copy-retry behavior remains enabled. Packaging reads the prompt tree back from ASAR and verifies every path and SHA-256. This reduces small-file installation work but does not guarantee a fixed installation duration; no timing A/B was run on the user's machine.

- Image Studio canvases move from a single workspace setting to an independent local project library so new and imported canvases can be reopened after closing their tabs or restarting the application. After full validation of references, drag-and-drop import and background generation, the 1.3.6 installer and ZIP were rebuilt and verified. Actual results and remaining limitations are in the [1.3.6 validation record](VALIDATION_1.3.6.md).
- Image Studio adds a **Use reference images** control that is off by default and saved with the workspace. When enabled, it sends at most the first three selected assets in selection order and shows an overflow notice when more are selected. Images can be previewed and removed individually, or uploaded as PNG, JPEG, WebP or GIF files; each upload enters the local asset library and is selected automatically. Image files can also be dragged onto the workspace for quick asset-library import; this uses the existing validation budgets and does not automatically enable references. After a generation request is sent, switching to ChatAgent or the workstation leaves Image Studio running in the background until the provider responds; returned images are saved to the asset library and active canvas. Switching surfaces does not cancel the request, while the explicit Cancel control and application shutdown can. GIF and WebP references both use only their first frame converted to PNG before sending. The converted reference remains subject to the 25 MiB per-image limit, and the original asset in the library is not replaced. APNG is not supported. Without references, requests continue through the OpenAI Images-compatible `/images/generations` JSON path. With references, both single-image and multi-image requests use `/images/edits` multipart. Gateways that do not support edits, multi-image input or the related parameters return an explicit error and are never silently retried as reference-free generation. The renderer submits only controlled asset IDs, and the main process validates, deduplicates and reads the files. Only images explicitly selected after the user enables references are sent to the selected image provider. Image-to-prompt remains a separate flow that uses its own vision-model input.
- Generated assets can now keep trusted prompt records. Images generated by Mingshen Harness store the user's original positive prompt and negative prompt separately from any provider-revised prompt, and each card offers **Import prompts**. Every valid re-import asks before replacing the current workspace text; cancel changes neither field. A generation explicitly made with a blank negative prompt can clear the current negative field after confirmation, while an older record without negative metadata restores only the positive prompt and keeps the current negative field. External imports and incomplete legacy records produce an explicit unavailable message, never a guessed or split legacy prompt, and never clear either current field. The asset selection bar supports selecting all current search results, clearing the selection, adding selected images to the current canvas, and exporting a ZIP with up to the 200-item library capacity (500 MiB source-image-data cap with processed asset and byte progress). Confirmed batch deletion removes matching prompts from asset records and the legacy workspace backup; the entire batch is cancelled if any selected image is still referenced by a saved or currently open canvas.
- `BeforeModelRequest` `type: "prompt"` entries now accept optional `position: "before" | "after"` and `format: "context" | "plain"`; omitted fields keep the existing `before + context` behavior. The four combinations can place text before or after the original model request and either retain the plugin-context wrapper or send plain text. `after + plain` can append `123abc` directly after `xxxx` without showing `<mingshen_plugin_context>`, `Plugin N`, source attribution or an extra plugin explanation. This position is within the outgoing model request, not before or after the response; `plain` remains ordinary user-priority content and does not become a system instruction or gain permissions. Declarations are read again for each model request, retry, tool-loop round, compaction or memory request and are added temporarily without being written into conversation history. `before + context` remains system context. Other user-content additions decorate ordinary input in place when possible. In tool-result rounds, they follow the wire protocol by adding ordinary user text after the complete tool-result group, either as a text block in the existing user content or as a separate user tail message when required. They are never inserted between a tool call and its result, and the call/result pairing is not rewritten or split. Invalid fields, declaration-read failures, the 3-second aggregate budget, the 4,000-character per-prompt limit or the 12,000-character aggregate limit still fail the affected request closed.
- Each canvas uses a separate local project file containing its name, dimensions, layers, timestamps and referenced asset metadata. Shared image assets remain in the Image Studio asset directory, so duplicating a canvas does not duplicate its binary images.
- Image Studio adds explicit Import canvas, New canvas, Open and Close entry points. Closing a tab only removes the project from the open workspace and does not delete its local file; deletion must be explicitly requested from **My Canvases**.
- The asset sidebar adds **My Canvases** with search, reopen, rename, duplicate, delete and reveal-file actions. Rename and duplicate pass validated canvas IDs to the main process; the renderer does not submit arbitrary local paths.
- Canvases in the previous SQLite workspace are migrated to independent project files on first use with a backup of the old value. The open-tab list is then restored from those projects, and repeated starts do not overwrite existing files.
- Canvas writes use a temporary file, sync and same-directory replacement. Damaged, malformed, oversized, symbolic-link or path-escaping projects must be rejected. Asset deletion should check whether saved canvas projects still reference the image rather than silently breaking a closed project.
- When a valid provider image has different dimensions from the request, Image Studio saves it at its actual size and can add it to the canvas. The result includes a per-image requested-versus-actual size warning instead of discarding the image.
- Fixed the startup smoke test attaching to the short-lived startup presentation instead of the real main interface. It now continues through the first-use consent and guide; normal users must still explicitly accept the policies.
- Canvas close, delete, duplicate and rename pause editing to prevent late saves from reopening closed tabs. Missing assets block overwriting an existing project, and failed save compensation retains new assets with an explicit recovery message.
- The Windows install layout now embeds built-in prompts and Skill resources in `app.asar`, so NSIS no longer copies more than 13,000 individual small files into the installation directory. LSP, the native sandbox and the plugin SDK remain external where a real filesystem path is required. Packaging reads the complete prompt tree back from the ASAR and compares every file's SHA-256. This removes the small-file unpacking overhead; actual install time still depends on antivirus scanning, storage, Windows policy and machine performance.

## 1.3.5

- Fixed built-in plugin-creation Skill loads that requested nonexistent reference filenames. `plugin-creator` and `harness-plugin-api` accept their actual entry Markdown filename or the default `SKILL.md`; named on-demand references now cover manifests, hooks, the API and development workflow. Missing resources report the available relative paths found for that Skill.
- Local plugin validation accepts one plugin directory or a `marketplace.json` market root. Market-root validation reports each plugin's source and errors without registering the market or installing anything. Each round-robin update-check batch reads at most 10 registered markets and up to 200 entries per market catalog. Candidate results merge across batches, while a batch replaces results only for the markets it scanned; the next-check button rotates to the next batch instead of rescanning all markets. Candidates are removed when a market is unregistered or its registered path identity changes, a plugin is no longer installed or its recorded source provenance no longer matches, or the installed version has caught up to the candidate. An installed plugin with no recorded source or an untraceable source is not automatically matched to a same-name market entry; its original source must be verifiable. An update is offered only for a strictly newer semantic version with a rechecked matching source path. The user must click Update; new versions are never silently installed or executed.
- Ordinary installed and enabled plugins default to on-demand activation: CodeAgent/WorkAgent can search with `discover_capabilities` and activate a plugin for the current run with `use_plugin`, without manual preselection. `activation: "required"` still requires a user reference. Added prompt-only `BeforeModelRequest` context before each model request and retry in an activated primary Code/Work run, including compaction and memory requests triggered by that run. Actual child tasks launched through `runSubagent` inherit only declarative `type:"prompt"` context from the active parent run's selected or activated plugins, on their initial and subsequent model requests. Later parent-run activation is read before the child's next unsent request and cannot change a request already sent. On-demand activation starts with the next request; select a `required` plugin before submitting when its marker is needed on the initial primary request. Hook collection has a 3-second aggregate budget and 4,000/12,000-character per-prompt/aggregate limits. A declaration read failure, timeout or size overflow stops the request before it is sent instead of silently omitting the marker. The hook adds bounded, low-priority untrusted text and runs no commands or MCP actions. This inheritance does not enable `UserPromptSubmit`, `Interrupt`, plugin commands, MCP tools, action hooks or `local_plugin` in child tasks. It does not apply to an independently opened `@` child conversation without an active parent-run mapping, approval-safety models, ChatAgent, independent AutoDrive/draft-polishing calls or post-run title generation.
- Raised the per-call request budget for `web_search` and `web_fetch` to 90 seconds. Search fallback shares one budget, and user cancellation, timeout and web-service errors are reported separately.
- Refined the default Simple theme's workspace hierarchy, spacing, focus feedback and runtime status presentation while retaining the existing feature structure. Empty task areas now collapse to their content instead of reserving a large blank region.
- The startup presentation covers the primary screen in a topmost, non-exclusive window, animating the existing atom mark and orbits and reporting actual startup stages. With normal display and the main window ready it lasts about five seconds; settings can disable it, and the button or focused-window `Esc` can skip it. Errors or an approximately eight-second fallback end it. For users who have already accepted the policies, bounded conversation index warming may occur while it is active, without reading bodies or keys or guaranteeing a speedup. First-use policy reading starts after the presentation ends and the main window is shown, retaining the minimum five-second reading requirement. Reduced motion retains status and controls without movement.
- The optional desktop companion remains disabled by default and includes 36 transparent actions processed from the supplied character videos. It responds to task, drag, rest and interaction states, falling back to a still image on decoding errors. Its context menu offers task status and conversation navigation, Quick Chat, interactions and previews, rest/wake, position locking, display options, settings, temporary hiding and persistent disablement. Manual rest does not stop work and previews do not change task state. Idle chat is local and makes no model or network request. Original videos are not overwritten; background removal and character consistency are not guaranteed lossless.
- Windows pinning uses Electron's `screen-saver` window level. While pinned, a 200 ms watchdog checks hidden/minimized state and reapplies the topmost level and Z order while the pet remains visible, including when another topmost window covers it without causing blur; Z-order reassertion pauses while the native context menu is open. After a system hide it attempts an inactive restore after 120 ms. This is best-effort recovery for `Win+D` and other system hides, not a guarantee for every Shell state. Manual hide, close, unpin and disable stop recovery. UAC secure desktop, exclusive-fullscreen and system-level windows are not guaranteed to be covered.
- Image Studio now sends configurable quality, automatic/preset/custom resolution, dimensions, aspect ratio, transparent background and 1–10 image count with generation requests, and persists all validated returned images in the asset library. Each asset card has a Download button that uses the Windows save dialog to choose a destination. Parameter support depends on the selected model/gateway; unsupported settings produce an error rather than silently downgrading, and remote image URLs are not downloaded.
- Refined transparent-edge colors to reduce color bleed from transparent pixels into character contours during VP9 encoding. Fine warm edges or source-material variation may remain; background removal is not lossless.
- Added a working-conversations panel that opens by default when a task starts, retracts with no active tasks, and can be collapsed or reopened manually. It displays titles, states and locally calculated elapsed time, combining runs in the same conversation and prioritizing waiting for confirmation. Titles are shown by default and can be disabled in Desktop experience; when disabled, the companion window receives null titles and the panel and menu use anonymous labels. Other than titles, conversation bodies, file contents, workspace paths, command arguments and approval details are not sent to the companion.
- Companion navigation protects unsaved edits and prioritizes the latest valid selection. Batch management locks conflicting input and creation controls. Quick Chat waits for input processing and draft persistence before switching or archiving its current conversation; failed saves or unsubmitted message edits keep the original conversation available.
- Added optional idle actions at Low, Normal or High frequency while no tasks are active. Quiet mode pauses automatic greetings, idle chat, idle actions and automatic rest without stopping real tasks or disabling manual interactions.
- Added ChatAgent sidebar batch management, with individual or search-scoped selection across groups and batch archive, restore or permanent deletion. Archive and deletion require confirmation; running conversations cannot be archived, and deletion first stops related tasks. Results are retained per item, with failed conversations remaining selected for retry.
- Improved small companion status and action transitions, focus outlines and still-image fallback movement.
- Added branded artwork and an animated atom-mark welcome page to the Windows installer. The page embeds eight frames, `00–07`, and rotates them on a timer while retaining current-user installation, directory selection and standard NSIS page flow. Standalone UI-fixture checks do not constitute formal installer runtime, install/upgrade or uninstall acceptance.
- Desktop-experience preferences remain local. No database schema or policy revision changes, and existing user-data paths and the application atom icon remain unchanged.

## 1.3.4

- Added in-run guidance for primary Code/Work/Chat conversations and Quick Chat. Plain-text updates enter a subsequent model request in the same run without cancelling the current response or tool batch. Pending, Delivered and Not applied states are explicit; failed submission keeps the draft, and stop/restart does not resend automatically. The next-turn queue remains for later independent messages, and guidance does not expand permissions.
- Expanded the creative workstation to 780 distinct scenarios, 65 task structures and 12 categories, each with brief and detailed versions. Brief mode retains the original framework; default Chinese detailed prompts contain at least 800 Han characters, combining scenario-specific content with shared professional workflows and execution rules, plus real Skill recommendations. The count does not mean 800 characters are independently authored for each scenario or guarantee quality; editing may change the length. Combine category, format and multi-keyword filters, preview and copy the full prompt. New drafts default to detailed and old mode-less drafts restore as brief; switching preserves all edits and supports undo and JSON persistence. WorkAgent handoff appends the same prompt while preserving existing text and attachments; the user sends it. Office collaboration scenarios use supported artifacts or handoff specifications.
- Built-in source Skills now expose the latest semantic version of each matching source and path in both discovery and manual selection: 98 active entries, with 26 historical versions in nine groups hidden while all 124 physical sources and notices remain. Independent sources and workflow variants remain separate, including four PDF source roles. Old-selection mapping respects existing deny/ask rules and CodeAgent's scope is unchanged.
- Fixed a large blank gap in the Code/Work sidebar caused by obsolete positional grid rows after project navigation was inserted. Controls size to content and the conversation list receives the remaining scrollable space.
- Added Image Studio using user-configured OpenAI Images-compatible models that return Base64. Image and text/vision models are selected separately; prompt polishing is previewed and approved before adoption, and image-to-prompt requires vision input. Local assets, canvas layers, PNG export and portable project bundles with assets are supported. GIFs are assembled from selected image frames, not generated as AI video, and provider-returned remote image URLs are not downloaded.
- Added read-only AutoDrive: an explicit request uses the conversation, plan and bounded project evidence allowed by the active Profile to propose three to five directions. The model receives no command or file-editing tools, and choosing a proposal only appends it to the draft without sending. An unestablished worktree is rejected until a task in that conversation establishes it; AutoDrive does not create one or fall back to the main directory.
- Expanded the built-in catalog to 18 Agent roles. A coordinator can split a goal into two to six packages and dispatch real child tasks while the parent continues independent work; concurrency, approvals and write coordination remain in force. Verification commands and independent QA are recorded separately, and missing evidence, blocked commands or failures cannot be marked passed on text alone. A Test Engineer can author tests subject to its approval policy; the quality verifier does not edit files.
- Added the `Ctrl+Shift+P` command palette for currently available commands, conversations and workspace files. Project navigation shows projects and unread status; branch/worktree attribution uses actual established session records, and unrecorded history remains unknown.
- Added a user-operated interactive multi-tab Shell with input, resizing and stop controls. It is limited to the main window, trusted Code/Work projects, Full Access, non-patch-only mode, and host execution or an actual worktree; Chat, Quick Chat and actual SubAgents are excluded. Unconfirmed process cleanup retains an error and retryable state. Historical command records and model pipe commands remain separate.
- Local review now offers Git, branch, session and previous-turn diff scopes and contiguous-line comments with old/new line numbers. Files and diffs are rechecked before handoff; changed content retains comments and requires refresh. Comments append only to the draft and clear only after it saves successfully; they are not sent automatically.
- Fixed comment actions spilling into execution evidence in short review panes. The whole review pane can scroll while code and pending comments retain bounded scrolling. Narrow titlebars use compact mode and update controls, and creative surfaces omit conversation-only layout actions.
- Added canvas-toolbar toggles for the asset library and settings panel. Narrow windows start with both sides closed, and open panels no longer cover zoom, Fit canvas or PNG export controls.
- Added draft assistance: configure an independent text model, compare the original and polished suggestion, and explicitly apply it. The composer also offers a one-turn instruction and a workspace tone shared by Code/Work; queued items retain their own one-turn instruction. These settings do not expand tool permissions.
- Fixed DeepSeek requests returning HTTP 400 when thinking was enabled and a controlled `execute_tool_chain` expanded synthetic assistant tool steps without the required provider continuation state. Internal execution steps remain in local history and the UI, while DeepSeek Chat requests fold them back into the original chain-root result instead of sending provider-unreturned synthetic call/result pairs as independent history.
- Fixed native Memory task summaries using a fixed 512-token output budget that reasoning could exhaust before visible text. Recovery remains bounded by the existing deadline and cancellation path and never persists truncated or partial summaries; the TencentDB analysis branch is unaffected.
- Fixed native sandbox runs potentially hanging forever when `taskkill` failed or the target process never emitted `close`. Termination now settles within a hard bound. If process-tree cleanup cannot be confirmed, the workspace write barrier and leases remain in place and execution never falls back to the host.
- Fixed session delta synchronization advancing a global revision after skipping unknown IDs, which could leave a new or newly visible conversation unrecoverable after a missed live event. A controlled catalog refresh restores the row without deleting database history.
- Closed the conditional host-path reparse race between snapshot or Git restore validation and the later I/O. Restore remains an explicit user action and continues to reject static links, paths outside the workspace and unconfirmed outcomes.
- Removed the tool-result cache entries written by `deduplicate()` under generation-prefixed keys that no caller read, preventing those entries from occupying the shared LRU.
- Fixed persistent commands retaining an old `cleanupError` even after a later cleanup succeeded, eventually consuming all 64 command slots. Genuinely unconfirmed process-tree cleanup still retains the record, lease and write barrier until safe confirmation.
- Tightened shutdown and interrupted-recovery lifecycle: every service-stop step settles before Guarded I/O, stale plugin versions and the database close; recovery rechecks evidence, workspace barriers, active writers and leases, releasing Native Sandbox tombstones and recovery barriers only after explicit user confirmation. A later confirmed persistent-command cleanup can still clear a previous command cleanup error automatically.
- Improved quick creation in ChatAgent: the sidebar header, named groups, Ungrouped heading and Chat empty-state New actions now create and select a blank conversation directly without opening the full New conversation dialog. A grouped chat inherits the provider, model, reasoning level and chat settings from the most recently updated unarchived Chat in that group. Inheritance follows update time rather than pinned display order. Empty groups fall back to the most recently updated unarchived Chat, and a catalog with no Chat uses the default available configured model. History, drafts, attachments and runtime state are not copied, the Code/Work workspace is never inherited, and an invalid source model asks for repair instead of being silently replaced.
- Fixed the composer switching to formatted preview after pasting or ordinary typing. New input starts with the original Markdown/LaTeX source, and paste, typing, IME or shortcuts do not open preview automatically. Only the eye button opens preview; a saved draft restores the user's prior source/preview choice, and sending always uses source. The appearance setting controls whether source/preview controls are shown. Image paste remains an attachment action.
- Added a per-conversation ChatAgent **Allow internet / Block internet** control. Allowed `web_search` and `web_fetch` no longer request approval each time and still enforce protocol and public-target checks. Blocked access removes both tools from the model tool list and is enforced again in the main process. Existing chats default to allowed; grouped chats, forks and renewed Quick Chats based on an existing Chat preserve its blocked state. This does not block the configured model provider connection or sending user-uploaded attachments.
- Chat Completions no longer treats `[DONE]` or stream closure as success without a provider-issued non-empty `finish_reason`, and tools from that incomplete stream are not executed.
- Added a shared attachment-batch contract of at most 10 files, 25 MiB per file and 50 MiB total. The renderer checks count and declared size before file reads or IPC, and the main process revalidates before base64/parsing. Send and queued-attachment replacement use the same limits.
- Workspace OpenCode/Mingshen JSON configuration and project-origin Markdown Agents load only after project trust. Project `{file:...}` prompts use guarded reads inside the workspace, rejecting links and escapes. A project `build` creates a separate project Profile instead of replacing or contaminating built-in `primary`, and removing trust removes the corresponding project-origin Profile. LSP path queries use the same workspace boundary. Full-access host command cancellation settles when process-tree cleanup fails or the child never emits `close`; unconfirmed cleanup retains the writer barrier, lease and tombstone. Startup failure performs bounded cleanup before exiting instead of leaving a windowless single-instance process.
- DOCX/XLSX/XLS/PPTX/ODT/PDF extraction now uses at most two workers with a 384 MB worker heap, a 180-second deadline and cancellation. ZIPs reject absolute, traversal, empty-segment, backslash, ADS-colon and NUL paths, duplicate entries, Unix symlinks and XML `DOCTYPE/ENTITY`; PPTX requires a presentation part and at least one slide. Spreadsheet extraction has explicit sheet, row, column, cell and text limits; text attachment decoding rejects invalid UTF-8 and binary control characters. PDF vision stops rendering after its 20 MiB image budget is exhausted.
- Structured Excel requests now share a 100,000-cell work budget and reject `WEBSERVICE`, RTD, DDE/EXEC, external workbook, URL/UNC and `EXTERNAL` formulas. Host document replacement now locks and rechecks the old target, moves it to a same-directory backup, installs a new temporary file, reopens the requested path to verify identity, size and hash, and attempts recovery on failure. Cancellation, timeout or unconfirmed recovery returns an explicit error with a backup path; this is not a gap-free atomic swap and does not claim power-loss protection. Embedded workbooks are scanned before extraction and share limits of 64 archives, 4,000 entries, 100 MiB declared uncompressed data and four recursion levels. Controlled DOCX editing rejects external non-hyperlink relationships, attached templates, subdocuments, OLE/ActiveX packages, `altChunk` and active field types; generated PNG/JPEG images receive structural integrity checks.
- `office_document verify` now reports explicit overall, render and recalculation states: `verified`, `partial`, `unavailable` and `failed`. Any non-verified overall state makes the tool result fail visibly. Formula inspection beyond 2,000 spreadsheet cells is `partial`; PDF export, opening a document and structural inspection cannot be reported as page-by-page visual or formula acceptance.
- MCP OAuth token POST requests refuse redirects so authorization codes, refresh tokens and client secrets cannot be forwarded to another origin. Editing MCP credentials preserves existing values only for declared Header/environment keys; removing a key deletes its secret and undeclared secret input is rejected. Embedded `file:` browser preview now uses a per-session workspace-bound approval token instead of globally allowing arbitrary local URLs. Headless session creation reuses normal model, profile, workspace and configuration validation.
- ACP now settles `run_failed` and `run_interrupted`, rejects concurrent prompts for one session and prevents stale events from replacing a newer request. A `session/cancel` abort request has a 10-second default limit; an HTTP failure, network error or timeout rejects the active prompt as "remote stop is not confirmed" and clears the local waiter instead of reporting a false cancellation. The experimental launcher verifies the pinned native sandbox and builds the current source on every run, so deleted files, changed configuration or missing outputs cannot silently reuse a stale build. Local plugin SDK marketplace updates use an in-process queue, a cross-process lock, a random same-directory temporary file and atomic rename, then read back the result. Normal writers wait up to 15 seconds. A lock older than 60 seconds is not removed automatically by mtime; the SDK reports its path and leaves the catalog unchanged, requiring the user to confirm no writer is active and delete only the lock file. This avoids release races deleting another process's newly created lock.
- Synchronized the application, launch/package prompts, SDK default, current documentation and release notes to 1.3.4. Historical 1.3.3 installers, ZIPs, SHA-256 values, sizes, release SQL and validation records remain unchanged and must not be reused.

## 1.3.3

- Added CodeAgent, WorkAgent and ChatAgent modes with a main-titlebar switch. CodeAgent and WorkAgent share the existing conversation catalog and workspace and can change type within the same conversation for the next turn while retaining history, folder, draft, attachments, plans and summaries. Running, send-preparation, approval/question waiting and compaction lock mode changes in both UI and main process until the task finishes or is stopped. ChatAgent uses a separate grouped conversation page and cannot be converted directly from or into Code/Work.
- ChatAgent accepts user-selected PNG/JPEG/WebP/GIF/BMP/TIFF/AVIF raster images, PDF, Word, Excel and PowerPoint (`.pptx`) for read-only questions and processes only uploaded bytes. Image MIME declarations are checked against file signatures at both draft and send boundaries; SVG, disguised payloads and legacy binary `.ppt` are rejected explicitly. It exposes only `web_search` and `web_fetch`; the execution layer rejects local paths, file modifications, commands, browser clicks/login, MCP, Skills, hooks, custom tools and subagents. Chat conversations support group create/rename/delete, pin, search, archive and restore. Deleting a group moves its chats to Ungrouped without removing history, drafts or attachments.
- Strengthened CodeAgent's engineering loop with five on-demand engineering, frontend, backend/data, debugging and verification skills. Complex work can load focused references for large changes, failure forensics, test design, visual acceptance and release safety. Repeated identical failures trigger state inspection and a changed hypothesis or strategy. Each tool result retains at most 4,000,000 UTF-16 characters with head/tail excerpts and an explicit omitted-middle marker; each conversation retains at most 40 results and 16,000,000 cumulative UTF-16 characters. `read_tool_output` can page only through that bounded area and cannot recover unlimited originals or omitted, evicted or never-captured content. Only managed file-tool writes in a primary conversation with Full Access and host execution create per-file local checkpoints; each file is limited to 25 MiB, and a checkpoint and the per-turn total are subject to the `128 MiB / 128 checkpoints` budget. Commands and external MCP side effects are not covered by the per-file snapshot guarantee. Code index, LSP/diagnostics, tests/lint/type checking and up to three repair-and-verify attempts retain existing permissions and isolation.
- CodeAgent and WorkAgent now maintain an on-demand capability index for built-in Skills/Plugins and every installed and enabled Skill/plugin. The composer **+** reference panel can manually select a built-in capability or installed extension per conversation; selected items remain first, while other enabled items are still searchable through `discover_capabilities` by task context and can load a matching Skill body or read-only reference by exact ID. Manual selection does not disable automatic discovery. Disabled extensions are excluded, and ChatAgent is rejected at both discovery and loading boundaries. Discovery executes no scripts; MCP/hook, approval and isolation rules remain unchanged.
- Added per-conversation manual selection of built-in capabilities: up to 32 entries, stored in existing `app_settings` rather than `session_extensions` and never described as installed extensions. Built-in records currently include `builtin:plugin-github` (GitHub API) and `builtin:plugin-browser` (embedded Chrome/Edge) metadata. Selecting a plugin only records a tool preference; its ID is never passed to `use_skill`, and selection does not connect an account, sign in, start the browser service or invoke a tool. Changes are rejected while the root conversation, its children or runtime state is running or waiting for approval. Work-only choices stay hidden in Code and return when switching back to Work; forks and child conversations copy the selection. Selected records use `session_selected:true` and sort first in discovery, while exact IDs enter the system prompt. Skill bodies are preloaded only when the active Agent Profile permits `use_skill` and no interactive approval is required, including the default read policy. The controlled first-turn preload is capped at 64,000 characters; `ask`, `deny`, unavailable or over-budget entries remain exact deferred IDs for the real `use_skill` path. Built-in loading is read-only UTF-8 text, limited to 2 MiB per resource with path isolation and no script execution. Chat rejects both list and set.
- Added the native local-plugin interface: `.mingshen-plugin/plugin.json`, a local `marketplace.json` development market, host validation, and Settings validation/install/enable/update flows. Import compatibility also recognizes `.codex-plugin`, `.zcode-plugin` and a legacy root `plugin.json`. Plugins can declare Skills, Markdown commands, MCP servers and supported hooks, but installation does not execute scripts or broaden permissions. Install/enable only exposes discoverable capabilities; hook-capable plugins must also be referenced in the current primary CodeAgent/WorkAgent conversation. Action hooks are attempted only with host execution, Full Access and a trusted project; Request Approval, Docker, ChatAgent, actual SubAgents and read-only profiles do not execute them. `Interrupt` uses an independent fire-and-forget cleanup signal capped at about 1.5 seconds and accepts only prompt activity text; Command/MCP actions are skipped without approval, process launch or tool recovery. A primary CodeAgent/WorkAgent in a host Windows conversation can use the read-only `local_plugin` actions `inspect`, `validate` and `list_markets` in either Request Approval or Full Access. Plugin source reads inherit `read_file` Profile rules, accept only real absolute directories inside the workspace, and use path-scoped approval in Request Approval; Docker, worktree, ChatAgent and actual SubAgents are rejected.
