# Mingshen Harness Changelog

Current version: 1.3.3.

## 1.3.3

- Added CodeAgent, WorkAgent and ChatAgent modes with a main-titlebar switch. CodeAgent and WorkAgent share the existing conversation catalog and workspace and can change type within the same conversation for the next turn while retaining history, folder, draft, attachments, plans and summaries. Running, send-preparation, approval/question waiting and compaction lock mode changes in both UI and main process until the task finishes or is stopped. ChatAgent uses a separate grouped conversation page and cannot be converted directly from or into Code/Work.
- ChatAgent accepts user-selected PNG/JPEG/WebP/GIF/BMP/TIFF/AVIF raster images, PDF, Word, Excel and PowerPoint (`.pptx`) for read-only questions and processes only uploaded bytes. Image MIME declarations are checked against file signatures at both draft and send boundaries; SVG, disguised payloads and legacy binary `.ppt` are rejected explicitly. It exposes only `web_search` and `web_fetch`; the execution layer rejects local paths, file modifications, commands, browser clicks/login, MCP, Skills, hooks, custom tools and subagents. Chat conversations support group create/rename/delete, pin, search, archive and restore. Deleting a group moves its chats to Ungrouped without removing history, drafts or attachments.
- Strengthened CodeAgent's engineering loop with five on-demand engineering, frontend, backend/data, debugging and verification skills. Complex work can load focused references for large changes, failure forensics, test design, visual acceptance and release safety. Repeated identical failures trigger state inspection and a changed hypothesis or strategy. Each tool result retains at most 4,000,000 UTF-16 characters with head/tail excerpts and an explicit omitted-middle marker; each conversation retains at most 40 results and 16,000,000 cumulative UTF-16 characters. `read_tool_output` can page only through that bounded area and cannot recover unlimited originals or omitted, evicted or never-captured content. Only managed file-tool writes in a primary conversation with Full Access and host execution create per-file local checkpoints; each file is limited to 25 MiB, and a checkpoint and the per-turn total are subject to the `128 MiB / 128 checkpoints` budget. Commands and external MCP side effects are not covered by the per-file snapshot guarantee. Code index, LSP/diagnostics, tests/lint/type checking and up to three repair-and-verify attempts retain existing permissions and isolation.
- CodeAgent and WorkAgent now maintain an on-demand capability index for built-in Skills/Plugins and every installed and enabled Skill/plugin. The composer **+** reference panel can manually select a built-in capability or installed extension per conversation; selected items remain first, while other enabled items are still searchable through `discover_capabilities` by task context and can load a matching Skill body or read-only reference by exact ID. Manual selection does not disable automatic discovery. Disabled extensions are excluded, and ChatAgent is rejected at both discovery and loading boundaries. Discovery executes no scripts; MCP/hook, approval and isolation rules remain unchanged.
- Added per-conversation manual selection of built-in capabilities: up to 32 entries, stored in existing `app_settings` rather than `session_extensions` and never described as installed extensions. Built-in records currently include `builtin:plugin-github` (GitHub API) and `builtin:plugin-browser` (embedded Chrome/Edge) metadata. Selecting a plugin only records a tool preference; its ID is never passed to `use_skill`, and selection does not connect an account, sign in, start the browser service or invoke a tool. Changes are rejected while the root conversation, its children or runtime state is running or waiting for approval. Work-only choices stay hidden in Code and return when switching back to Work; forks and child conversations copy the selection. Selected records use `session_selected:true` and sort first in discovery, while exact IDs enter the system prompt. Skill bodies are preloaded only when the active Agent Profile permits `use_skill` and no interactive approval is required, including the default read policy. The controlled first-turn preload is capped at 64,000 characters; `ask`, `deny`, unavailable or over-budget entries remain exact deferred IDs for the real `use_skill` path. Built-in loading is read-only UTF-8 text, limited to 2 MiB per resource with path isolation and no script execution. Chat rejects both list and set.
- Added the native local-plugin interface: `.mingshen-plugin/plugin.json`, a local `marketplace.json` development market, host validation, and Settings validation/install/enable/update flows. Import compatibility also recognizes `.codex-plugin`, `.zcode-plugin` and a legacy root `plugin.json`. Plugins can declare Skills, Markdown commands, MCP servers and supported hooks, but installation does not execute scripts or broaden permissions. Install/enable only exposes discoverable capabilities; hook-capable plugins must also be referenced in the current primary CodeAgent/WorkAgent conversation. Action hooks are attempted only with host execution, Full Access and a trusted project; Request Approval, Docker, ChatAgent, actual SubAgents and read-only profiles do not execute them. `Interrupt` uses an independent fire-and-forget cleanup signal capped at about 1.5 seconds and accepts only prompt activity text; Command/MCP actions are skipped without approval, process launch or tool recovery. A primary CodeAgent/WorkAgent in a host Windows conversation can use the read-only `local_plugin` actions `inspect`, `validate` and `list_markets` in either Request Approval or Full Access. Plugin source reads inherit `read_file` Profile rules, accept only real absolute directories inside the workspace, and use path-scoped approval in Request Approval; Docker, worktree, ChatAgent and actual SubAgents are rejected. Host validation requires no system Node.js, PATH or out-of-sandbox SDK, while the bundled SDK remains an optional user-run preflight. Installation, update, enablement and removal remain user-only Settings actions; the on-demand `skill-creator`, `plugin-creator` and `harness-plugin-api` skills guide creation and validation.
- WorkAgent shares CodeAgent's execution engine and workspace and adds research, analysis, Word, Excel, PowerPoint, operations and artifact-quality skills plus the structured `office_document` tool. Word, PDF and PPTX authoring can use `executive`, `consulting`, `editorial` and `minimal` design presets with `airy`, `balanced` or `compact` density; PPTX adds cover, section, statement, cards, timeline, data, metric-grid and closing semantic layouts. Excel supports workbook themes and sheet title/header/body surfaces, grid lines, print area, repeated title rows, orientation and fit-to-page, with controlled `format_sheet` styling for existing workbooks. WorkAgent plans audience, argument, tone, information hierarchy, typography, polish, editable objects and sources instead of treating package or text-extraction success as visual acceptance.
- The built-in domain-skill catalog now contains 21 foundation capability entries: five Code, twelve Work, three Creator and one shared artifact-quality entry. Nineteen are original workflows; the two new Work-only IDs, `builtin:work-ppt-master` and `builtin:work-asd-ste100`, adapt the open-source PPT Master 6.9.0 and ASD-STE100 0.4.0 skill resources. Mode filtering exposes nine foundation entries in CodeAgent and sixteen in WorkAgent. The separate `WorkAgentSkill/` inventory covers 124 physical source entries, 104 unique body SHA values and 93 unique names. The original bodies of 82 design resources are preserved byte for byte and remapped through catalog wrappers, while 22 unique bodies are original adaptations for the primary design source and non-design material. Runtime keeps a stable ID for every physical source path and may share a body by SHA; these entries are discoverable only in WorkAgent and load through `use_skill` on demand without injecting all bodies into the default prompt. They are not 124 independently authored workflows. PPT Master scripts, Python dependencies and paid services are never installed or executed automatically, and binary references such as WAV cannot be loaded directly through `use_skill`; the ASD-STE100 adaptation does not include the official dictionary and is not an official certification. PDF-related material has ten physical sources and five unique source-body SHA values across four workflow roles: production, viewer, reading and loose general-purpose handling; the historical Viewer 0.2.1 body is also retained. The source catalog preserves third-party provenance, license dispositions and source SHA values. ZCode JWT/authentication, viewers, canvas, source scripts and private host APIs are not enabled by a skill, and neither compatibility inventory nor host catalog validation is a claim of real-runtime acceptance.
- Added optional Microsoft Office COM recalculation/rendering only for WorkAgent with Full Access, host execution and a primary, non-child conversation when Office is installed, idle and permitted. Temporary copies are used; Office is never installed automatically and a user's active document is not taken over. Request Approval, Docker, child sessions, missing Office or COM failure retain structural checks and explicitly mark formula recalculation or rendering as unverified. Written formulas, cached values, actual Excel calculation and Word/PowerPoint page rendering remain separate evidence.
- Agent profiles now apply to CodeAgent and WorkAgent by default and can target only one mode. A mode switch is rejected when no compatible profile exists, and ChatAgent never uses custom Agent profiles. Permanent schema9 adds conversation modes and chat groups plus profile applicability while preserving providers, models, messages, drafts, archive state, settings, consent and credentials.
- Raised the per-extension local Skill/plugin import limit from 4,000 to 20,000 files, with a 64 MiB total limit, and the separate marketplace skill limit from 1,000 to 20,000. Fixed false count errors when an empty or ignored directory follows the last allowed file; excess counts still fail before copying/downloading. Skills are discovered through metadata such as name and description by default and loaded on demand by `use_skill`, one page of at most 32,000 characters at a time with `char_offset` continuation. A loadable text resource is limited to 2 MB, and binary resources cannot be loaded as instructions. The former 120,000-character startup injection of extension bodies has been removed.
- Added localized DOCX editing without placeholders: read indexed structure and the full source SHA-256, then replace unique inline text, complete body paragraphs/tables, or paragraph layout. Supports split formatting runs and table-cell text; replacements can contain native equations, rich tables, approved images and charts while retaining unselected content and unrelated package parts. Defaults to a new output with independent source-read authorization, atomic writes, conflict and cancellation protection. Complex bookmark, revision, field and section ranges are rejected; arbitrary Office files are not guaranteed lossless.
- Added DOCX/PDF paragraph spacing, line spacing, indentation, justified alignment and pagination controls, plus relative table column widths and repeated headers. Existing DOCX paragraphs can change layout alone. PPTX rejects the new controls explicitly. Tool guidance, format matrix and bilingual manuals are synchronized.
- Refined Light Trails into an enterprise workbench surface: the titlebar is now a 56px unframed shell, the tool rail is 48px, insets are 12px and region gaps are 8px, and the square-edged breadcrumb/status rows are 44px/24px. Workspace titles use 15px/600. The task pane defaults to `clamp(224px, 28dvh, 304px)`, or 160px in a narrow workbench or when a file editor opens at short height. The shell clips overflow and isolates stacking; drawer calculations reserve an 88px sidebar shell or a 96px inspector shell for the rail, outer insets and splitters. Day uses a white conversation pane on a pale gray-green shell; night uses low-saturation ink-teal surfaces. Decorative gradients are removed from the titlebar, rail, selected states and panels; continuous workplanes, 1px hairlines, flat selection and real running-state lines now establish hierarchy. The composer context uses `1fr / 96–136px / 88–128px`; the footer and its children may shrink, and the update action stays content-sized up to 220px. Conversation, execution timeline, review, terminal and task panes share 12px metadata, heading rhythm and keyboard focus. Orbit ChatAgent has its own 264px grouped conversation sidebar with solid chrome, 13px/550 titles, 12px metadata and a 1px brand selection line; its empty title is fixed at 24px, and below 900px the sidebar becomes a drawer instead of compressing the chat. None of these changes alters business data or permissions.
- The Light Trails task pane now supports pointer and keyboard resizing, Enter or double-click reset, and collapse to a single row; Escape cancels an active drag. Height and collapse state persist per workspace, with custom height constrained by available window space. Review rows show file names and directories, and previews show workspace-relative paths when available. Conversation rows and task controls use a denser layout, while the Chat empty state aligns with its composer. Empty WorkAgent conversations offer Word, Excel and PowerPoint starters that append to the draft without sending automatically.
- Unsaved plan edits now block switching to another conversation or ChatAgent, creating a new conversation, and archiving the current conversation or one of its ancestors. The task workbench reveals the Plan tab and asks for Save or Cancel; Code/Work switching within the same conversation remains available. The guard neither saves nor discards edits and does not promise recovery of unsaved edits after restart.
- Motion now carries state and continuity only: a single short light beam on composer focus, a slow breathing signal on active execution nodes and the status bar, a 3px streaming-message settle that keeps text fully opaque from the first frame, and short disclosure transitions for tool details and settings. Reduced-motion and app “Motion off” settings remove travel and looping animation while retaining color, focus and readable state feedback. Interface-style stability checks now observe the real running status light instead of treating the one-shot composer focus beam as a looping animation assertion.
- Fixed the composer switching from raw editing to formatted preview on its own. Preview now opens only when the browser reports an explicit `insertFromPaste` / `insertFromPasteAsQuotation` input and the corresponding paste is still pending. Ordinary typing, IME composition, stale paste markers and shortcut handling no longer trigger it. The original source remains available for sending.
- Adjusted background SubAgent collaboration: the fixed ten-minute wall-clock lifetime is removed, so work no longer stops merely because its cumulative duration reaches the limit. A SubAgent continues until explicit completion, failure, user stop or parent cancellation, while individual model requests, tools, commands, network calls and external services retain their own timeouts. After `spawn_subagent` starts background work, the primary Agent can continue its own independent tasks and collect real results later with `wait_subagents` instead of waiting idle.
- Added a running-task next-turn queue for main-interface CodeAgent, WorkAgent and ChatAgent conversations. While a task is busy, the composer can save its text and validated attachments as a later turn without inserting Steer into the active provider turn or interrupting/restarting the current run. The queue persists in existing `app_settings` under schema 9 with no migration. Each conversation holds at most ten pending items and 50 MiB of queued attachments, while each file keeps the 25 MiB validation; dispatch is strictly first-in, first-out with no reordering. After normal completion and background cleanup, the first item starts automatically without an individual Continue click. Editing first holds the whole queue; if the active run is stopped or fails during editing, saving or cancelling ends only the edit and the queue remains paused. A failed attachment replacement keeps the previous attachment snapshot and pauses the queue so unconfirmed content is not sent automatically. Manual Stop, a failed run, an automatic send failure or application restart preserves and pauses the queue. It continues from the first item after an explicit queue-level Resume or after a later normal run in the same conversation succeeds, and approval waits do not advance the queue. A configuration snapshot covers Agent mode, workspace, Agent profile, provider, model, permission, approval and execution environment; changes block the whole queue without skipping its head item. A durable `sending` claim is written before dispatch, and an accepted run ID removes the item; send failure retains it, while unconfirmed cleanup locks retry and shows a pending-cleanup notice. Queues are conversation-private, are not copied to forks, and are deleted with their conversation. Quick Chat and actual SubAgents do not expose the queue, and the main process rejects their queue requests.
- Added global shortcuts. By default, `Ctrl+M` toggles Quick Chat and `Ctrl+Alt+L` toggles the main interface/tray. Pressing `Ctrl+M` again while the compact window is visible hides it. Quick Chat supports attachments, web search/fetch, drafts, Stop, rewrite, compaction, New, Open main window and `Esc` to hide; its titlebar pin persists an always-on-top choice, while local files, commands, MCP, Skills, hooks and subagents remain rejected. You can record and customize both global shortcuts in Settings. Three- and four-key Ctrl/Shift/Alt chords are supported while the two-key defaults remain valid. Each combination needs at least one modifier and one primary key, the two cannot conflict, and saving registers them immediately. If a combination is occupied or registration fails, Mingshen keeps the previous valid bindings, shows an error and allows the defaults to be restored.
- Fixed the circular warning icon in the Light Trails header stretching and buckling its local row layout; its size, line box and alignment are constrained again while error state and tooltip semantics remain intact.
- Version, launch/package messages, SDK default, embedded bilingual guides and changelogs now say 1.3.3. The historical 1.3.2 installer, release SQL, hashes and sizes remain unchanged and must not be reused for this version.

## 1.3.2

- Added native Google Gemini GenerateContent as a fourth protocol with `x-goog-api-key` authentication, native SSE, thinking, tools, image/audio/PDF inputs, paginated model discovery and connection tests. Every model selector uses the same configuration. Returned Part boundaries, order, empty text and opaque signatures are retained; same-name calls use internal pairing IDs, while only server-issued optional IDs go back on the wire. Incomplete, blocked, cancelled or malformed turns neither execute tools nor save native state.
- Connection settings now edit authentication and custom headers. Active tasks block endpoint, protocol or authentication changes. Gemini leaves thinking at the API default unless configured: use `auto` for 2.5 (Flash also permits `none`), and model-supported `minimal/low/medium/high` for 3 and later. No token budgets are guessed. Native Gemini uses implicit caching without foreign-provider hints or billable cache creation.
- DOCX/PDF table cells now accept `{"blocks":[...]}` for multiple paragraphs, inline formatting, Markdown, lists, code, quotes and equations. DOCX equations remain editable OMML; PDF keeps their layout. Existing string cells remain literal text, and PPTX tables stay string-only. Each structured cell is limited to 50 blocks and 20,000 characters, counted toward the global 1,000-block/500,000-character limits, including template replacements. Tool examples and embedded bilingual guides are synchronized; version remains 1.3.2.
- Added Gemini and DeepSeek model families. Automatic detection requires matching official endpoints and protocols; unknown gateways can select a family in provider connection settings and must forward native fields. Family selection does not translate protocols or certify compatibility. Automatic caching uses server-managed implicit reuse without injecting OpenAI cache keys, Claude breakpoints or creating billable explicit-cache resources.
- Retain opaque Gemini Chat Completions message/tool signatures and actual DeepSeek Chat, Responses and Anthropic native reasoning continuation state. Tool order is preserved. Replay requires matching provider configuration, model, protocol, endpoint, visible text and tool identities/arguments. Invalid, oversized or incomplete state falls back to ordinary history; missing state is never invented from displayed thinking or retroactively added to old records.
- Token Saver preserves native-state messages and tool pairing. Independent text summaries exclude `provider_state` and opaque signatures. The Privacy Policy explains local storage of API-returned DeepSeek plain-text reasoning and opaque Gemini signatures, distinct from credential encryption and without a new recipient.
- DeepSeek Chat explicitly maps selected reasoning levels to thinking and effort, while Responses / Anthropic retain their own native mappings. An unset level leaves the API default intact. DeepSeek Responses no longer requests OpenAI-only encrypted-reasoning include fields.
- Usage normalization accepts DeepSeek hit/miss counters and native Gemini usage aliases as compatible fallbacks. Valid standard fields take priority, explicit zero differs from missing reports, conflicting/invalid counters are rejected and cached input is not counted twice. Native Gemini fallback output includes reported thinking tokens while retaining the provider's complete total.
- Updated embedded bilingual guides, changelogs and agreement application versions to 1.3.2, with configuration, diagnostics and official research sources. Minimum cache lengths, expiry and routing remain provider-controlled, with no hardcoded per-model thresholds or fixed hit-rate guarantee. Upgrades, model changes, compaction and missing state in old history can still rebuild prefixes.
- Added permanent schema8 migration to extend provider protocol/authentication constraints, validate foreign keys transactionally and retain keys, models, sessions, messages and settings. Historical schema1–7 migrations and policy revision `2026-11-04.3` remain. The maintainer's existing 1.3.1 installer and separate release SQL remain historical materials. This work does not package or publish 1.3.2, and old hashes and sizes must not be reused.

## 1.3.1

Chat and every model selector share a collapsible Starred models group at the top, labeled “Model ID (Provider)” to distinguish matching names. Menus also support provider reordering and stars; drag handles accept Alt+arrow keys, and Escape cancels a drag. Stars belong to exact configurations and respect each selector's model eligibility, so starring a disabled model does not make it selectable.
- Provider display order and model stars save automatically on this device, synchronize across settings and model menus, and survive restarts. Deleting providers or models cleans their preferences, and new providers append to the list. Existing selections, default/backup models, inheritance and key priority remain unchanged. Save failures show an error and retry control; model configuration changes still use their existing save actions.
- Added Settings → Conversations and data → Manage conversations by folder, including folders with only archived records and conversations without a workspace. Filter unarchived/archived/all roots and search their titles, then check individual roots or select all matching roots across pages for archive, restore or deletion. Pages contain 50 rows with independent scrolling. All children follow their root, including separate worktrees; archive/delete confirmation shows actual root and child counts. Deletion stops related work and permanently removes messages, drafts, attachments and application snapshots while retaining project files. Archive retains drafts and pauses schedules; restore does not reenable them. Per-item failures retain their selection for retry without rolling back successes, and settings stays open during processing. Version remains 1.3.1 with no new data migration.
- Expanded built-in authoring with native editable DOCX equations from LaTeX, Markdown, mixed text/inline math, footnotes, code, quotes, TOC fields, headers/footers, page numbers and margins. DOCX/PPTX charts include embedded workbooks. DOCX templates support controlled standalone placeholder replacement, while PDF gains offline Markdown/math layout. Tool guidance and package checks cover the new modules. Unsupported equations fail explicitly without silently becoming images; existing approval and file protections remain.
- All conversations now save unsent drafts locally, including new chats, existing history and child conversations. Complete text, format state and actual attachment contents survive switching and normal application restarts, even if the original attachment files are removed. An accepted send consumes only its submitted revision; pre-accept failures retain the draft, and late replies preserve newer input. Explicit clearing or conversation deletion removes unsent content. Automatic retention protects drafts and their parents. Exit, update handoff and reload wait for writes; failures keep the window open with a retryable error. Failed notification replies queue durably and are acknowledged only after safe, deduplicated merging.
- Pasted Markdown and LaTeX now render directly inside the composer by default, including headings, lists, tables, code and math. Use the footer controls to edit source or preview formatting. Settings → Appearance and language can disable this immediately and persist the choice. Sending retains the original source and native editing, selection, undo/redo, Chinese composition and image attachments remain available. Drafts over 30,000 characters or with complex syntax use source editing; draft previews do not open links or fetch remote images.
- Fixed long workspace file lists being clipped without scrolling to later entries. The file tree, editor and docked command panel retain their own scrolling regions.
- Fixed Light Trails child-agent expansion and conversation menu buttons overlapping conversation titles. Long titles retain their complete hover text.
- Fixed long compaction errors and tool details widening the chat's internal grid, displacing history and the composer beyond the window after expanding and collapsing details.
- Improved long tool-history rendering by loading closed details on demand and avoiding repeated historical argument formatting during typing, streaming and timer updates. Complete commands, arguments, output and copy controls remain available.
- Fixed automatic post-edit checks showing “No applicable project diagnostics configured” as a successful check. Checks without an applicable engine are skipped, and progress starts only after a diagnostic engine is selected. Startup failures, missing commands and real check failures from configured checkers remain visible. Checks reporting failure without error output are still marked as failed, with a notice that error details are missing.
- Synchronized the application, launch/package commands and embedded bilingual documents to 1.3.1. Schema7, historical migrations and the policy revision remain unchanged. Existing 1.3.0 installer metadata and release SQL retain their actual hash/size; 1.3.1 release metadata must come from a newly built package.

## 1.3.0

- Refined Light Trails with metallic tonal depth and mint/ice-blue edge light across the caption, tool rail and composer, plus clearer live execution states. The main model selector shows “Model (Provider)”, with independently bounded names and complete tooltips/accessibility names. Provider groups and selection behavior in settings remain unchanged.
- Runtime activities, retry/compaction/reviewer diagnostics, final errors and integration status now expand/collapse with complete received content and copy controls; fixed activity lookup for full tool arguments/results. Historical tools separate commands, arguments and output, with line wrapping and independent scrolling. Review, manual Commands and MCP/runtime settings also expose details. Opening chat details pauses following, and bounded child previews link to the full conversation. MCP HTTP/OAuth diagnostics no longer silently stop at 4000 characters; a 100000-character cap has an explicit notice, retaining redaction and other execution limits.
- Rebuilt **Light Trails** as a distinct workbench matching the preview: a 56px tool rail, Workspace conversation sidebar, breadcrumb header, central chat and bottom status strip. Upper-right review/files/terminal and lower-right tasks/Agents stay visible together, retaining Git, browser, saved-plan and real child-output controls. The default **Simple** interface and all three layouts remain; each style saves project layout, widths and open states independently while sharing features and data.
- Light Trails message headers show identity, primary/child Agent roles and actual timestamps. Consecutive tool calls form an expandable execution timeline, review shows the selected file's real stored diff, and permission/isolation controls move to the composer footer. Day/night palettes, metallic edges, thin light tracks and real-state feedback remain; the large local-memory-engine card is omitted and existing memory entry points remain.
- Settings → Appearance & language saves the application-wide style for the next interface reload or restart. Reload waits for preference writes, draft persistence and attachment reads; save failures cancel it with a retryable error, and saved unsent content returns afterward. Unsaved file, message or plan edits still block reload. The main process blocks reload during active work, send preparation, manual compaction, pending approvals/answers, shutdown cleanup or update installation handoff, without automatically stopping tasks. Day/night themes still change immediately.
- Decorative motion respects system reduced motion or the application's Off option; highlights pause while the window is hidden. This change concerns layout and interface presentation only. Version remains 1.3.0 with schema7, permanent migrations and the policy revision unchanged.
- New-model creation applies editable ID-prefix presets once: `gpt-6` (including `gpt-6.1`) gets 1000000 context, 128000 output, text/image/file inputs and `none,low,medium,high,xhigh,max`; `deepseek-` gets 1000000 context, 384000 output, the same inputs and `low,high,max`. Saved models are not overwritten. The new GPT form has an unchecked long-context billing control that explicitly sets context to 200000 or back to 1000000 without resetting output. These are local form presets, not verified provider capabilities or billing detection.
- Context/output inputs accept case-insensitive decimal K/M units and save safe positive integers, preserving invalid drafts with focused errors. Saved providers can edit name, Base URL and API protocol while retaining keys/models/conversation references. Active work blocks endpoint/protocol changes; incompatible cache settings reset to Automatic/five minutes on protocol changes.
- Restored TencentDB's pinned upstream generic conversation extraction and conflict prompts. The analysis model generates `persona`, `episodic` and `instruction` memories with `store/skip/update/merge` decisions. Removed the rule adapter that directly stored complete answers or `Assistant result excerpt`. Valid empty results mean no additions; confirmed preferences cannot be automatically updated or merged, and saved status requires committed changes.
- Settings → Project instructions and trust supports manual workspace selection and per-workspace backend, primary analysis model and fallback configuration. An unset primary uses the current primary conversation model, and a fallback may be configured alone. Failed calls or invalid results restart the entire extraction/conflict operation with the fallback, without raw-answer excerpt fallback. Necessary conversation text and candidate memories are sent to the corresponding providers and incur API usage.
- Explicit backend switches retain both directories without deletion, renaming or migration; only the selected backend is active. Ambiguous legacy directories require an explicit Settings selection, and child/worktree settings resolve to the top-level parent's memory workspace. Changes wait for project tasks and memory maintenance to finish. Cancellation, invalid output, changed configuration and revision conflicts preserve committed data. Native summaries, version 1.3.0, schema7 and the policy revision remain.
- Responses retain provider-issued encrypted reasoning/compaction items and assistant `commentary` / `final_answer` phases, replayed only after provider/model/endpoint and visible-content checks. Raw hidden chain of thought is not stored; progress is not treated as a final answer. Missing gateway state is never invented or replayed across models or endpoints. Ciphertext string length is not counted as tokens: each item reserves 1024, capped at 8192 total and 5% of the model window, with actual usage calibration retained and no exact-count guarantee.
- Added workspace `view_image` for approved PNG/JPEG/WebP/GIF pixels, bounded to 20 MiB per image, using native model image input and the existing capability, path, approval and native MXC/Docker gateways.
- `browser_screenshot` saves a PNG and returns actual pixels in `tool_result.images` for the next vision-model request, enabling visual page inspection. Screenshots have a 2048-pixel longest-edge limit and an 8 MiB PNG limit, separate from `view_image`'s 20 MiB limit. Models without configured image input receive an explicit notice that the image was not sent.
- Added pipe-based `exec_command` / `write_stdin` for incremental long-command output, input, stdin closure and termination. Sessions belong to their conversation/run and are cleaned up when it ends. Unconfirmed cleanup retains the write barrier and lease; failed cleanup recovery may require restarting, and clearing the barrier does not confirm process/container termination. This is not full PTY/TUI support. File reads now support line ranges, `limit` and long-line `char_offset` cursors, with range caching still checking the full source hash.
- Models with parallel tool calls enabled can run at most three adjacent independent built-in reads concurrently. Commands, writes, tool chains, browsers, MCP and custom tools are excluded; each operation retains approvals, isolation and budgets.
- Writable managed children can queue up to six checks with `request_verification`. `wait_subagents` collects requests; after all tool results from that model turn are saved, the parent runs checks sequentially under its own profile, approval, isolation and writer locks, saving separate results to preserve Chat/Anthropic call/result pairing. Child shells remain read-only; queued or denied checks are not passes.
- New Token Saver settings disable early turn-count summaries by default and use Auto response guidance. Explicit existing choices and the 85% context safeguard remain. Native-state/image-result messages retain exact text; opaque and image bytes are not counted as ordinary text for early-summary thresholds.
- Added six reproducible task fixtures and grading. The default is synthetic offline evidence only; live model execution requires explicit isolated-profile loopback API configuration. Missing telemetry is unobserved, and current wire/Token Saver visibility gaps and incomplete billing scope are disclosed instead of treating synthetic passes as model-quality certification.
- Agent profiles now expose a per-profile child-agent model choice only for `Subagent` and `primary + Subagent` roles. Each profile can inherit the parent conversation model or select its own model; `@` calls and `spawn_subagent` share the same routing rule. Primary and Plan profiles cannot accidentally route their model override to child work. Existing `model_id` values are preserved, unavailable explicit models fail visibly instead of silently switching, and the version stays 1.3.0.
