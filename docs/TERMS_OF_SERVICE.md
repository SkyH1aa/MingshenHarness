## 3. 用户授权与责任

用户仅可授权软件访问自己有权使用的文件、仓库、账户、网络和设备。用户负责核查模型输出、代码、命令、上传内容和第三方操作，并按需要备份。禁止将软件用于未经授权的入侵、破坏、窃取数据、违法内容或侵犯他人权利。

“请求批准”要求对受保护的工具操作进行确认；“完全访问”允许更广泛的访问和执行。批准命令或第三方工具即表示允许其在显示的范围内执行。用户不应将完全访问授予不可信任务、仓库、脚本或扩展。固定命令识别、快照、容器等措施降低风险，但不是绝对安全保证，也不能替代备份和代码审查。

用户可配置审批模型并主动启用自动审批，将待执行操作的命令、路径和参数交由所选模型判断后逐项允许或拒绝。该模型可能不同于对话模型，会向其供应商发送必要的操作数据，并可能产生额外 API 用量。模型判断可能出错，不构成安全认证；审核失败时等待手动处理，用户可随时切回手动或停止任务。沙箱、Agent 只读策略和致命命令保护不因自动审批而取消，Shell Hook 仍需显式手动批准。选择“此项目完全访问”会立即影响该目录的现有会话和后续新会话，用户应核对项目范围。

## 6. 数据与保密

默认会话和工作区记录保存在本地。用户主动发送的消息、附件、工具结果和上下文可能传输至所选模型或工具服务。不得在无授权情况下提交个人信息、商业秘密、受出口或其他法律限制的数据。凭据加密不能防御已经控制当前 Windows 账户或设备的攻击者。

上下文自动压缩会把较早的消息与工具结果发送给压缩模型。默认使用当前会话模型，用户也可配置全局或单会话独立供应商；该选择授权向所选供应商发送相应历史资料并可能产生额外 API 用量。摘要可能遗漏细节，不是完整原始记录的替代品；用户可在本地查看原始聊天并复核重要事实，原始记录不会因压缩被删除。

用户配置备用审批或压缩模型，即授权主模型发生调用或返回验证失败时，向备用供应商发送相应操作或历史资料并尝试一次；可能产生额外 API 用量。主审批模型有效拒绝的操作不会转备用重新审批，两次审核失败保留人工处理。备用模型不是额外的安全认证，用户应核查主备供应商的数据政策、权限和用量安排。

模型请求在连接、限流和临时服务错误后，每次断连默认最多自动重连 5 次，用户可配置 0–20 次；恢复有效输出后再次断连重新计数，不是整段对话的总额。重试向同一供应商重新发送当前请求，可能增加用量和费用；审批与压缩保留原主备供应商选择及总超时。前述主备各“一次”指逻辑尝试，内部可含传输重试。停止会取消等待，已完成工具不因模型重试而自动重放。具体设置及限制见内置手册。
